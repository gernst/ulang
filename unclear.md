# Unclear

Trip-ups and unclear points met while working on ulang code, each with what was wrong and what is so, until the
documentation is fixed from them (see the working rules of `CLAUDE.md`).


- **The parser of `ulang/` is too slow in the interpreter for a test**: a test that imports `ulang` and calls `parse_file` on the compiler's own package ran for minutes under `ulang.sh test`, and in 2 seconds compiled; so such checks are in `checks/`, which `make testdocs` runs compiled.
- **`import "ulang"` in `ulang/prove/syntax.u` showed no clash**, although `prove.md` expected `Expr` and the like to be ambiguous: the types of a module hide those of its imports, so the clash shows only in a sibling that imports `ulang` and sees the exports of `ulang/prove/syntax.u`, where every type of both, also the alias `Id`, is `Ambiguous`. Imports are per module, so each member of `prove/` that names a type of `ulang` imports it itself.
- **`git add` with one missing path stages nothing**: `git add -A ulang … tests` after `tests/` was moved away failed with `pathspec 'tests' did not match`, and the commit after it held only the renames of `git mv`, without the edited contents, until amended.
- **A library module `project.u` makes `ulang/prelude/` a root**: `project_root` of `ulang/parse/parse.u` stops at the nearest directory with a file `project.u`, whatever its content, so a module of that name in the library would have made `ulang/prelude/` the root of `ulang/prelude/test/`; `load_package` also leaves `project.u` out of the members. The type `Project` is in `ulang/prelude/os.u` instead.
- **The interpreted parser and checker take about 11 seconds per case** that loads the library, compiled about 35 milliseconds, which decided that `ulang/test/errors/` runs only compiled.
- **A reference in the docs reads every list of backticks before `of`**: "by default `main`, `EntryProc` of `…`" made `checks/docs.u` look for `main` in that file; a word other than a separator between them, "as the entry", ends the list.
- **The cross-references of `TODO.md` go stale when items are deleted**: deleting an item renumbers its section only when the list is renumbered by hand, so Diagnostics went 1, 2, 4, …, which Markdown renders as 1, 2, 3, …, while "Verification 5", "Modules 2", "Compiler 3" of `assembly.md`, and "Checker 4" of the rejected `Option` pointed at items that had moved or gone; `checks/docs.u` checks names of declarations, not these numbers.
- **The doc of `cached` of `ulang/compile/compile.u` claimed that an exception resets the cache**, but the handler was popped before the result expression was evaluated, so a function without parameters whose body is one expression that raises stayed `U_COMPUTING` and reported a recursive initialization at its next use; the result is now computed into a local before the pop.
- **`CLAUDE.md` said both that lets generalize (Syntax) and that they do not (Overloading)**; they did, until Checker 3 removed it.
- **`ulang.sh test file.u` outside a project failed with `cannot list file.u`**: `compiled_only_of` of `ulang/ulang.u` passed the path of the file to `project_root`, which takes a directory and, without a `project.u` above, returns it as the root, which `os_list` then read; inside the repository a `project.u` is always found, so no test saw it.
- **A rename by regular expression must not treat `(` and `)` as boundaries of strings**: excluding them, to spare `"(acc)"`, skipped every name in an argument list, such as `t1` in `zonk_type(s.sub, t1)`; skip the string literals instead.
- **A `local` after a statement is `declaration expected but local found`**: `skip` then `local n := 1` in a procedure body failed so, at the `local`, as if the body had ended; locals are declared only at the start of a body, which `CLAUDE.md` states as a rule of style ("Each `local` is declared at the start of the innermost body"), not as syntax, and the message does not say it.
- **`Gen` of `ulang/syntax/syntax.u` cannot be named in `ulang/compile/compile.u`**, whose own `Gen` of the names it generates hides it, so a helper `free_in_gen(g: Gen, …)` there was a type error `cannot unify ulang/compile/compile.Gen and ulang/syntax/syntax.Gen`; the constructors `GVal` and the like stay visible, so code there matches the shape of a generator inside the statement instead of taking a `Gen`.
- **A lambda's formal takes no type annotation**: `lambda y: Int => not (y < y)` is `=> expected but : found`, since the formals of lambdas are patterns, and patterns have no annotations; the type comes from where the lambda is used, or from the declared type of a local, `local g: Int -> Bool := lambda y => …`.
- **`strip_yield` of `ulang/syntax/syntax.u` is private**, while `strip_expr`, `strip_stmt`, `strip_pat`, and `strip_cmd` are exported, so comparing two `Yield`s without positions in another package took wrapping both in an `EFor` and comparing them by `strip_expr` (`is_identity` of `ulang/lint/lint.u`, on the branch `lint`).
- **A bare constructor without arguments in a pattern is a `PVar`**: `case None =>` parses as `pat_var("None")`, which the checker resolves to the constructor, and `case None() =>` as `PApp`, so a syntactic test of a pattern takes both.
- **A field name has one type in all constructors of a datatype**: `case XCall(…, outs: List[Expr], …)` and `case XCallRaises(…, outs: Int, …)` is the parse error `field outs of Example has different types`; `CLAUDE.md` says so only of names that repeat ("a name may repeat in the constructors of a datatype with the same type"), easy to read as allowed rather than required.
- **A local without a type must be initialized by the leading single assignments of its block**: generated `SBlock(List(Var(x, THole)), …)` followed by a `call` with `out x` was `missing type for x`; `initialized` of `ulang/check/check.u` decides it, which `CLAUDE.md` did not state.
- **A procedure lambda's formal cannot be `_`**: `lambda in _: List[Cmd] => skip end` is `keyword _ is not a name`, while function lambdas take patterns, so `_` works there.
- **`ulang/check` cannot use `format_name`**, which is of `ulang/format`, a later layer; the checker builds texts of names itself.
- **New syntax in the library needs a new seed first**: `make` compiles `ulang/prelude/` with the seed, which rejected `example` in `list.u` (`declaration expected but example found in prelude/list`), and `make selfcompile` depends on `out/ulang.bin`, which `make` then wants to rebuild with the old seed; `make -o out/ulang.c -o out/ulang.bin selfcompile` takes the current binary as it is.
- **The library package is the list `library_modules`, not the directory `ulang/prelude/`**: a new file there is not loaded until it is listed (`package_files` of `ulang/parse/parse.u`), unlike the packages of a project, which are their directories.
- **`raises` is a keyword, so no field or variable may be named so**: the field of `TProc`, `CProc`, and `CProcSig` was first `raises`, which the seed rejected at `make` as `keyword raises is not a name in ulang/syntax/syntax`; it is `raised` (on the branch `raises`).
- **A rule of the checker that the seed's checker breaks on the new sources takes two seeds**: after `raises` became part of `TProc`, the seed compared raises exactly, so it rejected the annotated sources (`cannot unify ParseError and ()`), and `make bootstrap` checks with the same seed; the way through was a copy of the sources with the annotations stripped, built by the old seed into a compiler with the new rules, whose C became the seed, after which `make selfcompile` reported `the seed is unchanged`, since annotations do not change the C.
- **`Str`, `Int`, and the other builtin types are datatypes to the checker**: `is_data` of `ulang/check/sig.u` holds for them, since the builtin section declares them as datatypes without constructors, so a test of "a datatype" by `is_data` admits `raise "x"`.
- **`check.u` exports only `TypeError` and `check_program`**, so a new member of `ulang/check` that needs a part of the checker, such as the exhaustiveness check, needs an export of it (`covers_all`).
- **Diagnostics 3 of `TODO.md` says the checker drops the positions**, "before it drops the positions", which a plan of lint (`lint.md`) took as given, so it planned a record of resolutions as its first step: since `1c2db95` the checked program keeps every part as `At` with its position, so the resolved name and type of a parsed part are found in the checked program by its position, and the item needs rewording.
- **A mode is written once per group of formals and arguments**: `procedure transfer(in amount: Int, ref from: Account, ref to: Account)` and `call transfer(in 15, ref a, ref b)` are the parse errors `) expected but , found`, since a mode covers the formals after it until the next mode; write `ref from: Account, to: Account` and `ref a, b`. `CLAUDE.md` shows the grouping only by examples, `divmod(in a: Int, b: Int, out …)`, and by "the modes `in`, `out`, and `ref` in front of the first formal of their group" of the printer.
- **`make test` crashed once with a segmentation fault** in the tests of `ulang/run/run.u` (`test expressions pass` cut off), on the branch `prover` after adding `ulang/prove/equations.u`; the file alone passed, and the next `make test` passed whole, so the cause is open, maybe the stack or the collector under the whole run.
- **Two branches that each teach the seed a syntax the library uses cannot be merged by either seed**: main's seed parsed `raises` but not `example`, the branch's the reverse, and `ulang/prelude/` used both, so `make` failed with either; the way through was `make` with main's seed and the lines `example` taken out of the library, then, with them back, `make -o out/ulang.c -o out/ulang.bin selfcompile`. `CLAUDE.md` names `make bootstrap` for sources that the seed cannot compile, which does not help here, since the interpreter of the seed parses the same sources.
- **`or_else(a, b)` evaluates `b` also when `a` is `Some`**: arguments are strict, so a fallback written as `or_else(first_equation(…), decided_body(…))` in the unfolding of `ulang/prove/simp.u` did both at every level of a recursive evaluation, which made even `a < b ==> a + 1 <= b` run for minutes; a fallback that costs belongs in a `match` on the first.
- `join` of `str` takes the separator first, `join(" ", strs)`; I wrote `join(strs, " ")`, which the checker rejects only by the types. Its signature has no example; `example join(", ", List("a", "b")) == "a, b"` would settle it.
- An out assigned only inside a `while` whose condition starts true is `OutputUnassigned`, since the checker assumes the loop may not run; assign it before the loop.
- **A clause before the body must end by layout**: with examples after `:=` and the body after them, `example f(1) == 2` followed by a body `-x` or `(a, b)` reads as `2 - x` or `2(a, b)`, since the lexer drops newlines and nothing else ends the expression; found only when converting `ulang/test/examples/arith.u`. An example now ends at the first token on a later line that is not indented deeper than its `example` (`example_tokens` of `ulang/parse/parse.u`), and the `requires` and `ensures` of `prove.md`, planned at the same place, need the same rule.
- **The printer writes some continuation lines at the indentation of the line they continue**: the body of a `let` follows `in` on a line at the indentation of the line of the `let` (`CLAUDE.md`, Style), so an example `(let y := 8 in y) == 8` printed at the indentation of its `example` ended there and did not parse back (`the source does not parse`); examples are printed one level deeper (`spec_text` of `ulang/format/format.u`), which any layout rule of the parser has to take into account.

- The parser of tests (`parse_text`) knows no notation of the prelude, so a text with `>`, `==`, `++`, or the type `Int * Int` fails with `undeclared operator`; the text declares what it uses, and in a module with sections only in `export` (`notations belong to the export section`).
- `format` puts a `let` of several long bindings on one line of 300 characters; split such a body into functions instead.
- `catch` is a keyword, so a variable of type `Catch` is not `catch` (`keyword catch is not a name`).
- `out/ulang.sh test file.u` interprets the current sources of the tested package, so tests of `ulang/lint` run without `make`, while `check --lint` uses the built binary.
- **The parser's recovery depended on the handler of a `try` seeing the variables as before it**: `parse_mod` of `ulang/parse/parse.u` caught the errors of `parse_command` and of `enter_section` in one `try` and skipped from the restored tokens, while for the error of `enter_section` the call before had returned and moved the tokens; clang -O2 lost the copies that `compile.u` makes before `setjmp`, so an unrelated change made the command after one in the wrong section disappear (`builtin_data`), correct in the interpreter and at -O0. Not to fix in the compiler: code relies only on calls giving back no outs and refs when they raise, and the recovery now catches `parse_command` alone.
- **The seed parses only what the language could when it was last replaced**: a doc before a statement, allowed since step 10 of `diagnostics.md`, made `make` fail in the sources of the compiler (`ImportError` of the old message of misplaced comments from `bootstrap/ulang.sh compile`), since the seed's lexer still rejects it; until `make selfcompile` replaces the seed, the sources of `ulang/` cannot use a new syntax, which `CLAUDE.md` says only for keywords.
- **A format error of a member names the first file of its package**: after editing `ulang/prove/translate.u` without formatting it, `make testerrors` reported `"file": "ulang/prove/egraph.u", "module": "ulang/prove/translate"`, so the file to format is the one of the module, not of the file field.
- A word of a command that starts with `-` was taken as a path: after `--lint` was removed from `check`, `check --lint file.u` exited 0 without output, since `targets_of` found no file `--lint`; `paths_request` of `ulang/ulang.u` now rejects options that a command does not take.
- **The checked program holds only definitions**: planning error nodes on commands, I assumed every type error has a command in `Prog.cmds`, but `check_package` of `ulang/check/check.u` keeps only the checked definitions, the tests of examples and lemmas, and generated `CAbstract`s (`is_definition` drops `CFunSig`, `CProcSig`, `CAbstract`), and none at all when an error of a declaration blocks the definitions (`is_blocking`), so the errors of signatures and of declarations have no command there to sit on.
- **A `let` of several bindings binds them in parallel**: `let k := size(fixed), levels := range(d, d + k) in` is `unknown variable k` at the second binding (`ELet` of `ulang/syntax/syntax.u` says so, `CLAUDE.md` too); a binding that uses another takes a `let` of its own, as `assign` does.
- **Levels are the least terms of the order of the prover**: `head_key` of `ulang/prove/syntax.u` puts `ELevel` before every application, so the best term of a class with a variable and an application is the variable; a variable kept for printing, as the definitions of a proof are, would have become the normal form of its value and blocked the rules on it, so extraction ranks the defined levels last (`term_rank` of `ulang/prove/simp.u`).
- **A comma after a `with` in `assign` continues the update**: `assign s := s with errors := …, found := true` was `unknown field found of State`, since `, name :=` after `with` adds a field of the update, not another assignment, as `CLAUDE.md` says under Syntax and translations; a local beside an update takes an `assign` of its own.
- **Another session may rewrite a plan at the root from its own copy**: my revision of `diagnostics.md` was overwritten by a version with another edit of its step 14, so a plan of work on a branch of one's own goes into a file of its own name, as `error-nodes.md` of the worktree `error-nodes`.

## x86 backend (assembly.md)

- Lists have no `at(i, xs)`; I guessed it from `str` and `array`. So it is: `at` exists only for strings and arrays, and a list is indexed by `drop(i, xs)` and a match.
- A field name that two constructors share must have the same type (`field dst of Instr has different types`). `CLAUDE.md` states this, but it is easy to miss when designing instruction datatypes, where `dst` is naturally an `Operand` in one constructor and a `Reg` in another.
- `NumberedName` warns on `utf8`, a standard name whose digit is no index, so it was renamed `utf8_bytes`; `ShowName` warns on `show_fun`, which names the function of the show hook, not a printer.
- `format` realigns `call` lines to `call   ` when a block contains an `assign`, so scripted replacements written against the text before `format` miss lines after it.
- A doc before a statement, which `CLAUDE.md` allows, breaks `make` in the sources of the compiler: the seed is older and reports `ImportError` "a comment is the doc of the command or case on the next line" at it. So it is: until the seed is replaced, the sources of `ulang/` put such notes on the procedure or on a `case`, which the seed takes.
- `check` of a file that imports a package exited with 0 and printed nothing while that package had a type error in an element of a `List(…)` form: the error was found but lost (fixed by `686c75c`), and the check stopped silently after that package. So it was: when `check` passes code that is plainly wrong, compare the raw errors of `check_all` with `diagnostics(q)`, e.g. by a small compiled program in a scratch worktree.
- `diagnostics(q)` and `check_text` disagree by design: `check_text` raises the first error of the working list, so the cases of `ulang/test/errors/` cannot catch an error that the tree loses; such a case reads `diagnostics` of `checked_text`, as `errors_of_forms` does.
- The lemma tests of samples with functions that do not terminate grow memory without bound under `ulimit -s unlimited`, which killed a session; run samples under `ulimit -v` and `timeout`.
- **A field cannot be named by a keyword**: `Spec(requires: …, ensures: …)` was `keyword requires is not a name` at every use, so the fields of a syntax named by its keywords take other names, `pre` and `post`; likewise locals named `test` or `call`.
- **A `Map(…)` comprehension yields `k => v`, not a pair**: `Map(for cmd in cmds for p in proc_of(cmd) yield p)` with a pair `p` is the parse error `=> expected but ) found`; bind the pair by its pattern, `for (k, p) in proc_of(cmd) yield k => p`.
- **A `for` statement takes one generator**, unlike the forms: `for (p, (m, cmd)) in placed for name in f(cmd) do` is `for takes one generator and an optional condition`; build the list by a comprehension first.
- **`enter` of `ulang/check/check.u` resets the substitution for every command**, so types recorded while one command is checked, e.g. the environments at loops, are zonked before the next one, after `settle` in `commands`, or they stay unknowns.
- **`.that` of an `At` raises `MissingField("At.that")` for an `AUnparsed`**, which only partial checks have, e.g. `checked_around_unparsed` of `ulang/test/errors/types.u`; that case runs only compiled, so the interpreted part of `make test` passes and only `make testerrors` fails. Walks of statements of checked programs guard by `is_parsed`.
- **`options` of `ulang/syntax/syntax.u` is private**: other modules write `List(for e in o yield e)`.
- **`make test` took 1m32 to 1m42 here**, of which `make testerrors` about 1 minute, against about 30 seconds in `CLAUDE.md`, while other sessions built in their worktrees.
- **A result of `beta` was checked by hand**: the order of its arguments, the last one `EBound(0)`, matches `bind` of `ulang/prove/translate.u`, the last variable innermost, which only its doc says; a claim whose contract mixes ins and outs proved only once both agreed.

## Experience of the session on lemmas about procedures (2026-11-12)

- What carried the work: the checker's errors, which name the place and often the fix (`add case StepInvariant(_) =>`, the expected and found types), so each edit was followed by `check` of 0.6 seconds and a fix of what it listed; the exhaustive matches over `Cmd`, `Stmt`, and `Step`, which listed every walk that a new constructor reaches; `format`, which removed every question of layout; and the cases of `ulang/test/errors/`, whose expected values come from a run with a placeholder.
- What cost time: scripted replacements written against the text before `format`, which realigns lines, so that they missed and the next check reported the old errors (a helper that asserts that each replacement matches exactly once, and writes nothing otherwise, made that loud); the seed, which accepts less than the sources, here a doc before a statement; and the build of the compiled suite, about a minute per round, which is the only way to run the cases of errors.
- What was hard to see: which side of a sequent a printed goal is, since the printer folds values into the names of definitions, so a goal that should close looked like `a == t ==> a == t`; telling a weakness of the simplifier from a bug of the translation took a reduction to a lemma about values, `via_direct` in `prove.md`, section 1.
- `CLAUDE.md` is dense but was right in every point that was looked up; the few gaps are the entries above.

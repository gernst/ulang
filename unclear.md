# Unclear

Trip-ups and unclear points met while working on ulang code, each with what was wrong and what is so, until the
documentation is fixed from them (see the working rules of `CLAUDE.md`), when they move into the items of `ideas/`.

- A call of a builtin procedure in a scratch program, `os_println(show(y))`, was written without its mode, though every call writes `in` before its ins, also of one argument, `os_println(in show(y))`; the parse error said so.
- A procedure lambda without formals, `lambda in => p(…) end`, and the type `() raises OsError` of a procedure without formals were guesses that do not parse: CLAUDE.md, Semantics, gives the forms of procedure values only with formals, and says nothing of one without.
- **A formal named `test` gives a misleading error at its call**: `test` is a keyword, and the call then reports `name expected but , found; modes come in the order …`, which says nothing of the keyword; renaming the formal, to `tester`, fixed it.
- **`catch case ParseError(message, _)` around `parse_file_text` is `UndeclaredRaise`**, since `ParseError` has other constructors, `ImportError` and `ParseErrors`, which the handler leaves raised; `case e => … parse_diagnostic(e).message` covers them all, as `parsed` of `ulang/refactor/refactor.u` does.
- **A module whose sections are all emptied becomes a file without sections**: `format` writes no empty section, so dropping every export of a module leaves only its declarations, without `export` and `implementation`, which then all count as implemented.
- **A pattern variable named `lemma` gives a parse error far from it**, `the for … has no end`: `lemma` is a keyword, and the message names the construct around it, not the name.
- **`Var.name` is a `Name`, `Id` is `Str`**: a set of the names that an expression reads, `expr_names` of `ulang/lint/lint.u`, is of `Id`, the bases, so a `Var` compares by `x.name.base`; the error was a mismatch of `Set[Str]` and `Set[Name]`.
- **A multi-assignment built as a tree in a test also depends on its meaning**: the lint that found the assignments that read each other walks parsed sources only, and missed the `sum` of the test `procedures` of `ulang/run/run.u`, whose `SAssign` is built by hand and which then computed 14 instead of 10.
- **`check` judges by the built checker, not by the sources**: after an experiment that changed `ulang/check/check.u` and ran `make`, reverting the source left `out/ulang.bin` with the experiment, which kept reporting its errors; and sources halfway through a change of types cannot be built, so a change of the checker's own datatypes is checked by the binary of the commit before, built in a worktree of its own.
- **A type change by text needs word boundaries**: replacing `ms: List[Id]` also changed `params: List[Id]`, which the checker caught only because `Id` and `Path` differ; and `module_text` existed already in `ulang/format/format.u`, for the text of a module from its comments, so a new function of the same name in an imported package overloaded it by arity instead of clashing.
- **`var a, b, c, d: Int` types only `d`**: the type of a declaration of `var` belongs to its own name, so `b` and `c` were `missing type for b`, while `a` took its type as the out of the call right after the declaration; each takes its own, `var a: Int, b: Int, c: Int, d: Int`.
- **An `else if` chain of statements inside a `match` case fails at the head of the `match`**, `the match, or a construct inside it, has no end: end expected but procedure found`, at the line of the `match`, far from the chain: each `else if` opens an `if` of its own that needs its own `end`, so a chain of three branches takes two; a `match` on the next token reads better there.
- **Scratch files in one directory are one package**: a scratch `a.u` beside a `b.u` with errors fails `compile a.u` and prints the errors of `b.u` on `check a.u`, so each scratch program needs a directory of its own.
- **The tests of `ulang/refactor/test/` have no command of their own**: the agents of 15 November 2026 each rebuilt them by hand from `make testerrors`; the command is now in Working on it of `ideas/refactor.md`.
- **`os_write_utf8` makes the directories of the file it writes**, in the runtime and the interpreter, which `ulang/prelude/os.u` does not say, so an `os_mkdir` looked missing where only the listing of a directory that does not exist yet blocked `@put`.
- **A test file for `@fix` without an entry or exports loses its declarations**: `UnusedPrivate` fires on every function and its fix drops them, which hides the edits under test.
- **The worktree of an agent may start at an older commit than `main`**, where `ideas/` numbers its items otherwise, so a brief that names items by number names others; a brief names them by their titles, and the agent merges `main` first.
- **Imported modules drop their examples** (`without_examples` of `ulang/parse/parse.u`), so a tool that shows them, as `@sig` does, reads them from the text by the span of each command.
- **The library of this repository has the ids `prelude/x`**, not `ulang/prelude/x`, so the id of a file checks the directory of the library before the root.
- **`normal_file(here, here, root)` with the root as the working directory gives the absolute root**, not `.`, so it compares with no relative path.
- **There is no negation of expressions**, only negative literals, so `-x` is written `0 - x`; CLAUDE.md says only that `-n` of a number is a literal.
- **`format` does not rewrap comments longer than 120 characters**, which then stay as written.
- **`is_numbered` of `ulang/lint/lint.u` flags only one digit after a letter**, so `sha256` and `x86` were never warned on, while `utf8` and `pop3` were.
- **An interpreted run of one case of `ulang/test/errors/` loads its whole file**, 1.5 to 3.5 minutes per case on a loaded machine, not the cheap run that CLAUDE.md suggests.
- **`pgrep -f` with a pattern that the waiting command contains matches itself**, so a loop that waits on it never ends.
- **The examples of an exported function stand on its signature in `export`**, not on its definition in `implementation`, so a pass that pairs each example with the checked definition at the same position finds none for them; `failed_owners` of `ulang/check/check.u` pairs them by the name of the owner.
- **The binary of `compile --tests` takes the targets of `check --test`, not its options**: `u_run_tests` of `ulang/runtime/ulang.c` reads every argument before `--` as a target, so `--timeout 5` is two missing targets, while CLAUDE.md said that it takes the arguments of `check --test`, until the options of Testing 6 showed the difference.
- **A check in a worktree ran the binary of the main tree**: `../../../out/ulang.sh check` from a worktree without its own `out/` checks by the build of the main tree, which other sessions rebuild from their edits; a worktree runs `make` first and then its own `out/ulang.sh`.
- **The scratchpad of a session is shared by its agents**, so a scratch project of one is written by another unless its name carries the agent's id.
- **A walk named `sorts_in` in `ulang/prove/translate.u` was ambiguous** with `sorts_in` of `ulang/syntax/syntax.u`, which the prover imports and which already gives the names of the types in a type, as a list; overloading by type made each use ambiguous instead of hiding the import.
- **A regression test of an order passed without the fix**: `measure_slots` of `ulang/prove/termination.u` only fails when the function without formals comes first in the component, which the names order, so the case names it `base` before `count`; a case of a bug that depends on an order is checked against the code before the fix.
- **Examples on the definition of an exported function are `ExampleOnDefinition`**: CLAUDE.md, Specifications, says so, but the habit of writing the example at the body is strong, and the error does not block the definition, only fails the example tests; the examples go after `:=` of the signature in `export`.
- **`first` is of pairs only**: `first(xs)` of a list is a mismatch of `(?, ?)` and `List[Str]`; the head of a list is taken by a `match`, or `find(xs, lambda _ => true)`.
- **The lint `UnusedVariable` misses a read by a later binding of the same `let` expression**: `let b := n + 1, c := b * 2 in c` reports `b` as never read, also with tuple patterns, `let (ops, placed, after) := f(next), (more, others, last) := g(after) in …` (`create_children` of `gui/protocol.u`), so the lint does not see the sequential scope of the bindings of one `let`.
- **A module of only a builtin section does not parse**, `builtin follows export`: the `builtin` section must follow an `export` section, which may be empty, as in `ulang/prelude/window.u`, and `format` keeps the empty `export`.
- **A pattern alias that builds has no `CPatAlias` in the checked program**: `with_definitions` of `ulang/check/check.u` replaced the written alias by its checked function, so only the aliases with `_` stayed; `with_alias` now puts the alias with its resolved pattern after the function.
- **The compilers call a function directly only if the type of its name has the arity of the call** (`arity(ty) == size(args)` in `compile_named` of `ulang/compile/compile.u`), so code that an expansion makes after checking needs a function type of the right arity on its names, `TFun` of holes in `form_call` of `ulang/expand/expand.u`, and `THole` makes every such call `u_apply`.
- **`ulang/check/check.u` imports only `ulang/syntax`**, now also `ulang/expand`, while `ulang/format` and `ulang/parse` are imports of its siblings, each member importing what it uses itself, so an edit script that expected `import "ulang/parse"` in `check.u` found none.
- **Checker 5 named failures that did not occur**: a tab after `test`, a line break after `lemma`, and `test(` were classified right, since the text of an unparsed command is its tokens joined by spaces (`skip_command` of `ulang/parse/parse.u`), and `is_tight` never joins a keyword to `(`; only a command that is its keyword alone, `test` at the end of the input, failed, which probes by `compile` showed.
- **A `@patch` line splits at its first ` => `**, so a new text with a lambda or a case arrow takes the block form, the old lines, `=>` alone, and the new lines; and the anchor of `@put after` is a declaration written `file.u:name`, not a bare name.
- **A new builtin that compiled code calls needs the seed first**, also one called only by the interpreter and the library: the seed's `native_procs` of `ulang/compile/lower.u` does not know it, so the C of `make` calls a mangled name that nothing defines; the builtin goes in with the runtime and `lower.u` first, then `make selfcompile`, then its uses.
- **The agents' shell refuses compound commands that mention git after other commands**, and once skipped a `cat >>` of such a command silently, which looked like a bug of `refactor`; and it refuses writes to the scratchpad from a worktree, so the scripts of an agent stay in its worktree's `out/`.

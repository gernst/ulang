# Documentation

1. **An agent that writes programs reads the documentation of the implementation**: `CLAUDE.md` states the language, its implementation, and the workflow together, in sentences that carry a reference in every clause, loaded whole into every session, while the Language section of `README.md` is short but lacks the habits of other languages that fail, which `CLAUDE.md`, Writing ulang, lists. Solution: a reference of the language for writers of programs, `LANGUAGE.md`, by example: the constructs, the semantics of effects and exceptions, the library with its shared names, and what differs from other languages, checked by `checks/docs.u` and its examples by `check`; `README.md` links it, and `CLAUDE.md` keeps the implementation, the workflow, and the style, with a pointer to it in place of Writing ulang. Besides the habits there, it says what tripped up an agent new to ulang: the bindings of one `let` are parallel, so a binding that reads another nests a `let`; lists are mapped and filtered by generators, `List(for x in xs if p(x) yield f(x))`, and flattened by `concat`; evaluation is strict, so `or_else(p(cs), q(cs))` computes both and a recursive grammar of combinators is a function of its input; a `try` restores every variable that its body changes, also a counter passed by `ref`, so what a failed branch learns leaves only by the fields of its exception; an array is copied by each change, where a `Map` keeps state that changes; and `e.head` of a list is a field of `Cons` that raises `MissingField` on `List()`.
2. **Facts that agents tripped over are missing from `CLAUDE.md`** or easy to misread there, collected from their notes. Of the language, for the reference of item 1: a field name that repeats in the constructors of a datatype must have the same type there, which "a name may repeat … with the same type" reads as allowed rather than required; a mode covers the formals and arguments after it until the next mode, `ref a: A, b: B` and `call p(ref a, b)`, shown only by examples; a keyword is no name of a field or a local either. Of the implementation: the types of a module hide those of its imports, so a clash of type names shows only in a module that sees both from elsewhere, a sibling or an importer, and each member that names a type of an imported package imports it itself; a bare constructor in a pattern, `case None =>`, parses as a `PVar` that the checker resolves, and `None()` as a `PApp`, so a syntactic test of a pattern takes both; `is_data` of `ulang/check/sig.u` holds for `Str`, `Int`, and the other builtin types, datatypes without constructors; `enter` of `ulang/check/check.u` resets the substitution for every command, so types recorded while one command is checked are zonked before the next, after `settle`; a reference of `checks/docs.u` reads every list of names in backticks before `of`, so "by default `main`, `EntryProc` of …" names `main` in that file, and a word between them that is not a separator ends the list; and `ulang.sh test` interprets the current sources, while the other commands are the built binary. Of the workflow: `git add` with one path that does not exist stages nothing, so the commit after it holds only what `git mv` staged; replacements scripted against the text before `format` miss, since it realigns `call` lines in a block with an `assign` and merges `local` lines, so a helper asserts that each replacement matches exactly once and writes nothing otherwise; when `check` passes plainly wrong code, the raw errors of `check_all` of `ulang/check/check.u` against `diagnostics` of the checked program show an error that the tree lost; samples with lemmas over functions that may not terminate run under `ulimit -v` and `timeout` (Testing 6); and the durations of `make test` in `CLAUDE.md`, about 40 seconds in sum, were 1m32 to 1m49 in sessions while others built in their worktrees. Solution: each into `CLAUDE.md` or the reference of item 1, where the section it concerns is.

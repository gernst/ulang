# Documentation

1. **An agent that writes programs reads the documentation of the implementation**: `CLAUDE.md` states the language, its implementation, and the workflow together, in sentences that carry a reference in every clause, loaded whole into every session, while the Language section of `README.md` is short but lacks the habits of other languages that fail, which `CLAUDE.md`, Writing ulang, lists. An agent that wrote a mail client of 560 lines through `refactor` (15 November 2026) put it first among what to fix: `CLAUDE.md` is 15,600 words, of which a writer of programs needs about a tenth, and `README.md` with the hints of the errors was enough for its project; a second agent, which wrote a client of 809 lines the same day, read about 25,000 tokens of `CLAUDE.md`, then 98 KB, to use perhaps 2,000, the rules of statements, forms, modes, sections, and overloading among the names of the functions that implement them, missed the half sentence that overloading within a module is only by arity, and asked for a card of about two hundred lines apart from the notes of the implementation, with the habits that fail as its first section. Solution: a reference of the language for writers of programs, `LANGUAGE.md`, beginning with the grammar and the list of keywords and stating each rule by an example that runs, so that claims about values are checked as examples, while `checks/docs.u` checks only that names exist: the constructs, the semantics of effects and exceptions, the library with its shared names, and what differs from other languages, checked by `checks/docs.u` and its examples by `check`; `README.md` links it, and `CLAUDE.md` keeps the implementation, the workflow, and the style, with a pointer to it in place of Writing ulang. Besides the habits there, it says what tripped up an agent new to ulang: the bindings of one `let` are sequential, while the assignments of one `x := a, y := b` are simultaneous, so `y := f(x)` reads the `x` from before; lists are mapped and filtered by generators, `List(for x in xs if p(x) yield f(x))`, and flattened by `concat`; evaluation is strict, so `or_else(p(cs), q(cs))` computes both and a recursive grammar of combinators is a function of its input; a `try` restores every variable that its body changes, also a counter passed by `ref`, so what a failed branch learns leaves only by the fields of its exception; an array is copied by each change, where a `Map` keeps state that changes; and `e.head` of a list is a field of `Cons` that raises `MissingField` on `List()`.
2. **Facts that agents tripped over are missing from `CLAUDE.md`** or easy to misread there, collected from their notes. Of the language, for the reference of item 1: a field name that repeats in the constructors of a datatype must have the same type there, which "a name may repeat … with the same type" reads as allowed rather than required; a mode covers the formals and arguments after it until the next mode, `ref a: A, b: B` and `p(ref a, b)`, shown only by examples; and the `Int`s from -16 to 255 exist once in the runtime, every other one allocates, so `(n % 256 + 256) % 256` allocates where `n % 256` does not. Of the implementation: the types of a module hide those of its imports, so a clash of type names shows only in a module that sees both from elsewhere, a sibling or an importer, and each member that names a type of an imported package imports it itself; a bare constructor in a pattern, `case None =>`, parses as a `PVar` that the checker resolves, and `None()` as a `PApp`, so a syntactic test of a pattern takes both; `is_data` of `ulang/check/sig.u` holds for `Str`, `Int`, and the other builtin types, datatypes without constructors; `enter` of `ulang/check/check.u` resets the substitution for every command, so types recorded while one command is checked are zonked before the next, after `settle`; a reference of `checks/docs.u` reads every list of names in backticks before `of`, so "by default `main`, `EntryProc` of …" names `main` in that file, and a word between them that is not a separator ends the list; `ulang.sh check --test` interprets the current sources, while the other commands are the built binary, so an edit of the checker shows in `check` only after `make`; a hint of `hint_of` of `ulang/check/message.u` is no `Hinted` of `ulang/check/check.u`, so a case reads such a hint by `located_message`; a case of `ulang/test/errors/` runs alone in the interpreter, `check --test ulang/test/errors/types.u:<name>`, since only the walk of `check --test` skips the directory; the message of `OpenLemma` of a gap ends with ` at L.C`, which only the cases of `ulang/test/errors/lemmas.u` show; `Seq` and `Concl` are declared in `ulang/prove/simp.u`, not with the terms in `ulang/prove/syntax.u`; and moving a module out of the library keeps its file until `make selfcompile`, since the seed reads the library modules that it has compiled in. Of the workflow: `git add` with one path that does not exist stages nothing, so the commit after it holds only what `git mv` staged; replacements scripted against the text before `format` miss where it changes the layout, so a helper asserts that each replacement matches exactly once and writes nothing otherwise; when `check` passes plainly wrong code, the raw errors of `check_all` of `ulang/check/check.u` against `diagnostics` of the checked program show an error that the tree lost; samples with lemmas over functions that may not terminate run under `ulimit -v` and `timeout` (Testing 6); `check ulang/ulang.u` does not run the tests of the members of the packages it imports, which imports drop, so the rule that it suffices after a refactor that keeps behaviour misses tests that build the changed datatypes, and should name `check --test` of the changed files too; the binary reads the library from the directory compiled in, so comparing the output of two compilers also compares two libraries, and the reference is taken after a change of `ulang/prelude/`; and the durations of `make test` in `CLAUDE.md`, about 40 seconds in sum, were 1m32 to 1m49 in sessions while others built in their worktrees. Solution: each into `CLAUDE.md` or the reference of item 1, where the section it concerns is; facts from the design review of 5cd2fe1 among them.
3. **Comments may show syntax that the language does not have**: the prelude described lists as `[a, b; xs]`, sets as `{a, b}`, and arrays as `|a, b|` long after the forms replaced them, which an agent reads as ulang (the design review of 5cd2fe1). Solution: a check of `checks/docs.u` that the comments of the sources contain no syntax that the lexer rejects, such as `[a, b]` outside type arguments.

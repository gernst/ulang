# Diagnostics

2. **Hints are text**: the errors give the form to write after `; ` of their message for the habits of other languages that the parser and the checker recognize, but an agent or the VS Code extension cannot carry it out, and the missing cases of a match are given one at a time, by the witness of `NotExhaustive`. Solution: suggested edits as refactorings (item 4), e.g. all the missing cases of a match, or an annotation for an ambiguous use, listed with the diagnostic as edits of item 4 and carried out by `refactor @fix`, as the edits of the lints of item 5 are.
3. **The table of resolutions misses parts**: `hints` of `ulang/check/hints.u`, which the VS Code extension and `@resolve`, `@refs`, and `@sig` read, has no declaration of a use, so definition in the editor needs a search, the types of procedure values at their calls are missing, and so are the uses of types at their names, in annotations, signatures, and datatypes, which a rename of types needs. Solution: the declaration of each use in the table, its file and span, for definition in the editor and in the server of item 7; the types of procedure values at their calls; the uses of types at their names, as written; and the queries as commands of `ulang.sh` too, without a script, `resolve <file> <L.C>`, `refs`, and `sig <module>`, if the editor or the server needs them apart from `hints`.
4. **The refactorings beyond the edit scripts are missing**: `ulang.sh refactor` (Refactoring of `doc/tool.md`) writes declarations and nodes by scripts, renames functions, procedures, pattern aliases, and constructors, moves exports, and applies the edits of the lints by `@fix`, but fills in no missing cases of a match, adds no field to a constructor with its constructions and patterns, changes no signature with its calls, and applies no edits of errors (item 2). Solution: the operations of `ideas/refactor.md`, each refused if any other use resolves differently from before, as `@rename` is; not extracting or inlining, which edits of the text do well enough.
5. **The lints know only the syntax**: `ulang.sh check --lint` (`ulang/lint/lint.u`) rewrites the parsed module, so its patterns cannot ask for types or resolved names, `Some` and `value_or` are those of the library only by convention, a list of a list, `List(for x in xs)`, is not found, the same projection `List(for x in xs yield x.name)` repeated is no rewrite of one expression, and a rule gives its fix in one of two ways, one expression as `replacement` of `Warning` of `ulang/lint/lint.u` or an `Edit` of `ulang/syntax/syntax.u`. Solution: lints that look up the resolved name and the type of a part of the parsed module by its position in the checked program, which keeps the positions but not the forms, which it translates to folds, nor the source that `format` prints; each rule gives its finding as an `Edit` instead of the one expression of `replacement`, from the same match, so that the place found and the edit stay together, while the linter never applies them: `refactor @fix` does, with the re-check of every edit; a lint is kept only if the module checks with its edit; and the compiler may apply the rewrites as the optimizations of Compiler 3. The rules that need the e-graph of the prover are planned in `ideas/lint.md`. Still open among the walks: a `match` of one irrefutable case, which is a `let`; a `case _` where the match names constructors that a new one would need a decision beside, which no criterion of the syntax tells apart from the catch-alls that the rule of style keeps, neither the number of constructors that it stands for nor a recursion of the function, since every `case _` of the project is one that the rule keeps, so that the lint waits for the line `// lint allows …` below and then proposes `expand-wildcard`; an `if contains(k, m)` before a `get(k, m)`, one `match` on `get`, which the sources have no instance of yet; appends in loops elsewhere than to an emptied list, which suggest a `Buffer` and need the types, since `++` of buffers looks the same; a doc repeated on the signature and the definition of an exported name, which the second mail client of 15 November 2026 left twice after exporting by hand, before `@export` moved the doc; an access `e.f` where the type of `e` has constructors without `f` and no enclosing `match` narrows it, such as `xs.head` of `List()`, which raises `MissingField` at run time, counted over the project before it is proposed, since `ideas/rejected.md` keeps the partial accesses; and the formals of private declarations that are never read, which cannot be `_`, since a function passed as a value keeps its arity. And a warning cannot be suppressed: a line in the doc of a command or `case`, `// lint allows ShowName: …` with a reason, that is itself a warning where it suppresses nothing, for a place such as `show_in` of `ulang/run/run.u`, `utf8`, a standard name whose digit is no index, which `NumberedName` warns on, and `show_fun`, the function of a show hook, which `ShowName` warns on, and the rules that `project.u` turns off below a directory, for the unread locals that tests write on purpose; the first uses of the line are the three warnings of `RepeatedExpr` that no rule of shape tells from a repeat, code that writes literal output, which repeats as the output does: `IMov(slot(l), OReg(Rax))` and `ITest(OReg(Rax), OReg(Rax))` in `ulang/compile/x86.u`, and the syntax tree of a test program in `ulang/run/run.u`, where a skip of parts of constructors only would take one of the three.
7. **No language server**: the VS Code extension runs `ulang.bin` per action and reads its JSON lines. Solution: `ulang.bin lsp`, a server in ulang over the packages `parse` and `check`, compiled, behind a thin client in `vscode/`: diagnostics and formatting first, then the edits of item 2 as quick fixes, inlay hints of the inferred `raises` and the types of locals, and definition, hover, references, and rename from the resolutions of item 3, completion last. It reads the framing of JSON-RPC from `io_stdin`, the header lines by `io_read_line` and the body of `Content-Length` bytes by `io_read_bytes`, and needs columns converted between code points and the UTF-16 units of LSP, and checking cached per package; parsing and checking already continue past errors, as an open file needs. The server wraps the table of item 3, so it comes after it; it then also checks unsaved buffers and keeps the checked imports, which `hints` cannot.

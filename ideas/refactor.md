# Refactor: scripted editing of ulang files by `ulang.sh`

The open items of the command `refactor`, from its uses and from its design, and what working on them needs to know. What is built is described in Refactoring of `README.md` and in the entry of `refactor` in `CLAUDE.md`; an item that is done is deleted here. The refactorings in general are Diagnostics 4, the queries `resolve`, `refs`, `sig`, and `names` with the record of resolutions behind them Diagnostics 3.

## Working on it

- **Code**: the script, its actions, and the reply are `run_script` and `run_actions` of `ulang/refactor/refactor.u`, the nodes and their handles `kinded_nodes` of `ulang/refactor/nodes.u`, the command line `refactor_request` of `ulang/ulang.u`, and the diagnostics and format errors of the reply `checked_diagnostics` and `format_errors` of `ulang/ulang.u`.
- **Tests**: scripts on files before and after, one test file per area in `ulang/refactor/test/`, also of the refusals, with a case of each lint rule in `fixes` of `ulang/refactor/test/scripts.u`. `project.u` runs the directory only compiled, since each parse loads the library; a single file named to `check --test` runs interpreted, far too slowly for more than one case. Build and run them by `out/ulang.sh compile --tests ulang/refactor/test -o out/rt/rt.c`, then `cc -O1 -DULANG_LIB='"'$PWD/ulang/prelude'"' -I ulang/runtime out/rt/rt.c ulang/runtime/ulang.c -lgmp -lgc -o out/rt/rt.bin`, a copy of `bootstrap/ulang.sh` as `out/rt/rt.sh`, and `out/rt/rt.sh ulang/refactor/test`, about 25 seconds of C and 50 of tests; the real check, `checked_diagnostics` of `ulang/ulang.u`, is the driver's, so a test passes a check of its own, a procedure of a file and the overlays that reads the overlay of the file before the disk, and a test of `@fix` writes a file with an entry or exports, else `UnusedPrivate` drops its declarations.
- **The design, in the decisions that new work must keep**:
  - Few actions that write code by declaration, a fragment that names itself by name and arity, and follow-ups as diagnostics with handles, which the agent fixes by `@put` at the handles; a named operation only where the follow-ups need an analysis that agents get wrong by hand, modes, raises, moves across modules, and not merely because it would save a script.
  - A script is one transaction, applied by default, reversible by `@undo` (`journal_text` of `ulang/refactor/refactor.u`); the precondition is only that the files parse (`parsed`), where an import that fails, which the parser keeps at its line as an error node (`import_failures` of `ulang/parse/parse.u`), is no failure, since the reply lists the diagnostics that are new or gone, so errors before an edit do not hide what it changed.
  - Edits splice the text of whole declarations and nodes by the spans of the parsed file and `format` prints the result, since comments are not in the tree; a doc moves with its declaration since the splice takes the comments right above it.
  - The actions and checks of a script read its edited texts as overlays of the loader, which lists a directory with the files that the script writes there (`parse_file_overlaid` and `overlaid_files` of `ulang/parse/parse.u`), so nothing is written before the end of a script, but by `@rename`, which still writes its files to check them and restores them where the script is refused or dry.
  - Handles cannot follow their nodes by lines, since `format` moves lines around an edit, so an edit keeps the handles before and after it where `format` moved nothing and else moves them by the text of each node and the paths in the tree of nodes (`rebase` and `aligned` of `ulang/refactor/refactor.u`); an edit from outside makes a handle stale.
  - The postcondition of a rename is the comparison of resolutions, the sequence of resolved names of each command in the order of traversal, modulo the renaming (`commit_rename` and `first_difference` of `ulang/refactor/refactor.u`), read from `hints` of `ulang/check/hints.u`, which has no uses of types and none of fields at their names.
  - The lints never write: a rule gives its edit as an `Edit` of `ulang/syntax/syntax.u` in its `Warning`, from the same match, and only `@fix` applies it (`fix` and `local_splices` of `ulang/refactor/refactor.u`); the edits of errors, planned, take the same path.
  - A change is a refactoring if it needs a choice that the code does not determine, a fix if it is the one edit that removes an error, a canonicalization for lint if the code determines it, it keeps the meaning, and it is better for every reader, and an optimization, for the compiler and never the sources, if it is only faster.
- **Timing**, for judging what a loop costs: a script of check and tests on a project of 1,100 lines takes 0.4 to 0.8 seconds, an `@put` into `ulang/check/check.u` about 2 with the checks before and after about 2.7, and a rename about 3 seconds across three small files but 25 for a name of `ulang/parse/parse.u`. A `--dry` change of a private declaration of `ulang/check/check.u` takes 6.6 seconds, and a `--dry @drop` of its export `check_partial`, which checks the two importers that name it before and after, 16.9 instead of 6.5 without them.
- **Uses**, whose labels the items cite: R and T, the first mail client and its replay; 2T, 2R, and 2W, the second; 3T, the third, 1,142 lines in nine files through 37 scripts against `a6975f8`, whose report is summarized in the items that cite it. All three found the loop of `@put`, follow-ups with handles, `@rename`, and `@undo` right, and left the tool only for what it could not write. 4T, the two agents of 15 November 2026 that wrote `check --overlay` and `os_remove` with every edit of a `.u` file through `refactor`, without a refusal they could not get past. 5T and 5B, the two agents of 16 November 2026 against `c5e8040`, the mail client `umail`, 519 lines in seven files through 10 scripts, and `ubox/`, 860 lines in five files through 12, whose reports are summarized in the items that cite them by the number of each trip-up, 5T11 and 5B4: both judged the loop better than the edits of mainstream languages, with the reply as a diff of diagnostics with handles its best part, and the second made 2 errors of the language in 860 lines where the first made 15 in 519.

## Open items

By priority, each the problem and the solution.

### Modules and files

1. **No move across packages** (2T, 3T): extracting a package took three scripts, `@put` of the new module, `@drop`, and the imports. Solution: `@move decl F` with its doc, tests, and examples, its signature into `export` if it was exported or is used outside, imports added where now needed and removed where unused, refused with the private names it uses that the target does not see and where the imports would form a cycle or break the layers; within a package it needs no imports. `move-test` likewise, refused on a clash of names.

### Replies and addresses

4. **`SignatureMismatch` has no handle**, since it stands at the head of a definition, which is no node. Solution: the head of a definition as a node with a handle (`kinded_nodes` of `ulang/refactor/nodes.u`).
6. **A script is several times slower than the checks it runs** (4T): 18 actions with `@check test` on `ulang/ulang.u` took 3m22, its `--dry` 2m15, while `check --test --prove` of the file takes 59 seconds, and a one-line `@patch` of `ulang/compile/lower.u` 7 seconds. Solution: the checks before and after a script share what they load, `Loaded` of `ulang/parse/parse.u`, where `checked_diagnostics` of `ulang/ulang.u` starts each from nothing, and the check before is kept from a dry run for the run that follows it.

10. **Cascades in the follow-ups** (R14, T, 2T, 3T10, 3T15, 3T16, 4T, a field added to `RCheck` of `ulang/ulang.u`): 17 diagnostics for 6 sites after a change of the fields of a constructor, four for each call of a procedure of the old arity, a construction of a field too few as a unification of two function types, a false `NeverRaised` from errors elsewhere, and an `UndeclaredRaise` at a call inside a `try` that does not say that its handlers miss the new constructor. The messages are Diagnostics 6, to which the last joins: `no handler of EmptyBody of ClientError`; they cost here, where an agent reads every diagnostic of a reply to find the few sites.
11. **Three formats of output** (3T21): errors are JSON lines, warnings and tests plain text, and replies a third form. Solution: `--json`, the edits, the affected sites, and the diagnostics as records, one per line, as the diagnostics are, which the VS Code extension needs too, for rename on F2 and the code actions of item 14.

### Actions

12. **Fields, types, locals, and modules are not renamed** (R17, 2T): `@rename F:T.C.field new` is refused, and `@refs` does not take them. Solution: the record of resolutions of item 21, with the uses of types and of fields at their names; a field renamed in every constructor that has it, its accessors, updates, and the pattern variables that bind it by its name with their uses, refused where the new name hides a local; locals, formals, and type parameters with `HiddenLocal` as the guard; a package by moving its directory and rewriting the imports, refused for paths with `-` or keywords; and the references of the docs, `` `old` of `file` `` by the grammar of `checks/docs.u`, rewritten, where `@rename` now only lists them (`doc_references` of `ulang/refactor/refactor.u`).
14. **Fixes of errors and follow-ups are not applied**: the edits that leave no choice, applied by `@fix` and listed as applied, through the check by which `@fix` refuses an edit of a lint that adds an error: `write-raises` of `UndeclaredRaise` and `UntypedRaise` into the signatures and the procedure types of formals; the removal of an `UnusedImport` and of a `NeverRaised` handler; a qualified name for an `Ambiguous` use where one candidate checks; the hints of the habits of other languages (Diagnostics 2); after an `@put` of a datatype, `_` for a new field in patterns and a removed one dropped from constructions; after an `@put` of a signature, a removed formal dropped from calls whose argument has no effect, and the arguments put in the order of the modes; the examples of an `ExampleOnDefinition` moved to the signature, which took 5T four `@patch` and a `@put`, since `@patch F:name` covers both, so that the old lines occur twice; and the type of a `MissingType` written, that of the out of the later call that assigns it (5T6, 5B3, Checker 3). What needs a value stays a diagnostic: a new field at a construction, a new case of a match, a new `in` at a call.
15. **A fragment with a habit of another language is only refused**: `fragment 1.3, script 4.3: …` with the hint (`parse_message` and `with_script_lines` of `ulang/refactor/refactor.u`). Solution: the corrected fragment in the reply, `corrected:  x := 2`, also for `return`, `break`, `+=`, `+` of strings, `[1, 2]`, modes out of order, a keyword as a name, and an `else if` without its own `end`, which `@retry` applies.
16. **The comparison of resolutions guards only `@rename`**: every action that writes is refused if a use outside its target resolves differently, reported as the use, the name before, and the name after, which a move maps by the old and new module.
17. **Targets and handles**: `module.name/arity` of an overload, `module.T.f` of a field, `module.T.C` of a constructor, and a local as `F:proc/local`, besides those built (`target_of` of `ulang/refactor/refactor.u`); and `gone #9 (replaced by #31)` in the reply of the edit that removed a node.
18. **Named operations, each when a use asks for it**, with tests and refusals in `ulang/refactor/test/`: `expand-wildcard` of a `case _` into the remaining constructors as alternatives, with a group alias where one fits, which a lint of Diagnostics 5 offers; `fill-cases` of what `NotExhaustive` reports, with a body from the agent; `add-formal` with an argument at every call, checked in the caller's scope, `remove-formal`, `reorder-formals`, and `change-mode`, which moves the arguments to the group of the mode; `function-to-procedure`, each call in a statement made a call into a fresh `var`, and the functions that call it inside expressions listed, or turned too by `--transitive`; `tuple-to-record` of a tuple type by its constructions and patterns found by type, as `8e97aed` did by hand; `introduce-alias` of a pattern alias replacing its instances, as `2ab6b2f` did; `rewrite` by pattern, in ulang syntax with metavariables `$x` and `$x...` and `--where` on their types, refused per site where the result does not check, sharing the matcher with the rules of lint; `extract-procedure` of statements, with the modes and raises computed, and `inline`; and `to-case` of a failing program into a case of `ulang/test/errors/`, its exception taken from a run.
19. **Canonical forms that lint lacks**, each a rewrite with a test before and after, for `@fix`: `match c case true => a case false => b end` to `if`, `if not c then a else b` swapped, `if c then skip else s end`, `if a then b else false` to `and` and its dual, `not exists` and `forall` of a negation; `size(xs) == 0` to the empty container, `xs ++ List()`, `s ++ ""`, `e with f := e.f`, `let x := e in x`; `lambda x => f(x)` to `f` where `f` is one declaration; a `foldr` or `foldl` that only conses or inserts to the comprehension; a `try` whose only handler raises what it caught unchanged; a local whose value every path overwrites before reading; a pattern variable that binds a field under another name where the field's name is free; and, opt-in, the definitions of `implementation` in the order of `export`. Smells that lint reports without an edit, since their fix is a choice: `contains` of a list in a loop over another container, `at` or `get` of an association list in a loop, `foldr` over a list that grows with the input, and the same `get(k, m)` repeated in one body, and those of ubox (5B5), each a slow program that passed every check and test, found only by measuring (Library 2): a `++` of strings whose operand is a recursive call of the same function, a `slice(s, i, size(s))` of the rest in a recursion, and `index_of` of a string of one character, `index_of(str(List(c)), s)`. Policy, which rules are on, in `Project` of `ulang/prelude/os.u`, and the rules that are terminating, confluent, and uncontroversial enforced by `check` as `format` is.

### Concurrent edits

20. **Sessions that edit the same files at once**: a script reads, checks, and writes many files, so another session can write in between. Solution, from cheap to thorough: optimistic writes, the hash of each file read compared just before the writes, the script replayed on the new texts if one changed, under a lock `out/refactor.lock` by `flock` held only for the comparison and the writes, each file written to a temporary file and renamed, with `format` and the editor taking the same lock; actions stored as intent addressed by names, so that a replay runs them on any later version; `@rename --keep-old`, which leaves a forwarder that lint reports, for sessions still writing against the old name; `--base HEAD`, the script run on the committed version in memory and replayed on the working tree, with `--patch out.diff` of its own hunks; a merge driver `ulang.sh merge base ours theirs` for `*.u` by declarations, with the diff of declarations of P1 of `ideas/lint.md`; and the journal with the session and time of each script, the replay of an inverse where other edits followed, and `refactor log` of which changes are whose.

### Changes to ulang

21. **The record of resolutions** of Diagnostics 3, which declaration each name, field, type, and constructor resolves to, for item 12, the handles of diagnostics, and item 16.
22. **A single node formats as in its file**, also over error nodes, so that `@show`, `@patch`, and the code of diagnostics always match the file.
23. **Additions that break nothing**: patterns of fields by name, `case Link(url := u)`, the others implicitly `_`, and defaults of fields, `title: Str := ""`, which a construction may leave out at the end, so that adding a field is one `@put` without follow-ups.
24. **Drafting**: a hole `todo`, an expression of any type and a statement, which raises `Todo`, is an open goal for the prover, and whose uses `check --test` lists, so a new constructor is stubbed in each match by `case Scroll(_) => todo`; and an optional inline `export function f(…) := …`, so that a fragment is the whole truth of a declaration.

### Found by the third client outside the tool

25. **Format**: all bindings of a `let … in` stay on one line, 290 columns, and 400 for the 13 of a `let` of the mail client of 16 November 2026 (5T13), and all fields of a constructor, 140, while a list of twelve short strings is spread (3T4); and a comment above one field of a constructor is moved above the whole `case`, where it documents the wrong thing (3T17). Solution: `let` bindings and fields one per line past 80 columns, and the fields of a constructor a sequence of lines of `lined` of `ulang/format/format.u`, which places their comments.
26. **Library**: no way to make an empty directory, while `os_write_utf8` makes the directories of the file it writes; no test of a substring but `index_of(part, s) != None`, no replace, no formatting of dates, and no base64 (3T22); TLS is Library 1, the headers of the build Build 3 (3T0).
29. **No change of the representation of a datatype with its uses** (the owners of names): `Name(path, base)` to `Owned(path, owner, base)` was done by a pattern alias of the old shape, and the matches over it were found only by the `NotExhaustive` of the follow-ups; and moving `format_name` from `ulang/format` to `ulang/syntax` took `@drop` and `@put` (item 1). Solution: none needed for the alias, which worked; the move is item 1.

### Found by the agents of 16 November 2026

42. **A keyword in a fragment cascades over the whole file** (the work on items 4, 8, 33, 36, and 40 of 16 November 2026): `@put ulang/refactor/refactor.u:Parts` of a datatype with a field `builtin: List[(Str, Int)]` replied `fragment 3.62, script 4.62: builtin follows export`, `keyword builtin is not a name`, and then one line `ulang/refactor/refactor.u:N.1: builtin sections have signatures and types without a definition only` for each of about 300 declarations after it, since the parse of the spliced file takes the `builtin` of the field as the start of a section. Solution: the errors of a refused fragment only at the fragment, those at lines of the file after it dropped while one at the fragment explains them, as the hint `keyword builtin is not a name` does.
43. **A refused old line does not show the line it nearly matched** (the work on items 27, 28, 38, 39, and 41): `@patch ulang/refactor/test/declarations.u:patches_arrows` of the block whose old line was `  assert status == 1 and drop(size(reply) - 1, reply) == List("fragment line 1 split …")`, as the script had written it, was refused, `@patch: the old lines, "…", occur in no line of the target as whole lines`, since `format` had broken the line after `List(`, and only `sed -n` of the file showed it. Solution: the refusal of old lines that occur nowhere names the line of the target that shares the longest prefix with the first of them, with its line number, as the layout that `format` gave it.
44. **`@put F:name` of a fragment of several declarations leaves open where the others go** (the same work): to replace `patch` and add its helpers after it, while `patch_line` and `patch_block` changed their arities, the script took `@drop` of the two old ones, `@put F:patch` of `patch` alone, and `@put after F:patch` of the helpers, since the README says only that the others follow the target, not whether one that the file declares already is replaced where it stands or moved after the target, nor whether a new arity of an existing name, which overloading by arity allows, is added beside the old one or refused. Solution: the README says where the other declarations of a targeted `@put` go, and the reply says `added patch_line/5 beside patch_line/4` where a name gains an arity.
45. **The block form of `@patch` matches whole lines only, and its refusal does not name the line form** (Refactor 32 and 3, 16 November 2026): `@patch ulang/parse/parse.u:without_unparsed` with the block `yield m with exported := whole(m.exported)`, `=>`, and the new text replied `rejected`, `@patch: the old lines, "yield m with exported := whole(m.exported)", occur in no line of the target as whole lines`, since the text is the end of a line; the line form `old => new` applied. Solution: a block of one old line that is part of a line is taken as the line form, or the refusal says `write it as old => new`.
46. **`@put` of a fragment of only imports replied an empty note**, `a/a.u: ` after its import line was put (Refactor 32): `put_anchored` noted the empty list of what it did. Now the note is left out where nothing was put; the added import itself is still not named. Solution: `added import p.q` in the note.
47. **An error whose message names a metavariable is new and gone at once** (Refactor 3, 16 November 2026): a `@put` that replaced a test whose generator had an `UnknownContainer` replied `1 new, 3 gone`, with `+ … UnknownContainer: the type ?18 of the container …` and `- … the type ?19 …` at the same position, since `is_same` of `ulang/refactor/refactor.u` compares the codes and messages, not the positions, which edits move, and the numbers of the unknowns in a message depend on what was checked before. Solution: compare the messages with the unknowns renumbered in their order in each, `?1`, `?2`.
48. **A fragment line that starts with `@` ends the fragment, and the refusal does not say so** (the work on items 2, 5, 7, and 13 of 16 November 2026): a script `@patch ulang/ulang.u:usage` whose fragment was the line `@drop T, @patch T, @rename T new, => @drop T, @patch T, @example F:name, @rename T new,`, a part of the text of the usage, replied `rejected`, `@patch ulang/ulang.u:usage takes a fragment of lines old => new, or old lines, a line => alone, and new lines`, since the line started an action of its own; the workaround was an old text that starts before the `@`, ` N, @drop T, …`. Solution: the refusal of an empty fragment names the next line of the script that starts with `@`, which it took as an action, and a fragment line `@@…` writes `@…`.
49. **`@patch` by lines splits at the `=>` of a string as well** (item 27, again in the same work): the line `#4          y := y + 1\n#5        case _ => => #4          y := y + 1\n\n#5        case _ =>`, a change of the expected reply of a test, was refused, `splits at several =>`, so it took a shorter old text without `=>`, `y + 1\n#5 => y + 1\n\n#5`.
50. **The reply of `@patch` shows the node around a changed comment**, not the node below it, which the comment documents: `changed_nodes` of `ulang/refactor/refactor.u` takes the outermost nodes that start on the changed lines, else the innermost around them, so a patch of the comment above a statement in a loop shows the loop. Solution: a changed comment line counts as the line of the node that `with_comments` gives it.
51. **An edit at an element moves a comment at the end of its line**: `span_splice` of `ulang/refactor/refactor.u` keeps the text after a node on its last line with what replaces it, so `@put after` an element whose line ends in `, // note` gives the comment to the new element, and `@drop` of the last element whose previous line ends in a comment leaves its comma. Solution: the separator after a node, `,` or `)`, apart from a comment after it, which stays with the node.

# Refactor: scripted editing of ulang files by `ulang.sh`

The open items of the command `refactor`, from its uses and from its design, and what working on them needs to know. What is built is described in Refactoring of `README.md` and in the entry of `refactor` in `CLAUDE.md`; an item that is done is deleted here. The refactorings in general are Diagnostics 4, the queries `resolve`, `refs`, `sig`, and `names` with the record of resolutions behind them Diagnostics 3.

## Working on it

- **Code**: the script, its actions, and the reply are `run_script` and `run_actions` of `ulang/refactor/refactor.u`, the nodes and their handles `kinded_nodes` of `ulang/refactor/nodes.u`, the command line `refactor_request` of `ulang/ulang.u`, and the diagnostics and format errors of the reply `checked_diagnostics` and `format_errors` of `ulang/ulang.u`.
- **Tests**: scripts on files before and after, one test file per area in `ulang/refactor/test/`, also of the refusals, with a case of each lint rule in `fixes` of `ulang/refactor/test/scripts.u`. `project.u` runs the directory only compiled, since each parse loads the library; a single file named to `check --test` runs interpreted, far too slowly for more than one case.
- **The design, in the decisions that new work must keep**:
  - Few actions that write code by declaration, a fragment that names itself by name and arity, and follow-ups as diagnostics with handles, which the agent fixes by `@put` at the handles; a named operation only where the follow-ups need an analysis that agents get wrong by hand, modes, raises, moves across modules, and not merely because it would save a script.
  - A script is one transaction, applied by default, reversible by `@undo` (`journal_text` of `ulang/refactor/refactor.u`); the precondition is only that the files parse (`parsed`), since the reply lists the diagnostics that are new or gone, so errors before an edit do not hide what it changed.
  - Edits splice the text of whole declarations and nodes by the spans of the parsed file and `format` prints the result, since comments are not in the tree; a doc moves with its declaration since the splice takes the comments right above it.
  - Handles cannot follow their nodes by lines, since `format` moves lines around an edit, so an edit keeps the handles before and after it where `format` moved nothing and else moves them by the text of each node and the paths in the tree of nodes (`rebase` and `aligned` of `ulang/refactor/refactor.u`); an edit from outside makes a handle stale.
  - The postcondition of a rename is the comparison of resolutions, the sequence of resolved names of each command in the order of traversal, modulo the renaming (`commit_rename` and `first_difference` of `ulang/refactor/refactor.u`), read from `hints` of `ulang/check/hints.u`, which has no uses of types and none of fields at their names.
  - The lints never write: a rule gives its edit as an `Edit` of `ulang/syntax/syntax.u` in its `Warning`, from the same match, and only `@fix` applies it (`fix` and `local_splices` of `ulang/refactor/refactor.u`); the edits of errors, planned, take the same path.
  - A change is a refactoring if it needs a choice that the code does not determine, a fix if it is the one edit that removes an error, a canonicalization for lint if the code determines it, it keeps the meaning, and it is better for every reader, and an optimization, for the compiler and never the sources, if it is only faster.
- **Timing**, for judging what a loop costs: a script of check and tests on a project of 1,100 lines takes 0.4 to 0.8 seconds, an `@put` into `ulang/check/check.u` about 2 with the checks before and after about 2.7, and a rename about 3 seconds across three small files but 25 for a name of `ulang/parse/parse.u`.
- **Uses**, whose labels the items cite: R and T, the first mail client and its replay; 2T, 2R, and 2W, the second; 3T, the third, 1,142 lines in nine files through 37 scripts against `a6975f8`, whose report is `agent-report.md` at the root, not versioned. All three found the loop of `@put`, follow-ups with handles, `@rename`, and `@undo` right, and left the tool only for what it could not write.

## Open items

By priority, each the problem and the solution.

### Edits that must not break code

1. **`@fix` applies an edit after which the file no longer checks** (3T3): it applied four false `UnusedVariable` of item 2 and turned a clean module with 19 passing tests into 13 errors, replying `applied, 13 errors`. Solution: `@fix` applies an edit only if the unit has no new diagnostics with it, and lists the others as refused with the diagnostic they would cause, as Diagnostics 5 asks of a lint.
2. **A binding of a `let … in` that only later bindings read is `UnusedVariable`** (3T2): `let a := n + 1, b := a + 1 in b` warns on `a`, since the case of `ELet` in `expr_lints` of `ulang/lint/lint.u` checks each binder against the names of the body only; 10 false warnings in the third client. Solution: each binder against the values of the bindings after it and the body.
3. **`--dry` does not show what would break** (R18, 2T, 3T20): `--dry @drop` of a function that others use replies `would write F` with status 0, since the check reads the files from disk, which a dry run does not write. Solution: check the texts in memory, by `load_file` taking the edited texts of the unit instead of reading them, the overlays of item 24, which item 4 needs too.
4. **The imports of a script are checked against the disk** (3T18): a script that writes a new package and imports it from another file is refused, `the package config has no members`, so a move into a new package takes two scripts and is not atomic. Solution: the loader sees the files that the script writes, by the overlays of item 3.
5. **A local hides a function of the library without a word** (3T5): `out lines: List[Str]` and then `lines := lines(text)` gives `cannot unify List[Str] and Str -> ?5` and an `Unassigned`, while hiding a local is the clear `HiddenLocal`; the short names of the library, `lines`, `size`, `at`, `get`, `first`, `last`, `number`, and `str`, are those that one wants for locals. Solution: an error, or a hint of the mismatch, where a local hides a function that the same body applies, `the local lines hides the function lines of prelude/str, which this body calls`.

### Modules and files

6. **`@put F` into a directory that does not exist is refused** (3T1), `cannot list …`, naming neither the action nor the way out, the only step of the third client outside the tool. Solution: `@put` of a new module makes its directory.
7. **No move across packages** (2T, 3T): extracting a package took three scripts, `@put` of the new module, `@drop`, and the imports. Solution: `@move decl F` with its doc, tests, and examples, its signature into `export` if it was exported or is used outside, imports added where now needed and removed where unused, refused with the private names it uses that the target does not see and where the imports would form a cycle or break the layers; within a package it needs no imports. `move-test` likewise, refused on a clash of names.
8. **Moving a private procedure under `export` is `SignatureMismatch` without the difference** (3T19): the definition lacked the raises that had been inferred while it was private, and the error had no handle. Solution: `@put` of a signature into `export` writes the inferred raises, as `@export` does (`export_target` of `ulang/refactor/refactor.u`), and `SignatureMismatch` names the part that differs.

### Replies and addresses

9. **Cascades in the follow-ups** (R14, T, 2T, 3T10, 3T15, 3T16): 17 diagnostics for 6 sites after a change of the fields of a constructor, four for each call of a procedure of the old arity, a construction of a field too few as a unification of two function types, a false `NeverRaised` from errors elsewhere, and an `UndeclaredRaise` at a call inside a `try` that does not say that its handlers miss the new constructor. The messages are Diagnostics 6, to which the last joins: `no handler of EmptyBody of ClientError`; they cost here, where an agent reads every diagnostic of a reply to find the few sites.
10. **Comments are not shown** (3T12): a `//` above a statement of a fragment is kept in the file, but neither the echo of the placed node nor `@show F:decl #h` shows it, so the agent took it for lost and read the file. Solution: the echo and `@show` print the comments of their region, as `format` places them.
11. **A text target with quotes is not found** (3T14): `@show client.u:run "case List(\"fetch\")"` fails, since the text is taken raw between the first and the last quote, and its refusal took four other queries of the script with it. Solution: the escapes of literals in a text target, a line on it in Refactoring of `README.md`, and the queries of a refused script answered nonetheless.
12. **Handles of expressions are undocumented** (3T13): each element of a list that `format` spread over lines gets a handle, 169 handles for 1,100 lines, and `@put` at one works, while `README.md` names only statements, cases, constructors, and bodies. Solution: say so in Refactoring of `README.md`.
13. **Three formats of output** (3T21): errors are JSON lines, warnings and tests plain text, and replies a third form. Solution: `--json`, the edits, the affected sites, and the diagnostics as records, one per line, as the diagnostics are, which the VS Code extension needs too, for rename on F2 and the code actions of item 17.

### Actions

14. **Fields, types, locals, and modules are not renamed** (R17, 2T): `@rename F:T.C.field new` is refused, and `@refs` does not take them. Solution: the record of resolutions of item 25, with the uses of types and of fields at their names; a field renamed in every constructor that has it, its accessors, updates, and the pattern variables that bind it by its name with their uses, refused where the new name hides a local; locals, formals, and type parameters with `HiddenLocal` as the guard; a package by moving its directory and rewriting the imports, refused for paths with `-` or keywords; and the references of the docs, `` `old` of `file` `` by the grammar of `checks/docs.u`, rewritten, where `@rename` now only lists them (`doc_references` of `ulang/refactor/refactor.u`).
15. **Examples have no handles and no action** (2W): `@patch F:name` reaches the examples on the signature of an export, but the lines of a spec are no nodes. Solution: the examples, contracts, and other lines of a spec as nodes with handles, and `@example F:name` of a fragment of examples added to the spec wherever it stands.
16. **No query of a signature** (3T): the agent read the prelude to learn the types of library names. Solution: `@sig name` and `@sig module`, the exported signatures without bodies, and `resolve` of a position, the queries of Diagnostics 3 as actions.
17. **Fixes of errors and follow-ups are not applied**: the edits that leave no choice, applied by `@fix` and listed as applied, through the check of item 1: `write-raises` of `UndeclaredRaise` and `UntypedRaise` into the signatures and the procedure types of formals; the removal of an `UnusedImport` and of a `NeverRaised` handler; a qualified name for an `Ambiguous` use where one candidate checks; the hints of the habits of other languages (Diagnostics 2); after an `@put` of a datatype, `_` for a new field in patterns and a removed one dropped from constructions; after an `@put` of a signature, a removed formal dropped from calls whose argument has no effect, and the arguments put in the order of the modes. What needs a value stays a diagnostic: a new field at a construction, a new case of a match, a new `in` at a call.
18. **A fragment with a habit of another language is only refused**: `fragment 1.3, script 4.3: …` with the hint (`parse_message` and `with_script_lines` of `ulang/refactor/refactor.u`). Solution: the corrected fragment in the reply, `corrected:  x := 2`, also for `return`, `break`, `+=`, `+` of strings, `[1, 2]`, modes out of order, a keyword as a name, and an `else if` without its own `end`, which `@retry` applies.
19. **The comparison of resolutions guards only `@rename`**: every action that writes is refused if a use outside its target resolves differently, reported as the use, the name before, and the name after, which a move maps by the old and new module.
20. **Targets and handles**: `module.name/arity` of an overload, `module.T.f` of a field, `module.T.C` of a constructor, and a local as `F:proc/local`, besides those built (`target_of` of `ulang/refactor/refactor.u`); and `gone #9 (replaced by #31)` in the reply of the edit that removed a node.
21. **Named operations, each when a use asks for it**, with tests and refusals in `ulang/refactor/test/`: `expand-wildcard` of a `case _` into the remaining constructors as alternatives, with a group alias where one fits, which a lint of Diagnostics 5 offers; `fill-cases` of what `NotExhaustive` reports, with a body from the agent; `add-formal` with an argument at every call, checked in the caller's scope, `remove-formal`, `reorder-formals`, and `change-mode`, which moves the arguments to the group of the mode; `function-to-procedure`, each call in a statement made a call into a fresh `var`, and the functions that call it inside expressions listed, or turned too by `--transitive`; `tuple-to-record` of a tuple type by its constructions and patterns found by type, as `8e97aed` did by hand; `introduce-alias` of a pattern alias replacing its instances, as `2ab6b2f` did; `rewrite` by pattern, in ulang syntax with metavariables `$x` and `$x...` and `--where` on their types, refused per site where the result does not check, sharing the matcher with the rules of lint; `extract-procedure` of statements, with the modes and raises computed, and `inline`; and `to-case` of a failing program into a case of `ulang/test/errors/`, its exception taken from a run.
22. **Canonical forms that lint lacks**, each a rewrite with a test before and after, for `@fix`: `match c case true => a case false => b end` to `if`, `if not c then a else b` swapped, `if c then skip else s end`, `if a then b else false` to `and` and its dual, `not exists` and `forall` of a negation; `size(xs) == 0` to the empty container, `xs ++ List()`, `s ++ ""`, `e with f := e.f`, `let x := e in x`; `lambda x => f(x)` to `f` where `f` is one declaration; a `foldr` or `foldl` that only conses or inserts to the comprehension; a `try` whose only handler raises what it caught unchanged; a local whose value every path overwrites before reading; a pattern variable that binds a field under another name where the field's name is free; and, opt-in, the definitions of `implementation` in the order of `export`. Smells that lint reports without an edit, since their fix is a choice: `contains` of a list in a loop over another container, `at` or `get` of an association list in a loop, `foldr` over a list that grows with the input, and the same `get(k, m)` repeated in one body. Policy, which rules are on, in `Project` of `ulang/prelude/os.u`, and the rules that are terminating, confluent, and uncontroversial enforced by `check` as `format` is.

### Concurrent edits

23. **Sessions that edit the same files at once**: a script reads, checks, and writes many files, so another session can write in between. Solution, from cheap to thorough: optimistic writes, the hash of each file read compared just before the writes, the script replayed on the new texts if one changed, under a lock `out/refactor.lock` by `flock` held only for the comparison and the writes, each file written to a temporary file and renamed, with `format` and the editor taking the same lock; actions stored as intent addressed by names, so that a replay runs them on any later version; `@rename --keep-old`, which leaves a forwarder that lint reports, for sessions still writing against the old name; `--base HEAD`, the script run on the committed version in memory and replayed on the working tree, with `--patch out.diff` of its own hunks; a merge driver `ulang.sh merge base ours theirs` for `*.u` by declarations, with the diff of declarations of P1 of `ideas/lint.md`; and the journal with the session and time of each script, the replay of an inverse where other edits followed, and `refactor log` of which changes are whose.
24. **Editor buffers and the texts of a script**: unsaved edits in VS Code are versions too. Solution: overlays, `--overlay F=<path>`, the texts that `load_file` takes instead of the disk, for the extension and for items 3 and 4.

### Changes to ulang

25. **The record of resolutions** of Diagnostics 3, which declaration each name, field, type, and constructor resolves to, for item 14, the handles of diagnostics, and item 19.
26. **A single node formats as in its file**, also over error nodes, so that `@show`, `@patch`, and the code of diagnostics always match the file.
27. **Additions that break nothing**: patterns of fields by name, `case Link(url := u)`, the others implicitly `_`, and defaults of fields, `title: Str := ""`, which a construction may leave out at the end, so that adding a field is one `@put` without follow-ups.
28. **Drafting**: a hole `todo`, an expression of any type and a statement, which raises `Todo`, is an open goal for the prover, and whose uses `check --test` lists, so a new constructor is stubbed in each match by `case Scroll(_) => todo`; and an optional inline `export function f(…) := …`, so that a fragment is the whole truth of a declaration.

### Found by the third client outside the tool

29. **Format**: all bindings of a `let … in` stay on one line, 290 columns, and all fields of a constructor, 140, while a list of twelve short strings is spread (3T4); and a comment above one field of a constructor is moved above the whole `case`, where it documents the wrong thing (3T17). Solution: `let` bindings and fields one per line past 80 columns, and the fields of a constructor a sequence of lines of `lined` of `ulang/format/format.u`, which places their comments.
30. **Messages of locals**: `var a, b, c` before several calls is `MissingType` for all but the first, where `LANGUAGE.md` says that only the call right after the declaration gives the type, which the message should say (3T9); and `NumberedName` warns on a local `pop3`, a standard name whose digit is no index, which waits for `// lint allows` of Diagnostics 5 (3T11).
31. **Library**: no `os_remove` and no `os_mkdir`, so tests leave files in `out/`; no test of a substring but `index_of(part, s) != None`, no replace, no formatting of dates, and no base64 (3T22); TLS is Library 1, the headers of the build Build 3 (3T0).

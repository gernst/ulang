# Library

2. **Common helpers are missing**, which programs write again, as the Markdown converter of an agent did: `at` of lists, `trim`, `lines`, `take_while`, `drop_while`, and `span`. Solution: add those that are clearly general, as Code 4 asks, since every name of the library is a candidate of overloading in every module.
3. **Files are whole**: `os_read_utf8` and `os_read_bytes` read a file to its end, so standard input, which a client keeps open while it waits for its answer, cannot be read by lines, as the server behind inetd of `ideas/examples.md` and the language server of Diagnostics 11 need, and a large file is read at once. Solution: an abstract builtin type `IO` of `os` for files, standard input and output, and later sockets, with `io_stdin()` and the procedures `io_open(in path, mode, out io)`, `io_read_line(in io, out line: Option[Str])`, `io_read_bytes(in io, n, out bytes: Array[Byte])`, `io_write_utf8`, `io_write_bytes`, and `io_close`, names of their own since overloading within `os` is only by arity; the encoding is per call, as for paths, and lines are decoded whole, so no read splits a code point. A handle is passed `in`, since its state is the system's, which a `try` does not undo, as it does not undo a written file, a limit of the atomic effects to document; it is closed explicitly, since a procedure that closes on every exit would be generic over what its body raises, which procedure types are not, and the collector closes a forgotten one; handles are equal by identity and shown by their paths; the interpreter keeps the host's `IO` in a constructor of `Val`, which takes one more update of the seed. First `io_stdin` and `io_read_line` alone, which settle the design before files and sockets.

2. **Common helpers are missing**, which programs write again, as the Markdown converter of an agent did: `at` of lists, `trim`, `lines`, `take_while`, `drop_while`, and `span`; a mail client wrote `lower`, `drop_spaces`, and its own lines again, missed `upper` and a search of a substring, and `examples/grep.u` writes its lines too, where `split(text, '\n')` gives a last empty line for a text that ends with a newline, which the client sent to its server. Solution: add those that are clearly general, as Code 4 asks, since every name of the library is a candidate of overloading in every module.
3. **`os_print` does not flush when the output is a pipe**: `p_os_print` of `ulang/runtime/ulang.c` writes to `stdout` without `fflush`, while `io_write_utf8` on `io_stdout` flushes (`write_utf8`, for `stdout` and `stderr`), so a program that prints a request by `os_print` and then reads the reply from stdin waits forever, as a mail client whose server was its stdin and stdout would have, had its agent not read the runtime first, and no doc of `os` or `io` says so. Solution: `os_print` flushes as `io_write_utf8` does, or at least before every read of stdin, in both backends.
4. **Programs of the system lack the environment and the network**: no variables of the environment, no sockets, and no processes (Build 1), so a mail client took its credentials from a file and its server on stdin and stdout. Solution: `os_env` of a variable as an option, and later sockets as streams of `IO` of `ulang/prelude/io.u`, in both backends.

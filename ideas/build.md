# Build

2. **Every compiled program contains the C of all the packages it loads**, which `cc` parses again for each program, although it drops what nothing reaches, since the generated C is `static` except what `ulang/runtime/ulang.h` declares extern (`runtime_referenced` of `ulang/compile/lower.u`, `Linkage` of `ulang/compile/c.u`): the library was about 106 KB of the 123 KB of C of a small test of strings, about 70 ms of its 175 ms of `cc -O2` (2026-11-11), the compiler's `cc -O2` takes about 11 s, and the C of the library and the compiler is translated and parsed again for the binary of the tests of the project, `out/suite/suite.bin`, after any change of a `.u` file. Parked until a profile of `make testc` shows that `cc` of the library dominates its loop. Solution: packages compiled separately, each once, into a static archive, which programs link, with the library as the package `prelude`, a case of the same mechanism, not a special one; no shared libraries, which would need position-independent code, rpaths, and versions of their own, for no gain in binaries that tests throw away.
   - What makes it possible: every value is a `u_value`, without specialization by type, so one compiled `list.foldr` serves all callers; checked programs carry only resolved names, `Name(m, …)` of the path `m` of their module, which `mangle` and `c_text` of `ulang/compile/lower.u` make stable C names; orders, equality, and show are reached through the descriptors `t_…` of the types, not called by the users of a type; and the front end checks every loaded package anyway, so each unit has the whole `Defs` and declares what it references of other modules itself, without generated headers, as `prototypes` of `ulang/compile/compile.u` does for a unit itself.
   - Units: one C file and object per member, collected in `out/lib/<package>.a`, the id with `/` mangled as in C names, compiled by `-ffunction-sections -fdata-sections` and linked by `-Wl,--gc-sections`, so that the linker keeps only what is reached, which replaces `runtime_referenced`, and `cc` runs in parallel. Three linkages instead of the two of `Linkage`: defined once and extern, the functions, procedures, caches of functions without parameters, and the descriptors `t_…` and names `n_…` of datatypes, in the module that declares them; defined once and hidden, `__attribute__((visibility("hidden")))`, the private declarations, which the tests of the member link, and which never clash, since mangled names carry the module; and derived per unit and `static`, what each unit builds from `Defs` for what it references, the wrappers `w_`, `wc_`, and `wp_`, the tables of fields of `u_select` and `u_update`, string literals, and lifted lambdas, whose numbered names are unique per unit only, where duplicates are harmless and small. The archive of `prelude` holds the runtime too, and the formats `u_text_*`, so that the runtime's references to `t_list_46_List` and the like resolve within it.
   - Commands: `compile --package <dir> <outdir>` checks the package with its imports and writes the C of each member, without tests, and its stamp, while `cc -c` and `ar rcs` stay with the Makefile; `compile --separate <file> <entry> <target.c>` writes only the modules of the program, or with the entry `test` only the tests of a member, with `main`, linked with the archives in the order of loading reversed, users before what they use, `out/lib/prelude.a` last; `packages <file>` prints the ids of the packages it loads, in load order, for the Makefile to build their archives first.
   - Code: `compile_program` of `ulang/compile/compile.u` translates a selection of modules, `q.cmds` by the module of each name, with `Defs` still of the whole program; `wrappers` emits those of what the unit references, also in the whole-program mode, which then shrinks too; `descriptor_decls`, `data_decls`, and `field_table_decls` by module, descriptors where the datatype is declared and tables where they are used; `Linkage` gets a hidden linkage, decided by `linkage_of` by the module and the export, while `runtime_referenced` stays for the whole-program mode; and `texts` only in the unit of `prelude` and in the whole-program mode. Then the options of `ulang/ulang.u`, the archives of the Makefile and the suite of the tests alone by `compile --tests --separate`, and in `CLAUDE.md`, Build, the modes of `compile` and the archives.
   - Staleness: each archive defines a symbol `u_stamp_<package>_<hash>` of the hash of its inputs, the sources of its members, the stamps of the packages it imports, the runtime, the flags, and the tool, which each unit that uses the package references, so that a program linked with an archive of another build fails to link, not at run time.
   - Kept: the whole-program translation, the default of `compile`, for the seed, `bootstrap/ulang.c`, which stays one self-contained C file, and for `make selfcompile`, which compares such files, whose compiler must still pass `make test`, while `make testc` runs the separate mode.
   - Lost: `cc` no longer inlines functions of other packages, such as those of `option`, into their users; inlining at the level of ulang (Compiler 3) gets it back, since the front end sees the sources, and `-flto` meanwhile, at the cost of time, so the run times of the compiled compiler are compared before and after, with and without `-flto`.
   - Clash: a project with a directory `prelude/` at its root, which already clashes with the library in C, gets duplicate symbols when linking, which `doc/implementation.md` states.
   - Backends: the plan is of C, whose `cc` it saves most; `ulang/compile/x86.u` has its own `wrappers`, `data_decls`, and `texts`, and its objects need only the linker, 0.04 s for the compiler's on 5ad5ed1, so whether the assembly backend compiles separately too is open.
   - Steps: first time `compile --tests` and `cc -O1` of the suite, and the C and `cc` of an empty program, to know what the archives can save; then the hidden linkage, the selection of modules, and the wrappers and tables per unit in the whole-program mode, which must give the same results of `make test` and `make testc`, the C compared before and after in a worktree; then `--package` and the archive of `prelude`, linked by the binary of the tests and by `--separate` for programs that load only the library; then any package, `packages`, the archives of the packages that the tests load, the suite of the tests alone, and stamps; then the build of the suite measured against the first step.
   - Open: whether the tests of a member link the archive of their own package, which holds the member's code without its tests, assumed here as the simpler, or compile the member into their unit and link an archive without that member, which needs an archive per member left out.

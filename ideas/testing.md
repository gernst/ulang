# Testing

1. **Properties of code are only tested by lemmas**, whose tests `l.lemma` enumerate the values of their formals (`lemma_tests` of `ulang/check/check.u`), while the formals of tests are reserved but rejected. Solution: tests with formals, `test append_size(xs: List[Int], ys: List[Int]) := assert …`, by the same translation with the body of the test in place of the statement of the lemma, where the examples of the functions that the test calls are its first cases; then `TestParams` goes. They give the evidence "tested" of Verification 2.
2. **The tests of lemmas are limited**: a counterexample is a string in quotes inside `uncaught exception Falsified("…")`, with the escapes of the `Str` formals; type parameters are only `Int`; the depth is chosen once, so a lemma over two lists sees lists of at most 2 elements, and one whose assumptions small values do not meet, `requires n > 100`, is `Vacuous`; and abstract types are not enumerated. Solution: the runners print `Falsified` of `ulang/prelude/enumerate.u` as `falsified for x = 1, …`, in both backends; abstract types enumerated by their exported constructions, from the examples of their functions or a declared enumeration; and random values beyond the depth, by a seed in the name of the test, when a lemma needs larger cases.
3. **Examples are seen only in the source**: `ulang.bin sig` and the hover of the VS Code extension (Diagnostics 3) do not show them, the `▶ Run` links of the extension do not reach them, and a failure reads `assertion failed: 3 != 6` instead of `example 1 of gcd failed: gcd(12, 18) gave 3, expected 6`. Solution: `sig` and the hover print the examples below the signature, the extension shows `▶ Run` above each, and the test of an example asserts by a statement that knows its call.
4. **The texts of tests parse without the notation of the library**: `parse_text` of `ulang/parse/parse.u` uses the empty notation, so a text with `>`, `==`, `++`, or the type `Int * Int` fails with `undeclared operator` unless it declares them, and a module with sections only in `export`. Solution: `parse_text` with the notation that every module sees from the library, computed once, e.g. by a function without parameters, or passed in: reading the library from its files at each call, as `parse_texts` does, made the interpreted tests of `ulang/parse/parse.u` and `ulang/test/lint/lint.u` about 70 times slower, 2 s against 2 min 21 s; the texts that declare operators of the library then drop them, which is `operator ++ is already declared` otherwise, and `warning_text` of `ulang/lint/lint.u`, which formats replacements in a source without the library, needs the source with it.
5. **A case cannot catch an error that the tree of the checked program loses**: `check_text` of `ulang/test/cases/cases.u` raises the first error of the list that the checker builds, not of `diagnostics` of the checked program, which is what `check` prints, so a case of a lost error reads `diagnostics` of `checked_text` by hand, as `errors_of_forms` of `ulang/test/errors/types.u` does. But a `Diagnostic` of `ulang/syntax/error.u` does not hold the `TypeError` that the cases match on, about 167 patterns `Located(…)`, also by its structure, as `Mismatch(_, _, "an element of List")`. Solution: decide between an exception over a `Diagnostic`, which changes every such case to a code and a position, and `check_text` that keeps raising the first `TypeError` but fails with an internal error unless the first of the diagnostics has its position and code, which catches a lost error without touching the cases.
6. **The tests of lemmas over functions that do not terminate grow memory without bound** under the `ulimit -s unlimited` of `ulang.sh`, which once killed a session, so samples run under `ulimit -v` and `timeout` by hand. Solution: the tests of lemmas, and test runs in general, take a limit of memory and time, e.g. options of `test`, with a failure that names the test.
7. **`make test` crashed once with a segmentation fault** in the tests of `ulang/run/run.u`, on the branch `prover` after adding `ulang/prove/equations.u`, while the file alone and the next `make test` passed, so the cause is open, maybe the stack or the collector over the whole run. Solution: find it when it recurs, by a core dump of the run and the seed of its order.

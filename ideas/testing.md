# Testing

1. **The tests with formals start from the smallest values only**: they run on the enumerated values of their formals (`enumerated_tests` of `ulang/test/generate.u`), so the calls that the examples of the functions under test document are not among their cases, and they run after the other tests of their module, not in the order of the source. Solution: the examples of the functions that the test calls as its first cases, and the runners in the order of the source. They give the evidence "tested" of Verification 2.
2. **The tests of lemmas are limited**: a counterexample is a string in quotes inside `uncaught exception Falsified("…")`, with the escapes of the `Str` formals; type parameters are only `Int`; the depth is chosen once, so a lemma over two lists sees lists of at most 2 elements, and one whose assumptions small values do not meet, `requires n > 100`, is `Vacuous`; and abstract types are not enumerated. Solution: the runners print `Falsified` of `ulang/test/enumerate/enumerate.u` as `falsified for x = 1, …`, in both backends; abstract types enumerated by their exported constructions, from the examples of their functions or a declared enumeration; and random values beyond the depth, by a seed in the name of the test, when a lemma needs larger cases. The first of these is step 5 of `ideas/tester.md`.
3. **Examples are seen only in the source**: `ulang.bin sig` and the hover of the VS Code extension (Diagnostics 3) do not show them, the `▶ Run` links of the extension do not reach them, and a failure reads `assertion failed: 3 != 6` instead of `example 1 of gcd failed: gcd(12, 18) gave 3, expected 6`. Solution: `sig` and the hover print the examples below the signature, the extension shows `▶ Run` above each, and the test of an example asserts by a statement that knows its call.
4. **The texts of tests parse without the notation of the library**: `parse_text` of `ulang/parse/parse.u` uses the empty notation, so a text with `>`, `==`, `++`, or the type `Int * Int` fails with `undeclared operator` unless it declares them, and a module with sections only in `export`. Solution: `parse_text` with the notation that every module sees from the library, as `parse_texts` reads the library from its files.
5. **A case cannot catch an error that the tree of the checked program loses**: `check_text` of `ulang/test/cases/cases.u` raises the first error of the list that the checker builds, not of `diagnostics` of the checked program, which is what `check` prints, so a case of a lost error reads `diagnostics` of `checked_text` by hand, as `errors_of_forms` of `ulang/test/errors/types.u` does. Solution: `check_text` raises from the diagnostics of the checked program.
6. **The tests of lemmas over functions that do not terminate grow memory without bound** under the `ulimit -s unlimited` of `ulang.sh`, which once killed a session, so samples run under `ulimit -v` and `timeout` by hand. Solution: the tests of lemmas, and test runs in general, take a limit of memory and time, e.g. options of `test`, with a failure that names the test.
7. **`make test` crashed once with a segmentation fault** in the tests of `ulang/run/run.u`, on the branch `prover` after adding `ulang/prove/equations.u`, while the file alone and the next `make test` passed, so the cause is open, maybe the stack or the collector over the whole run. Solution: find it when it recurs, by a core dump of the run and the seed of its order.

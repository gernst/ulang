# Modules

The items in the order proposed for them: item 1 first, of most value (`ideas/index.md`); then item 2, two narrow fixes; item 3 only after its profile; item 4 parked with Later 1.

1. **Names cannot be qualified by their package**, and names and their modules are spelled in two ways. Two imported packages that declare a type of the same name make every use of it `Ambiguous` (`normalize` of `ulang/check/check.u`), and a clash that overloading by type cannot decide has no way around it but renaming: `ulang/prove/` imports `ulang/syntax` only since its `Expr` and `Branch` became `Term` and `TermBranch` of `ulang/prove/syntax.u`, and it still shares the constructors `EApp`, `ELam`, `EIte`, and `EMatch`, told apart by type. Where the types of a module hide those it imports or those of the library (`CLAUDE.md`, Modules), it cannot name the others at all: `Gen` of `ulang/syntax/syntax.u` cannot be named in `ulang/compile/compile.u`, whose own `Gen` hides it, so code there matches the shape of a generator instead of taking a `Gen`. And a module is a `Path` of `ulang/syntax/syntax.u`, the list of its names, which `Name(path, base)` holds and messages show with `.`, `ulang.check.check` (`path_text` of `ulang/syntax/syntax.u`), and imports write it so, `import ulang.syntax`, since the first steps, while the names that phases make join their parts by `.` inside the base, the accessors `T.f` (`accessor_name` of `ulang/check/defs.u`), the tests `l.lemma` and `f.example.N`, and `(enum)m.T` (`enum_fun_name` of `ulang/test/generate.u`), which Code 3 counts among the names encoded in strings. The checker resolves qualified uses already, `visible_names` and `overloads` of `ulang/check/check.u` taking a `Name(m, base)` whose path is not empty as exactly the declaration of module `m`; what is missing is syntax, one spelling of paths, and a rule for clashes. Solution:
   - **Paths**: a name is a list of names, its path and its base, `Name(path: List[Id], base: Id)`, where the empty path is an unqualified name; ids of modules and packages are such paths too, `ulang.check.check` and `ulang.check`, written with `.` everywhere, in imports, `import ulang.syntax`, in qualified uses, in messages, and in the field `module` of a diagnostic, and with `/` only as files on disk, where a function maps the path of a package to its directory. The names of a path are names of the language, also keywords, as the names of an import path are now.
   - **The library is no exception**: its packages are named by their paths as those of a project are, `prelude` and its members `prelude.list`, `prelude.os`, imported implicitly as now, and qualified as any other, `prelude.Option`; so `import prelude` and a directory `prelude/` at the root of a project stay errors, the one clash of paths that the library makes. Only C keeps the names of the files of the library, `t_list_46_List` and `"os.OsError"`, which the runtime and the seed refer to (`c_text` of `ulang/compile/lower.u`).
   - **Qualified uses**: the path of a package that the module sees, written before the name, `ulang.syntax.Expr` in types, `case ulang.syntax.EApp(f, args) =>` in patterns, where `.` does not occur now, so the parser builds the name directly, and `ulang.syntax.size(xs)` in expressions, which parses as accesses, `EField(EField(EVar(ulang), syntax), size)`, which the checker reads as a qualified name when the innermost base names no local and the chain names a package that the module sees, so the parser needs no state of imports; a formal, local, or pattern variable named as the first name of a seen path is an error, as `HiddenLocal` is, so the reading is unambiguous. The own package is qualified by its own path, `ulang.compile.Gen`. No short qualifiers for now: neither the last name of a path implicitly nor `import … as q`, so that two imports cannot clash by their qualifiers.
   - **No implicit resolution**: no declaration wins by being nearer, so the hiding of types goes, of an imported type by one of the module and of a type of the library by one of any module (`State.hidden_sorts` then hides only the privates of siblings): two visible types of one name make every unqualified use `Ambiguous`, listing both, and the use writes its path. Functions, procedures, constructors, and pattern aliases keep overloading by type, which decides by the types alone, without preferences, and is `Ambiguous` where they do not. The experiment, `visible_names` of `ulang/check/check.u` without its preference for the own module, made `check` of the project report two clashes only: the 23 uses of `Gen` of `ulang/compile/compile.u`, the record of its lifted declarations, beside `Gen` of `ulang/syntax/syntax.u`, and `ulang/test/modules/own-int.u`, whose own `Int` beside that of the library is the test of the hiding, which becomes a case of `Ambiguous`.
   - **Meaning**: the candidates of a use qualified by a path are the exported declarations of the members of the package of that path, and those of the module of that path, which a module and a package can share, `ulang.test.modules.paths` of the program `ulang/test/modules/paths.u` and the package it imports, where overloading by type decides as everywhere and a clash is `Ambiguous`. A qualified use in the source never reaches private declarations, unlike the resolved names of checked code, which `overloads` takes without `is_visible`, so that the generated tests reach the tester (`enumerate_module` of `ulang/test/generate.u`).
   - **Then**: the names that phases make become paths, the accessor of `f` of `T` in `m` the path of `m` and `T` with the base `f`, the test `l.lemma` the path of `m` and `l` with the base `lemma`, and the like, which takes the encodings of Code 3 apart; `mangle` and `c_text` of `ulang/compile/lower.u` make C names from the parts.
   - **Steps**: done, `Name` with a path and module ids as paths, which changed no generated C; the paths shown with `.`, in messages, in diagnostics, in hints, and in the names of types that `Unordered` and `Incomparable` give in both backends, while C names keep `/`; the resolution of a qualified name by its path, which the names that the checker makes follow too, so that `Name` needs no mark of a written qualifier; the syntax, `import ulang.syntax`, qualified types, patterns, and calls, and `QualifierLocal`, with tests, taught to the seed by `make selfcompile`, and the imports of the sources written with paths; and the hiding of types dropped, with `ulang.compile.Gen` where it clashed, `ulang/test/modules/own_int.u`, and the case `own_type_clash` of `ulang/test/errors/modules.u`. Left: the highlighting of qualified names in the VS Code extension, and the renames that qualifiers make unnecessary, `Term` of `ulang/prove/syntax.u` back to `Expr` only if its users then read better.
2. **A package costs a writer of programs more than it should**: a broken scratch file beside a program made `check ok.u` print 13 errors of the other file as `ImportError` and fail; and `format` of a copy of a file outside its directory fails with `unknown package`, and of a file beside a broken sibling with the `ImportError` of the sibling, so a tool that formats candidate texts must do so in place (the mail client of 15 November 2026). The rule itself stays, a package is exactly its directory (`CLAUDE.md`, Modules), as in Go, where a broken file breaks its package too. Solution, two narrow fixes:
   - `format` needs of the package and the imports only their notations, which `exported_ops` of `ulang/parse/parse.u` reads from the tokens of their export sections, so it parses the file alone with them, as `format_file` of `ulang/ulang.u` does now through the whole package, and fails only on the errors of the file; and `format --as <path>` formats stdin as the file at that path, without writing, for the texts of candidates.
   - `check` of a file beside a broken sibling reports the errors of the sibling once, as one line `sibling x.u does not parse` or its first error, instead of each as an `ImportError`, and the file still fails, since its unit does not load whole.
   - Proposed to drop, into `ideas/rejected.md`: a file inside each package that declares it, as `prelude.u` marks the library, with paths relative to it. A package is its directory, so such a file declares only its presence, a second source of what the directory already says, and imports stay paths from the root, as `ideas/rejected.md` decided against relative ones. What a project declares, its programs, its directories of tests, its dependencies, and its outputs, grows in `project.u` with Build 1, which owns it.
3. **A run over many files loads per unit**, a package of its targets: each unit parses and checks its own package, joins the signatures of the packages checked before, and loads the tester, so the driver threads a cache through the units, `Cache` of `ulang/ulang.u` by `load_file`, of the packages parsed (`parse_file_loaded` of `ulang/parse/parse.u`) and checked without errors (`check_cached` of `ulang/check/check.u`), which took `check` of the project from 22.8 s to 9.9 s, and `compile_tests` of `ulang/ulang.u` takes each module from the unit that it is a member of. Each package is still parsed and checked more than once in a walk such as `make test`: an imported package is checked as an import of an earlier unit and again as its own unit with its tests, since `check_source` of `ulang/check/check.u` never stores the own package in `Checks`; the caches are reset when the walk enters the library, whose root differs, and again when it leaves it (`load_file` of `ulang/ulang.u`), so the units after it check the compiler again; and `without_dependents` of `ulang/parse/parse.u` drops every package that imports the own one, so the units of `ulang/syntax/`, `ulang/format/`, `ulang/parse/`, and the library parse most of the compiler again. Solution, estimated from reading at 4 to 10 s of the about 37 s that a `make test` of 92 s spent before the first test of each file, unmeasured: each package parsed and checked once, by seeding the caches from its own unit. The units are visited in the order of their dependencies, packages before their importers, with the lines of each unit buffered if the order of the output is to stay; after the own package of a unit checks without errors, a copy without its tests, examples, generated tests, and contracts, as `without_tests_of` of `ulang/parse/parse.u` strips an import, goes into `Loaded` as parsed and into `Checks` as checked, with its signature; and one cache is kept per root, of the project and of the library, instead of the reset. Each file then gets the diagnostics, deferred errors, `UnusedImport`, format errors, lints, and proofs that `check` of it alone gives; a test checks that the stripped check of a clean own package equals its check as an import, also its inferred raises. The alternative of one source for all the targets of a run, every package its own main, from which the driver reports, runs the tests, proves, or lints per package, and `Cache` goes, saves at most 1 to 3 s more and changes outcomes: `Prog.main` and `Source.main` of `ulang/syntax/syntax.u` are one path, read by `module_error`, `require_parsed`, and `parse_member` of the parser, `check_source`, `with_errors`, and `diagnostics` of the checker, and `is_runnable`, `load_status`, `blocks_proofs`, and `load_file` of the driver; one lex error, one check that raises, or one internal error would stop the whole run instead of a unit; `partial` and `unparsed` of `load_file` are global, so one parse error would switch every package to partial checking and turn off `UnusedImport` everywhere; the caps of 20 errors and of one format error would hold for the project; every proof would see every contract of the project, which imports drop today, and could disagree with `check --prove` of its file alone; and the whole project with its tests would stay live in one `Run`. It is for a profile to justify, after the seeded caches.
   - First a gprof profile of the compiled `check` of the project, to tell whether the time left is in the units' own packages, which one source does not save, or in the joins of signatures and the loads of the tester, which it does; without a gain, only the simplification is worth weighing.
   - Tests: a package keeps its tests if it is a target, not only if it is the package of the main file (`without_tests_of` of `ulang/parse/parse.u`); importers never see tests, so this is harmless.
   - Entries: `Source` and `Prog` have one `main`, which for many targets is none, so the driver takes the tests and the entry by the modules of the targets, as `check_unit` and `compile_tests` of `ulang/ulang.u` do now by the files of a unit.
   - Errors: a unit fails only by the errors of its own package and of those it imports, so the diagnostics of the one source are filtered per package by the packages it sees (`seen_modules` of `ulang/syntax/syntax.u`).
   - Names: `units` of `ulang/check/check.u` and `module_package` of `ulang/parse/parse.u` take the package of a module by `module_dir` of `ulang/syntax/syntax.u`, as `check_source` of `ulang/check/check.u` does, instead of finding it in `Source.packages`, without their cases of a module of no package, which only the fixtures of tests make; their modules then take names with directories, one per package: those of `ulang/syntax/fixtures.u`, `bags` of `ulang/check/check.u`, `parse_text_recovering` of `ulang/parse/parse.u`, and the source that the tests of `ulang/check/hints.u` build.
4. **`os` is a member of the library**, so every module sees the procedures of the system without importing them, which its signatures do not show either (Later 1). Solution: `os` and `io` as packages of their own, imported by what uses them, decided together with Later 1 by capabilities as Later 4 describes (`ideas/index.md`). With the paths of item 1, the package is `prelude.os`, imported as `import prelude.os` and its uses qualified as `prelude.os.read_utf8(…)` or by its short qualifier, so the names may lose their prefix `os_`; then Code 4 moves `normal_path`, `relative_path`, and `has_file` of `ulang/parse/parse.u` there. Before deciding, an experiment that shows which uses become ambiguous; about 20 files of `ulang/` call the procedures of `os`.

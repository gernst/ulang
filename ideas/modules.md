# Modules

1. **`os` is a member of the library**, so every module sees the procedures of the system without importing them. Solution: `os` as a package of its own, imported by what uses it, after an experiment that shows which uses become ambiguous.
2. **Names cannot be qualified by their package**, so two imported packages that declare a type of the same name make every use of it `Ambiguous` (`normalize` of `ulang/check/check.u`), and a clash that overloading by type cannot decide has no way around it but renaming. For example, `ulang/prove/` could import `ulang/syntax` only after renaming its `Expr` and `Branch` to `Term` and `TermBranch` of `ulang/prove/syntax.u`, and it still shares the constructors `EApp`, `ELam`, `EIte`, and `EMatch`, told apart by type; and `Gen` of `ulang/syntax/syntax.u` cannot be named in `ulang/compile/compile.u`, whose own `Gen` hides it, while its constructors `GVal` and the like stay visible, so code there matches the shape of a generator instead of taking a `Gen`. The checker already resolves qualified uses: `visible_names` and `overloads` take `Name(Some(m), base)` as exactly the declaration of module `m`. What is missing is syntax, and a meaning of the qualifier as a package. Solution:
   - **Qualifiers**: the last name of the path of each imported package, `syntax` for `import "ulang/syntax"` and `nested` for `import "ulang/test/modules/paths/nested"`, written `q.x`. Two imports with the same last name are a parse error until there is a need for `import "…" as q`. A package whose last name is a keyword cannot be qualified. Possibly also the own package and `prelude`.
   - **Where**: in types, `syntax.Expr`, and in patterns, `case syntax.EApp(f, args) =>`, where `.` does not occur now, so the parser builds the qualified name directly. In expressions, `syntax.size(xs)` parses as the field access `EField(EVar(syntax), size)`, which the checker reads as a qualified name when its base is a qualifier. That needs no state of imports in the parser, and is unambiguous since a formal, local, or pattern variable of the name of a qualifier is an error, as `HiddenLocal` is.
   - **Meaning**: a qualified use has as its candidates the exported declarations of the members of that package, among which overloading by type still decides. It never reaches private declarations, unlike the exact `Name(Some(m), …)` of checked code, which `overloads` takes without `is_visible`.
   - **Representation**: the parsed name needs a mark that it names a package, not a module. The ids can coincide: the program `ulang/test/modules/paths.u` has the module id `ulang/test/modules/paths` and imports the package `"ulang/test/modules/paths"`. Options are a field of `Name`, or a constructor of uses that the checker replaces; not an encoding in the string (Code 3). `format` prints the qualifier as written.
   - **Nearness for types**, to decide with it: a type of the module hides those of other modules already, and the library's are hidden by any module's. If the members of the own package also hid the types of imported packages, `ulang/prove/simp.u` would keep writing `Expr` for its own, and only `ulang/prove/translate.u` would write `syntax.Expr`, instead of every file of `ulang/prove/` qualifying both.
   - Then `CLAUDE.md`, under Modules and Overloading, where "the parser builds no qualified names", and the highlighting of the VS Code extension; tests of qualified types, patterns, and calls, of a qualifier hidden by a local, of a clash of qualifiers, and of a qualified private name.
3. **The structure of packages is to be discussed again**: a package is a directory whose members are the files with sections, known only by having them (`has_sections` of `ulang/parse/parse.u`), imports are paths from the root of the project, and `project.u` at the root declares only the directories that run compiled. Preferred: one file *inside* each package that declares it, as `prelude.u` marks the library now, with all resolutions of its members, of imports and of paths, relative to that file; and one file of the project at the *top level*, which also holds its metadata, the programs and the directories of tests of Build 1, its dependencies, and the like. To decide with item 2 and Build 1, whose project file it is: what the file of a package declares, its members or only its presence; whether an import names a package by its path from the root or by its declared name. How the files of a directory without sections relate to it is decided: each is a member, and there are no programs (`ideas/packages.md`). The library would follow the same rule: it is the list `library_modules` of `ulang/syntax/syntax.u`, not its directory, so a new file in `ulang/prelude/` is not loaded until it is listed (`package_files` of `ulang/parse/parse.u`), unlike the packages of a project.

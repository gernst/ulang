# ulang

A minimal programming language with pure functional expressions, imperative statements, datatypes, and Hindley-Milner type inference, implemented in itself: a parser, a type checker, an interpreter, and a compiler to C in `self/`, with a runtime in C. The implementation in Scala 3, which the self-hosted one started from, is on the branch `scala-baseline`.

## Build

- `make` builds `./ulang.bin` from `bootstrap/ulang.c`, the C of the last compiler that compiled itself to the same C, with the runtime in `self/runtime/`, GMP, and the Boehm collector, where `ULANG_LIB` is the directory of the library `prelude/` for imports and `os_library`. Its commands are as in git, with exit status 1 if anything fails, and they need a large stack, `ulimit -s unlimited`, as the Makefile sets it:
  - `./ulang.bin run <file> [<procedure>] [-- args]` calls the procedure of that name, by default `main`, which takes no parameters, with the interpreter `self/run.u`, where `os_args` gives the arguments after `--`, and programs print strings with `os_print` and any value with `os_show` of the module `os`
  - `./ulang.bin test <file> [<name> ...] [-- args]` runs all `test`s of the file, or the named ones, each on its own, and prints `test name passed` or `test name failed: ...`
  - `./ulang.bin test <dir> [<path> ...]` runs the `.u` files of the directories, walked recursively in the order of names, and of the files, each in its directory with all its tests in one process, where a file must succeed, or fail with the error that its first line states, e.g. `// type error: unknown variable x`, prints the files that do not with what was expected and what happened, and `N of M files passed`
  - `./ulang.bin check <file>` only checks the file
  - `./ulang.bin compile <file> <entry> <target.c>` translates the file to C, where `main()` calls the procedure named entry, which takes no parameters, or runs all tests for the entry `test`, which then print `test name passed`, and `cc -DULANG_LIB='"'$PWD/prelude'"' -I self/runtime target.c self/runtime/ulang.c -lgmp -lgc` compiles it
  - errors are printed without positions, except those of parsing
- `make selfcompile` compiles the compiler with `ulang.bin`, and `make bootstrap` with the interpreter `self/run.u` in `ulang.bin` (`ulang.bin run self/ulang.u main -- compile …`), and both replace `bootstrap/ulang.c` and `ulang.bin` only if the new compiler compiles itself to the same C, after keeping the previous ones in `bootstrap/` with a time stamp, where the C files are versioned and the binaries are not
- `make test` is `ulang.bin test tests self simp prelude`, where the tests of `self/parse.u` and `self/compile.u` in the interpreter take most of its 97 seconds
- `make selftest` compiles the tests of the modules of `self/` with `ulang.bin` and the entry `test`, and runs them
- the test of `self/compile.u` writes the translations of some tests with the entry `test` to `self/out/`
- named fields of constructors, `C(name: T, …)`, give accessors `e.name` and updates `e with name := a, other := b`, which the checker resolves by the type of `e` to the generated functions `T.name` and `T.name:=`, which raise `MissingField("T.name")` for constructors without the field; a comma followed by `name :=` continues the updates, also in `assign` and `local`
- `make install` packages the VS Code extension in `vscode/` as `ulang.vsix` and installs it into VSCodium (`codium`): syntax highlighting, a run button, `▶ Run` links above procedures without parameters and tests, errors in the Problems view, and the tests in the Testing view, all by running `ulang.bin` with `run`, `test`, and `check`, the one of the workspace or that of the setting `ulang.binary`

## Tests

Tests are end-to-end only: programs in `tests/` with named tests `test name() := ...` of `assert` statements, whose names are distinct, where the parser accepts parameters, as of functions, which the checker rejects, and programs are entered by procedures without parameters, like `procedure main() := ...`.
Every program is checked after `prelude/prelude.u`, which declares the operators and imports the library modules `nat`, `option`, and `list` (also in `prelude/`).
The prelude also declares the exceptions of builtins: `DivisionByZero` of `/` and `%`, `NoIndex(Str, Int)` of `str_get` and the strict `str_slice`, `NoCharacter(Int)` of `chr`, and `MissingField(Str)` of an access `e.f` or update `e with f := a` of a constructor without `f`, with the name `T.f`. `raise e` is an expression of any type, and a failed `assert` cannot be caught.
The library modules `map` and `set` give maps `Map[K, V]` and sets `Set[A]` as AVL trees, ordered by the builtin `compare`, a total order of values consistent with `==` whose results are only `-1`, `0`, and `1`, which `map` and `set` match, where constructors are ordered by their position in their declaration. `list`, `set`, and `map` share the names of their operations, `size`, `contains`, `get`, `put`, `remove`, and `empty`, and `set` and `map` their constructors `Leaf` and `Node`, as overloads across modules: `self/check.u` takes the declarations of a name in all visible modules as candidates and resolves each use by its type, at the end of the command if several fit, preferring a single declaration of the module itself, see `overloading.md`.
The parser translates the literals `{a, b}` of sets to `set.from_list([a, b])` and `{k => v, l => w}` of maps to `map.put_all([(k, v), (l, w)], map.empty())`, and their comprehensions `{e for x in s if c}` and `{k1 => v1 for k => v in m if c}` to list comprehensions over `set.elements` and `map.entries`, where each entry of a map is bound to a hidden variable whose key and value are matched; these qualified names resolve whenever the module is part of the program. A function `compare` or `==` of two values `T[A, …]` of a datatype `T` of its own module, with distinct type parameters, is the order or equality of `T` (`order_of` in `self/check.u`), which the builtins `compare` and `==` use for all values of `T`, also inside other values and in generic code, e.g. lists of sets or maps keyed by sets, where `==` needs `compare`, with which it must agree; other datatypes are compared structurally. `set` and `map` declare both by their elements and entries, see `tests/orders.u`. The compiled runtime finds them through the type descriptor of each object (`struct u_type` in `self/runtime/ulang.h`, with `compare`, `equals`, and `print`), where the compiler emits one per datatype, `t_` with the mangled name, and the interpreter `self/run.u` through maps from constructors to these functions. Statically, overloads of builtins resolve to the most specific candidate that fits a use of a known type, and to the most general at the end of the command for a type that is still unknown.
Procedures are values of types `(in A, out B, ref C)`: a declared procedure by its name, and `lambda in x, out y, ref z => statements end`, which sees the variables around it by their values and assigns only its own outs and refs; `call p(...)` calls a variable `p` of such a type, which hides a procedure of that name, and compiled code calls them through `u_call_proc` and the wrappers `wp_`.
The parser reads `-n` for a number `n` as a negative literal, in expressions and patterns, e.g. `case -1 =>`, and both the interpreter and compiled code compute the value of a function without parameters once.
The library module `os` declares `OsError`, and with it come the builtin procedures `os_args`, `os_read`, `os_write`, `os_library`, `os_list` (the entries of a directory, sorted, with whether each is a directory, without following links), `os_is_dir`, `os_cwd`, and `os_chdir`, where those on files and directories raise `OsError` when they fail, with `os_walk` of `os.u` for the files below a directory, where relative paths start from the working directory, in the interpreter as in compiled programs, and `os_args` gives the arguments after `--`, e.g. `./ulang.bin run self/ulang.u -- compile source.u main target.c`.
`import name` loads the module `name.u` from the directory of the parsed file, or else from the library, once, without its `test`s. A module sees its own declarations, those of its direct imports, and the prelude, and the same holds for notations: imports are not transitive. The checker resolves every name to its module, so that names may repeat in modules that are not imported together. The checker checks each imported module once, after the modules it imports, where the prelude with its imports is one unit, and keep it by its name, commands, and the modules it sees: the `ref cache` of `check_modules` in `self/check.u`.
A file that is expected to fail states the error in its first line, e.g. `// type error: unknown variable x`, see `tests/errors/`.

## Style

- In the code, the parameters of functions, procedures, and lambdas are called formals, and params are type parameters.
- Omit comments that are self-evident from the code, such as doc comments that restate the name of a declaration.
- Use functions only for computations that terminate; code that may not terminate, such as the evaluator of `self/run.u`, which interprets any program, is written as procedures. The checker does not enforce this.

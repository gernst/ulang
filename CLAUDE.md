# ulang

A minimal programming language with pure functional expressions, imperative statements, datatypes, and Hindley-Milner type inference, implemented in itself: a parser, a type checker, an interpreter, and a compiler to C in `self/`, with a runtime in C. The implementation in Scala 3, which the self-hosted one started from, is on the branch `scala-baseline`.

## Build

- `make` builds `./ulang.bin` from `bootstrap/ulang.c`, the C of the last compiler that compiled itself to the same C, with the runtime in `self/runtime/`, GMP, and the Boehm collector, where `ULANG_LIB` is the directory of the library `prelude/` for imports and `os_library`. Its commands are as in git, with exit status 1 if anything fails, and they need a large stack, `ulimit -s unlimited`, as the Makefile sets it:
  - `./ulang.bin run <file> [<procedure>] [-- args]` calls the procedure of that name, by default `main`, which takes no parameters, with the interpreter `self/run.u`, where `os_args` gives the arguments after `--`, and programs print strings with `os_print` of the module `os`, e.g. `show` of any value
  - `./ulang.bin test <file> [<name> ...] [-- args]` runs all `test`s of the file, or the named ones, each on its own, and prints `test name passed` or `test name failed: ...`
  - `./ulang.bin test <dir> [<path> ...]` runs the `.u` files of the directories, walked recursively in the order of names, and of the files, each in its directory with all its tests in one process, where a file must succeed, or fail with the error that its first line states, e.g. `// type error: unknown variable x at 3.1`, prints the files that do not with what was expected and what happened, and `N of M files passed`
  - `./ulang.bin check <file>` only checks the file
  - `./ulang.bin compile <file> <entry> <target.c>` translates the file to C, where `main()` calls the procedure named entry, which takes no parameters, or runs all tests for the entry `test`, which then print `test name passed`, and `cc -DULANG_LIB='"'$PWD/prelude'"' -I self/runtime target.c self/runtime/ulang.c -lgmp -lgc` compiles it
  - `./ulang.bin format <file>` prints the file as source, by `show_program` of `self/format.u`, and fails if that source does not parse to the same commands
  - parse errors are printed at their tokens, `at L.C`, and type errors at the declaration that raised them, `at L.C` after the message, with ` in m` for a module m that the file imports (`Located` of `self/check.u`), where the parser pairs each command with its position in the sections of its `Mod`, while compile and runtime errors have no positions
- `make selfcompile` compiles the compiler with `ulang.bin`, and `make bootstrap` with the interpreter `self/run.u` in `ulang.bin` (`ulang.bin run self/ulang.u main -- compile …`), and both replace `bootstrap/ulang.c` and `ulang.bin` only if the new compiler compiles itself to the same C, after keeping the previous ones in `bootstrap/` with a time stamp, where the C files are versioned and the binaries are not
- `make test` is `ulang.bin test tests self prove prelude`, which takes 3 seconds
- `make testformat` formats every file that parses, which tests the parser and the printer by their round trip
- `make testc` runs the same files compiled, by `testc.sh`: each compiled by `ulang.bin compile` with the entry `test` and by `cc -O2` with the runtime object `out/testc/ulang.o`, run in its directory, in parallel, where a file must succeed, or fail with the error of its first line, except for `prelude.u` and `option.u`, which cannot be compiled on their own, since the runtime needs the lists of `list.u`, in about 20 seconds
- named fields of constructors, `C(name: T, …)`, give accessors `e.name` and updates `e with name := a, other := b`, which the checker resolves by the type of `e` to the generated functions `T.name` and `T.name:=` of a module that the module of the access sees, as other names, which raise `MissingField("T.name")` for constructors without the field; a comma followed by `name :=` continues the updates, also in `assign` and `local`
- `make install` packages the VS Code extension in `vscode/` as `ulang.vsix` and installs it into VSCodium (`codium`): syntax highlighting, a run button, `▶ Run` links above procedures without parameters and tests, errors in the Problems view, and the tests in the Testing view, all by running `ulang.bin` with `run`, `test`, and `check`, the one of the workspace or that of the setting `ulang.binary`

## Tests

Tests are end-to-end only: programs in `tests/` with named tests `test name() := ...` of `assert` statements, whose names are distinct, where the parser accepts parameters, as of functions, which the checker rejects, and programs are entered by procedures without parameters, like `procedure main() := ...`.
Every module imports the library modules `prelude`, `option`, `list`, and `str` of `prelude/` implicitly, always from the library, in that order, where each of these imports only those before it (`implicit_imports` of `self/syntax.u`), so that the prelude is a module like any other, which declares the operators in its export section and the types `Bool`, `Int`, `Str`, and `Char` in its builtin section, of which a module may declare names again, and where `str` has the functions on strings and characters, `list(s)` of its characters, `str(cs)` of characters, `ord`, `chr`, `is_digit`, `is_letter`, `is_space`, `size`, `at(i, s)`, `get(i, s)` as an option, `contains(c, s)`, `slice`, `join`, `split`, `quote`, and `number`, with the names and the order of arguments of the containers.
The prelude also declares the exceptions of builtins: `DivisionByZero` of `/` and `%`, `NoIndex(Str, Int)` of `at` and the strict `slice` of strings, `OutOfBounds(Int, Int)` of `at`, `put`, and the strict `slice` of arrays, with the index and the size, `NoCharacter(Int)` of `chr`, `MissingField(Str)` of an access `e.f` or update `e with f := a` of a constructor without `f`, with the name `T.f`, and `Unordered(Str)` and `Incomparable(Str)` of comparing an abstract type without an order, or without an order and an equality, with the name of the type. `raise e` is an expression of any type, and a failed `assert` cannot be caught.
The library modules `map` and `set` give maps `Map[K, V]` and sets `Set[A]` as abstract types of AVL trees, ordered by the builtin `compare`, a total order of values consistent with `==` whose results are only `-1`, `0`, and `1`, which `map` and `set` match, where constructors are ordered by their position in their declaration; the builtin `<` and the `<=`, `>`, and `>=` of the prelude, each by one `<`, follow `compare` on values of any type. `list`, `set`, `map`, `array`, and strings share the names of their operations, `size`, `contains`, `get` (of association lists for `list`), `remove` (of elements for `list` and `set`, of keys for `map`), `empty` of sets and maps, `exists(c, p)` and `forall(c, p)`, and the folds `foldr(c, acc, f)` and `foldl(c, acc, f)` in the order of lists and in ascending order of sets and maps, where `f` and `p` of maps take the key and the value, and they convert into each other by functions named after the type they convert into, which take the list of the other type, `list(c)`, the elements or entries in order, `set(xs)`, `map(ps)`, where the last entry of a key counts, `array(xs)`, and `str(cs)`, as overloads across modules, while `++` and `--` combine two of a kind, `infix right 8 ++` and `infix left 7 --` of the prelude, so that `a ++ b -- c` is `(a ++ b) -- c`: `++` concatenates lists, by `list`, and strings, by the builtin section of the prelude, unites sets, and joins maps, where the entries of the second count, and `--` takes the elements of the second list or set away, and from a map the keys of a set, where `intersect(s, t)` gives the common elements of two sets; the builtin section of the prelude also declares the arithmetic `+`, `-`, `*`, `/`, and `%` of integers, while `<`, `==`, `compare`, `show`, `and`, and `or` are builtins without a module: `self/check.u` takes the declarations of a name in all visible modules as candidates and resolves each use by its type, at the end of the command if several fit, preferring a single declaration of the module itself, and else the one candidate after which the other open uses of the command still have candidates that fit, e.g. `empty` and `put` of a map literal when `set` and `array` are imported too, see `overloading.md`.
The parser translates the literals of sets and maps to the folds of their elements, unrolled, `{a, b}` to `insert(a, insert(b, empty()))` and `{k => v, l => w}` to `put(l, w, put(k, v, empty()))`, so that the last entry of a key counts, `{}` to `empty()`, and literals with a rest after `;` add to it, `{a, b; s}` to `insert(a, insert(b, s))` and `{k => v; m}` to `put(k, v, m)`, as lists do with `[a, b; xs]`, where `insert` belongs to `set`, `put` to `map`, and `empty` to the module that its type determines, and all comprehensions to folds over the containers of their generators, nested for several generators: `[e for x in c if q]` is `foldr(c, Nil, lambda x, acc => if q then Cons(e, acc) else acc)`, `{e for x in c if q}` the same with `empty()` and `insert`, and `{k1 => v1 for k => v in m if q}` is `foldl(m, empty(), lambda acc, k, v => if q then put(k1, v1, acc) else acc)`, so that the last entry of a key counts, where `c` is a list, set, or map whose `foldr` or `foldl` overloading chooses, the accumulator has a name that users cannot write, and the names of these translations, `insert`, `put`, `empty`, `foldr`, and `foldl`, are names of the module `*`, which the checker resolves against the declarations of the visible modules but never against locals (`overloads` in `self/check.u`), so that literals and comprehensions of sets and maps need `import set` and `import map`; `self/compile.u` translates the folds of a list comprehension over lists and arrays, also of several generators, into nested loops that build the list in order, without intermediate lists. A function `compare` or `==` of two values `T[A, …]` of a datatype `T` of its own module, with distinct type parameters, is the order or equality of `T` (`order_of` in `self/defs.u`), which the builtins `compare`, `==`, and `<` use for all values of `T`, also inside other values and in generic code, e.g. lists of sets or maps keyed by sets; other datatypes are compared structurally. Only abstract types declare `==`, while datatypes whose constructors are visible may declare `compare`, which must agree with their structural equality, unchecked; with `compare` alone, `==` is `compare(a, b) == 0`. For an abstract type without `compare`, the checker synthesizes a private `T.compare` that raises `Unordered`, and without `==` either, `T.==` as well, both raising `Incomparable`, see `tests/orders.u` and `tests/modules.u`. `set` and `map` declare both by their elements and entries. Similarly, the builtin `show` gives the text of any value, with strings in quotes, and a function `show` of one value `T[A, …]` of a datatype `T` of its own module, with distinct type parameters and the result `Str`, is the show of `T`, which the builtin uses for all values of `T`, also inside other values, see `tests/orders.u`: the descriptor of `T` points to it, and `self/run.u` finds it through `shows` of `Prog`. The compiled runtime finds them through the type descriptor of each object (`struct u_type` in `self/runtime/ulang.h`, with `compare`, `equals`, and `show`, which have the signatures of the ulang functions and point to the declared ones directly, or else to the structural ones of the runtime), where the compiler emits one per datatype, `t_` with the mangled name, and the interpreter `self/run.u` through the maps of `Defs` in `self/defs.u` from datatypes to these functions, which it reaches from a constructor by its datatype, where `Defs` holds the definitions of the checked program for both. Statically, overloads of builtins resolve to the most specific candidate that fits a use of a known type, and to the most general at the end of the command for a type that is still unknown.
Effects on variables are atomic: a procedure works on copies of its outs and refs, which reach the caller only when it returns, and the handlers of a `try` see the variables as they were before it, so an exception leaves the variables of the caller and of the `try` unchanged; compiled code copies outs and refs in and out, and saves the variables that the body of a `try` assigns before its `setjmp`.
Variables are read only where they are assigned on every path, and outs must be assigned at the end of a procedure on every path that does not raise, where passing a variable as a ref reads it: the checker tracks this in its environment (`Local` in `self/check.u`), joining the paths of `if`, `match`, and `try`, where a `while` may not run its body and a handler starts from the variables before its `try`.
Procedures are values of types `(in A, out B, ref C)`: a declared procedure by its name, and `lambda in x, out y, ref z => statements end`, which sees the variables around it by their values and assigns only its own outs and refs; `call p(...)` calls a variable `p` of such a type, which hides a procedure of that name, and compiled code calls them through `u_call_proc` and the wrappers `wp_`.
The parser reads `-n` for a number `n` as a negative literal, in expressions and patterns, e.g. `case -1 =>`, and both the interpreter and compiled code compute the value of a function without parameters once.
A module may have a section `builtin` between `export` and `implementation`, of exported signatures of functions and procedures without definitions, which the interpreter and the runtime define, and of types without a definition, `type T[A]`, whose values the interpreter and the runtime make and order, compare, and show, with no synthesized `compare` and `==`, which the checker declares from the signatures and whose uses keep their module like those of any declaration, by which the interpreter (`builtin_names` of `self/run.u`) and the compiler (`builtin_functions` and `proc_name` of `self/compile.u`) find them, as `str.u` for the functions on strings, `os.u` for its procedures, and `array.u` for immutable arrays `Array[A]`, which programs import: `array(xs)`, `list(a)`, `size`, `at(i, a)`, `get(i, a)` as an option, `slice`, `contains`, and the folds, which comprehensions use, with the names and the order of arguments of the containers, where `self/run.u` keeps them as `Arr` of `self/value.u`, arrays of the compiled interpreter, and where the parser translates `|a, b|` and `|e for x in c if q|` to `array` of the module `*` applied to the list or the list comprehension, which `self/compile.u` builds without the list, by `u_mk_array` for a literal and, for generators over lists and arrays, by loops that fill an array with room for as many elements as the first generator has, which grows for further generators, and is shrunk at the end unless one generator without a condition made it exact, while `show` gives `|a, b|`, where the lexer reads `|` alone, as punctuation, so that no operator contains it, and a `|` where an operand starts opens an array, which the next `|` after an operand closes. The library module `os` declares `OsError` and the builtin procedures, which come with `import os`: `os_args`, `os_read`, `os_write`, `os_library`, `os_print`, `os_print_error`, `os_exit`, `os_list` (the entries of a directory, sorted, with whether each is a directory, without following links), `os_is_dir`, `os_cwd`, and `os_chdir`, where those on files and directories raise `OsError` when they fail, with `os_walk` of `os.u` for the files below a directory, where relative paths start from the working directory, in the interpreter as in compiled programs, and `os_args` gives the arguments after `--`, e.g. `./ulang.bin run self/ulang.u -- compile source.u main target.c`.
`import name` loads the module `name.u` from the directory of the parsed file, or else from the library, once, without its `test`s, where the imports of every module come first. The parser gives a program as `Source(mods, main)` of `self/syntax.u`, its modules in load order, each after those it imports, as `Mod(name, imports, exported, builtins, implemented)` with its explicit imports and the commands of its sections, where a module without sections has all its commands implemented, and the parser's only state is the list of modules loaded so far, from which it takes the notation that each module starts with, the exported notation (`exported_notation` of `self/syntax.u`) of its implicit and explicit imports. A module sees its own declarations, the exported declarations of its direct imports, and the prelude, and the same holds for notations: imports are not transitive. A module may have sections, see `prelude/set.u`: its imports first, then `export` with its notations, datatypes and aliases, which it exports, signatures of functions and procedures without bodies, and abstract types `type T[A]` without a definition, and then `implementation`, which defines them by definitions that repeat the signatures exactly, and by `data` for abstract types, with private declarations and tests; other modules do not see its private declarations and the constructors and fields of its abstract types, which are unknown to them, since a module is checked with the signatures of the modules before it (`Sig` of `self/sig.u`, filtered by `exported` for each kind of declaration), and a module without `export` is private, with its notations, so that only main programs, which are run, have no sections, and whose private procedures and tests are entry points of `run` and `test`. The checker resolves every name to its module, so that names may repeat in modules that are not imported together. The checker checks each module once, after the modules it imports (`check_program` in `self/check.u`).
A file that is expected to fail states the error in its first line, e.g. `// type error: unknown variable x at 3.1`, see the subdirectories of `tests/errors/` by kind of error, where helper modules sit next to the files that import them.

## Style

- In the code, the parameters of functions, procedures, and lambdas are called formals, and params are type parameters.
- Omit comments that are self-evident from the code, such as doc comments that restate the name of a declaration.
- Use functions only for computations that terminate; code that may not terminate, such as the evaluator of `self/run.u`, which interprets any program, is written as procedures. The checker does not enforce this.

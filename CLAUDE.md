# ulang

A minimal language with pure functional expressions, imperative statements, datatypes, and Hindley-Milner inference, implemented in itself in `ulang/`: parser, checker, interpreter, and a compiler to C, with a runtime in C (`ulang/runtime/`). Each phase is a package of its own, which imports those before it, so the imports check the layers: `ulang/syntax` (the syntax, the builtins, the notation, and the errors that all phases share), `ulang/format` (the printer), `ulang/parse` (lexer and parser), `ulang/check` (signatures, definitions, the checker, the exceptions of procedures, and the messages of type errors), `ulang/run` (the interpreter), `ulang/compile` (C and the compiler to it, x86-64 assembly and the compiler to it, and the part they share), `ulang/prove` (the prover), and `ulang/lint` (the lints), with the driver `ulang/ulang.u`, a program that imports them all. The Scala 3 implementation it started from is on the branch `scala-baseline`.

## Working rules

- A question asks for an answer, not an action: answer it, propose what suggests itself, and act only on an explicit go-ahead. Read-only lookups are fine.
- Checks:
  - After a refactor that keeps behaviour, `out/ulang.sh check ulang/ulang.u` is enough.
  - Run `make test` after changes of behaviour or when asked, and say that it ran; after edits of tests, rerun only the affected files.
  - Work split among sub-agents in worktrees is checked once, after the merge: each agent runs `check` and the test files and cases that its change affects, a case alone by `out/ulang.sh test <file>:<name>`, and the session that merges their branches runs `make test` on the merge, before it reaches `main`. A small item, a few lines in one place, is done inline rather than by an agent, which must first read this file and the code around it.
  - `make testc` only with a strong reason, e.g. changes to `ulang/compile/compile.u`, the runtime, or what the generated C depends on, and only after asking.
  - Time every phase of a run of checks and keep the output, so that questions about durations are answered from it; never rerun only to measure.
  - Redirect the output of `make` to a file, never pipe it into a command that may exit first, such as `tail -0` or `head`: `make` then dies of the broken pipe before linking, and a stale `out/ulang.bin` runs the next checks.
- Commits: no `Co-Authored-By` for Claude; end the message with `Agentic Coding (<model>)`, e.g. `Agentic Coding (Claude Opus 5.5)`. Run `make` after every commit, so that `out/ulang.bin` is current.
- Other sessions may edit the same files, also those of `ideas/` and `CLAUDE.md`, at the same time: commit only the hunks of your own work, applied to the committed version, and leave theirs in the working tree.
- `ideas/` holds the open items, one file per area, listed in `ideas/index.md`, each item as the problem and the desired solution, named by its area and number, Build 1 for item 1 of `ideas/build.md`; delete an item when it is done. Explanations go into this file or `README.md`.
- Plans and guides of work in progress, such as `ideas/prove.md`, are files of `ideas/`, versioned as all files are, and listed in `ideas/index.md`; delete each when its work is done, and what stays true afterwards goes into this file, `README.md`, or the items of `ideas/`.
- Before making a word a keyword, search the sources for it as a name and rename those uses: the seed still takes it as a name, so `make` builds, and only the new lexer of `make test` rejects it.
- When working on ulang code, record in `unclear.md` each trip-up and unclear point: a wrong guess, a search that led nowhere, a doc that was stale or misleading, each as what was wrong and what is so, so that the documentation can be fixed from it.
- To compare a compiler before and after a change, e.g. the C that both compile from the same files, build the one before from the committed sources in a worktree of its own, never take the `out/ulang.bin` of the main tree, which other sessions rebuild from their uncommitted edits; the binary finds the library by the path that `-DULANG_LIB` compiled in, no variable of the environment, so its worktree stays until the comparison is done.
- No auto-memory: rules for later sessions go into this file, and only if it does not already say them.
- Finished work goes onto `main`, never left on a branch, in a worktree, or as a patch; a reverted experiment is no work, so say where its patch is. Work of several steps runs in a worktree below `.claude/worktrees/` on a branch of its own, each step committed there; to hand it over, merge `main` into the branch, run `make` and only the tests that the work touches, the files and cases it changed or affects, never all of `make test` again, then `git merge --ff-only` the branch in the main tree and `make`, and remove the worktree and the branch when the work is done.
- A new lint rule is run over the project before it is committed, each warning classified as a mistake or intended, and proposed with its count and samples of its sites, since false positives sink a rule; warnings that the planned `refactor` could fix stay in the sources as its cases, not fixed by hand.
- Profile compiled programs with gprof, not perf, which cannot record call graphs here: build with `-pg`, run with `GLIBC_TUNABLES=glibc.gmon.maxarcs=50000000:glibc.gmon.minarcs=1000000`, and sum several runs by `gprof -s` if one has too few samples; gprof does not see time in shared libraries such as libgc.

## Writing ulang

Agents have almost no ulang in their training data, so what they write comes from this file, `README.md`, and the errors, which give the form to write after `; ` for the habits below that they recognize (`hint_at` and `operator_hint` of `ulang/parse/parse.u`, `hint_of` of `ulang/check/message.u`, and `Hinted` of `ulang/check/check.u`, with the cases `habits` of `ulang/test/errors/parse.u` and `hints` of `ulang/test/errors/types.u`). The habits of other languages that fail:

- Every statement starts with its keyword, `local x := e`, `assign x := e`, `call p(in a, out b)`, `raise e`, `skip`: `x := e` is `statement expected but x found`, as is a call without `call`; no `return`, `break`, or `+=`, so a procedure gives results by its `out` formals, and a loop ends by its condition or an exception.
- `if c then … end` and `while c do … end` in statements, `if c then a else b` in expressions, which always has its `else`; `else if` opens an `if` of its own, with its own `end`, and no `elif`; a missing `end` is reported at the construct still open where the parse ends, `the if, or a construct inside it, has no end`, which may be at the end of the input (`expect_end` of `ulang/parse/parse.u`).
- Containers are forms, `List(1, 2)`, `List(x; rest)` also in patterns, `Set(…)`, `Map(k => v)`, `Array(…)`, never `[1, 2]` or `x :: rest`; `[…]` is only for type arguments, `List[Int]`.
- Strings join by `++`, never `+`, which is of `Int` only, and `show` gives the text of any value.
- `//` is only a doc, a run of lines from the start of a line before a command, a statement, or a `case`, in any column, which `format` indents, never at the end of a line, above a blank line, before `end`, `else`, `catch`, or a `local` line, or within an expression.
- Functions are expressions without `raise`, failing only by the exceptions of builtins, so code that raises, may not terminate, or reads files is a procedure.
- An exported procedure that raises says so after its formals, `procedure load(in path: Str, out text: Str) raises OsError, ParseError`, in `export` and `implementation` alike, and a formal of a procedure type says what its values may raise, `step: (in Int, out Int) raises Failed`; private procedures infer it, so the errors name each place to change: `p raises T, which its raises omit` at the raise or call, `the procedure value q raises T, which its type omits` where `q` is passed, and `the handler of T is unreachable` for a handler that nothing in its `try` can reach.
- Layout is not written by hand: `ulang.sh format` gives it, and `check`, `lint`, and `test` reject any other.

A type error is reported at the innermost part around it, and a part of the wrong type at the part, with the type expected and found, e.g. `1 + true` as `expected Int but found Bool in argument 2 of the call` at the `true`, and `if 1 then 2 else 3` at the `1`, and `check` reports all type errors of the first package that has some, at most 20 per file, and the parser resumes after an error at the next command, at the next statement, and at the next `,` or `)` of an argument, reporting the errors of all of them, which the parsed modules hold as their parts that do not parse, `AUnparsed` of `ulang/syntax/syntax.u`, also the commands and the comments that document nothing (`parse_errors`, `has_errors`, and `require_parsed`, which raises them, of `ulang/parse/parse.u`, `parse_stmt_recovering` and `parse_arg`), where neither the parse nor its errors depend on the layout, only on the tokens, since a statement ends at the next statement keyword, at what ends its body, or at a name after what ends an expression, outside its brackets and blocks (`skip_stmt` and `at_next`), where a missing operand is found at the next token, which may be on the next line, and a file with parse errors is checked without its commands that do not parse, while a definition whose part after `:=` does not parse keeps its signature (`parse_expr_recovering` of `ulang/parse/parse.u`), a part of an expression that does not parse, and an unknown name, have the type `TError` of `ulang/syntax/syntax.u`, which unifies with every type and makes no error of what it reaches (`reaches_error` of `ulang/check/check.u`), and a statement that does not parse may assign every variable, so that the rest of the body is checked without follow-up errors, where a use of a name that one of them declares, as far as the parser read it, is `UnparsedDeclaration` instead of an unknown name and does not stop the definitions (`without_unparsed` and `unparsed_names` of `ulang/parse/parse.u`, `check_partial` and `is_blocking` of `ulang/check/check.u`): check after each small edit; which declaration an overloaded name such as `size` takes depends on the imports and the types, so read the `export` sections of the imported packages.

## Build

- `make` builds the tool `out/ulang.bin`, the compiler of the current sources `ulang/*.u` and `ulang/*/*.u`, with the library in `ulang/prelude/`: the seed `bootstrap/ulang.bin`, built from `bootstrap/ulang.c`, the C of the last compiler that compiled itself to the same C, translates them to `out/ulang.c`. Each binary is linked with the runtime, GMP, and the Boehm collector, and rebuilt when its inputs change: about 15 seconds from nothing, 7 after an edit of the sources; `rm -rf out` loses nothing that `make` cannot rebuild. `ULANG_LIB` is the directory `ulang/prelude/` of the library, for imports and `os_library`. Commands exit with status 0 if all succeeds, 1 for errors of the sources, 2 for a usage error, 3 for a run, test, or lemma that fails, and 4 for an internal error, the worst of several, the greatest (`load_status` of `ulang/ulang.u`, `has_errors` of `ulang/parse/parse.u` and of `ulang/check/check.u`, where the parsed modules hold their errors as the parts that do not parse and the checked program as its parts and commands that checking rejects, `AErr`, read by `diagnostics` of `ulang/check/check.u`). The interpreter and the compiler recurse as deeply as the programs they run, so each binary is run by a copy of `bootstrap/ulang.sh` of its name next to it, `out/ulang.sh` for `out/ulang.bin`, which `make` makes and calls, and copies with the binary to the root, `ulang.sh` and `ulang.bin`, which are not versioned, and which sets `ulimit -s unlimited`, else the hard limit, before it runs the binary; so the commands below are `out/ulang.sh run …` and the like, never `out/ulang.bin` directly. Compiled programs need the same limit, so the binaries of the Makefile have copies of the script, too.
  - The commands are those of `usage` of `ulang/ulang.u`, read by `request` into a `Request`, where a usage error exits with status 2 and prints the usage, also an option that a command does not take (`paths_request`), and `ulang.sh help <command>` describes one. Only `format` writes sources: `check` and `lint` report, and the edits that lints and errors propose are left to the planned `refactor` (Diagnostics 4 of `ideas/diagnostics.md`), which a lint never bypasses. A target `file.u:name` selects a declaration of a file, where only a path ending in `.u` is split at its last `:`.
  - `ulang.sh run <file>[:<procedure>] [-- args]` calls the procedure, by default `main`, without parameters, in the interpreter `ulang/run/run.u`, also in a program with errors, after reporting them, as far as they allow (deferred errors, under Syntax and translations); `os_args` gives the arguments after `--`.
  - `ulang.sh test [<path>[:<name>] …] [-- args]` runs the tests of the `.u` files of the paths, by default the root of the project of the working directory, directories walked in the order of names without the hidden ones and those named `out`, and for `test` without the directories that `project.u` runs only compiled (`targets_of`, `walk_all`, and `compiled_only_of` of `ulang/ulang.u`). The files are grouped into units, the members of a package, which load together, and each program alone (`units_of`); each unit is loaded and checked once, where the parser keeps the tests of all members of the package of the loaded file, and then the tests of each of its files run, each on its own, in the working directory, so that tests give paths from the root, where `make` runs them, printing `test name passed` or `test name failed: …` per test and lemma as it runs, labeled `file: ` if there are several files (`test_targets` and `test_module` of `ulang/ulang.u`); a file named alone runs only its own tests, though its package loads whole. A file passes if its unit loads, its tests pass, and its lemmas are proven, also the selected ones if names are given, while the tests of a unit with errors run too, failing where they reach one (deferred errors, under Syntax and translations); with several files it prints the files that do not, `file: failed` after their failed tests, or the errors of their unit, as JSON lines of its first file, and `N of M files passed`. The errors of a single file that fails to load go to stderr, as JSON lines.
  - `ulang.sh check [<path> …]` only checks, so a file passes if it loads.
  - `ulang.sh lint [<path> …]` checks as `check` does and prints the warnings of the lints of each file that loads, as `file: warning[Code]: message, write replacement at L.C`, which do not fail it, where `Code` is the rule, a constructor of `Lint` of `ulang/lint/lint.u`, and a rule without a replacement omits `, write …`. The rules are walks of the parsed module, which keeps the positions and the source that `format` prints, each with a test in `ulang/test/lint/`: rewrites from a pattern to a simpler expression with the same meaning (`placed_lints`, `iterated_list`, and `collecting_loops`), printed by `format_module_expr` of `ulang/format/format.u`; locals and pattern variables that are never read, and locals declared above the one branching statement that uses them (`locals_lints` and `binder_lints`); private declarations that no export, test, lemma, example, hook, or procedure without formals reaches (`unused_privates`); handlers that only `skip` (`swallowed`); and names with numeric indices or `show_` (`name_lints`). The walks judge names as written: a pattern names the library as written, e.g. `Some` and `value_or`, so a module that declares such names again may get a lint that does not check, and declarations count by their base names, so an overload that is used keeps the others.
  - `ulang.sh prove [<path>[:<lemma>] …]` proves all or the named lemmas of the files, printing `lemma name proved` or `lemma name open`, the latter with an error of the kind `proof` for each goal that its proof leaves open, at its step and with the goal as a detail (`gap_diagnostic` of `ulang/prove/lemma.u`), by the default proof of `ulang/prove/lemma.u`: simplification, else induction on one of the formals, with the lemmas proven before as facts; a recursive function that the lemmas reach unfolds only if the prover proves that it terminates (`terminations` of `ulang/prove/termination.u`), else it stays uninterpreted and an error of the kind `proof` names the call that no measure decreases (`termination_diagnostic` of `ulang/prove/lemma.u`); the checked program is translated by `translate` of `ulang/prove/translate.u`, which keeps its resolved names, since the builtins of the prover are pattern aliases over the names that checked programs carry (`ulang/prove/syntax.u`). `ulang.sh test` proves the lemmas of a file after its tests, and `out/ulang.bin` contains the prover.
  - `ulang.sh compile <file>[:<procedure>] -o <target.c>` translates the program to C, whose `main()` calls the procedure, by default `main`, as the entry `EntryProc` of `ulang/compile/compile.u`; the C is `static` except `main` and what `ulang/runtime/ulang.h` declares extern (`runtime_referenced` of `ulang/compile/lower.u`), so the C compiler drops the parts of the library that nothing reaches; compile it by `cc -DULANG_LIB='"'$PWD/ulang/prelude'"' -I ulang/runtime target.c ulang/runtime/ulang.c -lgmp -lgc`. A target ending in `.s` is x86-64 assembly for Linux instead, by `assemble_program` of `ulang/compile/x86.u` from the checked program, in the instructions of `ulang/compile/asm.u`, with the names and analyses that both backends share in `ulang/compile/lower.u`; link it by `cc target.s out/asm/ulang.o -lgmp -lgc`, the runtime that `make out/asm/ulang.o` compiles, and `make testasm` runs the tests of the project as `make testc` does, compiled through assembly, and `make selfcompileasm` checks that the compiler built from its assembly compiles itself to the same assembly and C, without replacing the seed (`ideas/assembly.md`).
  - `ulang.sh compile --tests -o <target.c>` translates the tests of all files of the project, also of the directories that `test` skips, into one program, each unit checked as `test` checks it and each module taken from its own unit (`compile_tests` of `ulang/ulang.u`), whose `main()` takes the arguments of `test`, at the root, and runs the selected tests as `test` does, with the tests of lemmas but without their proofs (`EntryTests` of `ulang/compile/compile.u`, `u_run_tests` of `ulang/runtime/ulang.c`); a unit that does not load fails the compilation.
  - `ulang.sh format [<path> …]` rewrites the files of the paths, by default the project, as source (`format_program` of `ulang/format/format.u`), in place, and refuses a file whose source does not parse to the same commands. `check`, `lint`, and `test` fail on a file that `format` would change, with a `format error` at the first line that differs, after the errors of parsing and checking (`check_file` of `ulang/ulang.u`, `require_formatted` of `ulang/format/format.u`), also of each member of the unit, so every file that parses and checks is formatted, which tests parser and printer by their round trip; `format` keeps the imports in their order, which is the order of loading. Run `ulang.sh format` on each `.u` file after editing it, and `make reformat` after a change of the printer, which formats the project.
  - Parse errors are reported at their token, type errors at the innermost part around them, since every part of an expression, statement, and pattern has its position (`At` of `ulang/syntax/syntax.u`, `infer`, `statement`, and `binders` of `ulang/check/check.u`), where the checker records each error by `report` and continues, and a part of the wrong type is a `Mismatch` at the part (`expect`), the innermost one, since `check` passes the expected type down to the components of a tuple, the elements of a form, the body of a `let`, and the arguments of a call of one candidate whose result fits it (`infer_against`, `apply`, and `checks_args` of `ulang/check/check.u`), else at their declaration, with the module `m` if it is other than the file, of an imported package or a sibling (`ImportError` of `ulang/parse/parse.u`, `Located` of `ulang/check/check.u`). Each error is a `Diagnostic` of `ulang/syntax/error.u`, printed as one JSON object on a line by `format_diagnostic`, with the fields `file`, `module`, `line`, `column`, `kind` of `error_kinds`, `code`, `message`, and details such as `expected` and `found`, the only output of errors, read by agents and the VS Code extension (`parseDiagnostic` of `vscode/extension.js`), and a missing procedure that `run` or `compile` is to call is the runtime error `UnknownEntry` of `require_entry` of `ulang/check/defs.u`. Runtime and internal errors have no positions; the texts of the runtime errors that both backends report are `runtime_message` of `RuntimeError` in `ulang/syntax/error.u`, which `ulang/compile/compile.u` writes into every program as the formats `u_text_*` that the runtime prints; `InternalError` of `ulang/syntax/error.u` holds the errors of the interpreter, the checker, and the compiler that checked programs never raise, since an earlier phase rules out what they meet, with `Unexpected(what)` for code without a case of its own; the messages of type errors are `located_message` of `ulang/check/message.u`, and those of internal errors `internal_message` of `ulang/syntax/error.u`.
- The repository is one project, whose root has `project.u`, so that the modules of `ulang/` and of the tests are known by their paths from it, and tests import their helpers by such paths. `project.u` declares what convention cannot decide, the function `project(): Project` of the type `Project` of `ulang/prelude/os.u`, here the directory of programs that run only compiled, `ulang/test/errors/`, which `ulang.sh test` does not run when it walks it; no directory below a root may have a file `project.u`, which would be a root of its own.
- `make selfcompile` compiles the sources with `out/ulang.bin`, and `make bootstrap` with the interpreter of the seed (`bootstrap/ulang.sh run ulang/ulang.u -- compile …`), for sources that the seed cannot compile. Both replace the seed, `bootstrap/ulang.c` and `bootstrap/ulang.bin`, only if the new compiler compiles itself to the same C, keep the previous pair in `bootstrap/<time stamp>/`, and then rebuild `out/ulang.bin`. Their stages are in a directory `out/stage-*` of each run, removed if it succeeds. The C of the seed is versioned, the binaries are not, and of the backups only those worth keeping are committed. `make selfcompile` takes about 15 seconds, `make bootstrap` about 4 minutes.
- `make test` is `out/ulang.sh test` of the whole project, about 9 seconds, where each unit loads and checks its package and the packages it imports, then `make testerrors`, which builds the binary of the tests of the project, `out/suite/suite.bin`, by `compile --tests` and `cc -O1`, about 12 and 9 seconds after a change of any `.u` file, and runs the tests of `ulang/test/errors/`, about 6 seconds, and then `make testdocs`, about 4 seconds.
- `make testc` runs all tests of `out/suite/suite.bin`, about 7 seconds once it is built, with the outcome of `make test` but without the proofs of lemmas. `compile` loads the whole library, so also the module `list`, which the runtime needs.
- `make install` packages the VS Code extension of `vscode/` as `ulang.vsix` into VSCodium: highlighting, a run button, `▶ Run` links above procedures without parameters and tests and `▶ Prove` links above lemmas, errors and open lemmas in the Problems view, and tests in the Testing view, by running the `out/ulang.bin` of the workspace or of the setting `ulang.binary`, so after a change of its path, `make install` again.

## Tests

- Tests are named, `test name() := …` of `assert` statements, in the `implementation` sections of the members, where they reach private declarations, and in programs in the subfolder `test/` of the package they test: `ulang/test/` of the language, which the whole of `ulang/` implements, `ulang/prove/test/` of the prover, and `ulang/prelude/test/` of the library. Every file passes: the errors that a phase must raise are cases of `ulang/test/errors/`, see below. Names are distinct, and the parser accepts formals, which the checker rejects. Programs are entered by procedures without parameters, e.g. `procedure main() := …`. The examples of functions and procedures and the lemmas run as tests too, `f.example.N` and `l.lemma`, in the files that declare them, also of the library, see Syntax and translations; a test of one call of a function is an example of it, `ulang/test/examples/` has those of the language.
- No test sits at the top of a `test/`: the programs that succeed are grouped by feature, one file per feature where their declarations do not clash, `ulang/test/expressions/`, `ulang/test/statements/` (also `for` and exceptions), `ulang/test/datatypes/` (also pattern aliases and orders, with their helper packages), `ulang/prelude/test/containers/`, `ulang/test/modules/`, `ulang/test/examples/`, a package whose examples run as its tests, `ulang/prelude/test/os/`, whose `files.u` writes its files below `out/test/os/` of the root, since no directory of the sources but the root has an `out/`, and `ulang/prove/test/`, of lemmas; a new test joins the file of its feature, under a name that tells it apart there.
- A test expects an exception by `assert raises p do … end`, in the file of its feature. No file fails: an error that a phase must raise is a case, the lines of a source text in a test of `ulang/test/errors/`, one file per kind, `parse.u`, `types.u`, `assignment.u`, `matches.u`, `runtime.u` (failed assertions, uncaught exceptions, and the errors of the evaluator), `modules.u`, and `lemmas.u` (lemmas that the default proof leaves open, and those whose tests fail, by `run_text`), which runs the case through the phases by `check_text`, `run_text`, or `prove_text` of `ulang/test/cases/cases.u` and expects by `assert raises` the exception of the phase where it fails, `ParseError` or `ImportError` of `ulang/parse/parse.u`, `Located` of `ulang/check/check.u`, `Unformatted` of `ulang/format/format.u`, the `RuntimeError` of `ulang/syntax/error.u`, or `OpenLemma` of `ulang/prove/lemma.u`, with `_` for the parts that hold types. A case sits at a path of `ulang/test/errors/`, so it imports the helper packages of the project from their files; a case of several modules of one package gives their texts to `check_texts` or `run_texts`, which parse them by `parse_texts` of `ulang/parse/parse.u`, so that no package on disk fails, also for cycles and broken siblings. The cases each load the library, too slowly for the interpreter, so `project.u` runs `ulang/test/errors/` only compiled, by `make testerrors`, which `make test` calls. The texts of the messages are tested apart, by `messages` of `ulang/check/message.u` and `ulang/syntax/error.u`.
- Tests of modules follow the packages: a directory is one package, so a test that is a module, or that expects an error in the sections of a module, has a directory of its own with the siblings it needs, e.g. `ulang/test/modules/siblings/`, and a helper that tests import is a package of its own, imported by its path from the root, `import "ulang/test/modules/hiding"`. The directory of an imported package needs a name of letters, digits, and `_`, `notation_right/`, while directories that nothing imports may have `-`.
- `checks/` holds the checks of the repository, programs whose `main` runs compiled at the root, since they parse the sources of the compiler, which the interpreter does too slowly, while their tests are of their own functions and run as all others do; `make testdocs` builds and runs them, and `make test` calls it. `checks/docs.u` checks that each reference of `CLAUDE.md`, `README.md`, and the files of `ideas/` but the review `ideas/review.md`, a list of names in backticks, separated by commas, `and`, or `or`, then `of` and a file, names declarations of that file, so lists of other things are separated by `;`, and a name that is only planned is written with `in`, not `of`. `make termination` builds and runs `checks/termination.u`, a report, not a test, of the recursive functions of `ulang/` and the library whose termination the prover does not prove, about 9 seconds.
- Take the expected exception of a case from a run of it, never guess it, e.g. by a pattern that matches nothing, such as `OsError("?")`, so that the exception is raised further and shows its value; positions count in the text of the case, which must be formatted if it parses and checks.

## Modules

- The root of a project is the nearest directory above a file with `project.u`, else the file's own directory, and a module of a project is known by its path from the root without `.u`, e.g. `ulang/check/check`, which messages, ` in m`, and mangled C names show; the modules of the library, a directory with `prelude.u`, as members of the package `prelude`, e.g. `prelude/map` (`place_of` of `ulang/parse/parse.u`, `library_module` of `ulang/syntax/syntax.u`), except in C, where they keep the names of their files, e.g. `t_list_46_List` and the key `"os.OsError"`, as the runtime and the seed refer to them (`c_text` of `ulang/compile/lower.u`). `import "p"` loads the package of the directory `p` from the root, once, without the tests of its members, where the names of the path have letters, digits, and `_`, also keywords, and never occur as tokens, so no `..` and no `-`; an import of a file `….u`, of an unknown package or one without members, of the own package, of the library, which every module sees without importing it, and a cycle of packages are parse errors (`parse_import` and `import_package` of `ulang/parse/parse.u`). Programs cannot be imported. `Mod.imports` are the ids of the imported packages, which `seen_modules` of `ulang/syntax/syntax.u` expands to their members. The parser gives `Source(mods, packages, main)` of `ulang/syntax/syntax.u`, the modules in load order, each after its imports, as `Mod(name, imports, exported, builtins, implemented)` with the commands of its sections paired with their positions, and the packages as `Package(id, members)`. Its only state is the source loaded so far, from which each module gets its initial notation, the exported notation of its imports and of the other members of its package (`exported_notation` of `ulang/syntax/notation.u`, `exported_ops` of `ulang/parse/parse.u`).
- Packages: a file with sections is a member of the package of its directory, known by the directory from the root, and `prelude` for the library; `project.u` and files without sections, programs, are none. Loading a module loads its package, all members, each parsed with the notations that the export sections of the others declare, read from their tokens before they are parsed, where whether a file has sections is known from its text, by a line that starts with `export`, `builtin`, or `implementation` (`load_package`, `has_sections`, `load_program` of `ulang/parse/parse.u`). Members see each other's exports without imports, also cyclically, and overload each other by type, while their private declarations and the constructors and fields of their abstract types stay private to their file; a program sees the exports of the package of its directory. Programs are not imported: each is the main file of its run, loaded after the package of its directory (`load_program`); so packages are the only units of imports, and cycles are cycles of packages. A project with a directory `prelude/` at its root shares the ids of the library, which `import "prelude"` rejects, and clashes with it in C.
- Every module implicitly imports the whole library, the package `prelude` of `prelude`, `option`, `list`, `str`, `set`, `map`, `array`, `buffer`, `os`, and `io`, whose members see each other (`library_modules` and `implicit_imports` of `ulang/syntax/syntax.u`), so no module imports one; the member `enumerate` of the library, the values that the tests of lemmas enumerate, is loaded with it but seen by no other module, so its names are no candidates of overloading, and the generated tests name its declarations by their qualified names, which the checker resolves without visibility (`overloads` of `ulang/check/check.u`); a module may declare their types again, which hide those of the library, and their functions with other types or arities, which overload them.
- A module sees its own declarations, the exported ones of the members of the packages it imports and of its own package, and the prelude, and likewise for notations: imports are not transitive. The checker resolves every name to its module, also of tests, `CTest(name, …)`, and gives `Prog(cmds, builtins, main)` of `ulang/syntax/syntax.u`, every command of the export and implementation sections of all modules with qualified names, at its declaration, the definitions checked and the rest as written, then the tests of examples and lemmas, the builtin sections apart, and the module of the loaded file, where the backends and `translate` take `definitions`, without the signatures and the pattern aliases, so that the driver takes the tests and `translate` the lemmas of a module by the modules of their names; it checks the members of each package together, and each program alone, once, after their imports, against their signatures (`check_program` and `check_package` of `ulang/check/check.u`, `Sig` of `ulang/check/sig.u`), where the private declarations of the members are in the signature, hidden from the other members by `State.hidden` and `State.hidden_sorts`, and type aliases are declared each after those it names.
- Sections, see `ulang/prelude/set.u`: imports, then `export` with notations, datatypes, aliases, signatures without bodies, and abstract types `type T[A]`, then optionally `builtin`, then `implementation` with definitions that repeat the signatures exactly, `data` for the abstract types, private declarations, and tests. Other modules see neither the private declarations nor the constructors and fields of abstract types. A module without sections has all its commands implemented and exports nothing, so only main programs have no sections; their private procedures and tests are the entry points of `run` and `test`.
- A `builtin` section has exported signatures without definitions and types without a definition, `type T[A]`, which the interpreter (`builtin_names` of `ulang/run/run.u`) and the runtime (`builtin_functions` and `proc_name` of `ulang/compile/lower.u`) define, make, order, compare, and show; its uses keep their module, and its types are not abstract types that raise `Unordered` or `Incomparable`. Examples: `str.u`, `os.u`, `array.u`, and the prelude, whose builtin section declares `Bool`, `Int`, `Str`, `Char`, the arithmetic `+`, `-`, `*`, `/`, `%`, and `++` of strings.

## Library

- The prelude declares the operators, `abs`, `gcd`, `min` and `max` of `Int`s, `first` and `second` of pairs, and the exceptions of builtins: `DivisionByZero` of `/` and `%`; `OutOfBounds(Int, Int)`, index and size, of `at` and the strict `slice` of strings and arrays; `NoCharacter(Int)` of `chr`; `NoByte(Int)` of `byte`; `MissingField(Str)` with the name `T.f`; and `Unordered(Str)` and `Incomparable(Str)` with the name of a type.
- `<`, `==`, `compare`, `show`, `and`, and `or` are builtins without a module. `compare` is a total order of all values, consistent with `==`, with results `-1`, `0`, `1`, where constructors are ordered by their position in their declaration; `<`, and the `<=`, `>`, `>=` of the prelude, each by one `<`, follow it.
- `str`: `chars(s)`, `str(cs)`, `int` and `chr` between characters and code points, `encode_utf8` and `decode_utf8`, `is_digit`, `is_letter`, `is_space`, `size`, `at(i, s)`, `get(i, s)` as an option, `contains(c, s)`, `slice`, `starts_with`, `ends_with`, `join`, `split`, `quote`, `number`.
  - A `Char` is a Unicode code point, 0 to 0x10FFFF without the surrogates 0xD800 to 0xDFFF, else `chr` raises `NoCharacter`, and a `Str` a sequence of them, which `size`, `at`, and `slice` count; `is_letter` and `is_digit` are ASCII, as names are. UTF-8 is only the encoding of the system: the procedures of `os` decode files, arguments, and names of files, where invalid UTF-8 raises `OsError`, and encode what they write; `encode_utf8` gives the bytes of a string, and `decode_utf8` the string of bytes as an option.
- A `Byte` of the builtin section of the prelude is one of 0 to 255, made by `byte(n)`, which raises `NoByte` outside them, read by `int(b)`, and shown as `byte(n)`; the interpreter keeps it as `VByte` of `ulang/run/run.u`, and the runtime as an object of `u_byte_type`, of which each byte exists once. Files of bytes are `Array[Byte]`, read and written by `os_read_bytes` and `os_write_bytes`.
  - The escapes of literals, `\"`, `\'`, `\\`, `\n`, `\t`, and `\r`, are `escapes` of `ulang/syntax/syntax.u`, which the lexer reads and the printers write by `escape`, where a quote is escaped only in a literal that it delimits; the runtime writes them by its own `escape` of `ulang/runtime/ulang.c`, which the test `escapes_round_trip` of `ulang/parse/lex.u` keeps in step in both backends.
  - The runtime stores each string in units of 1, 2, or 4 bytes, the narrowest that holds its code points, so that equal strings have equal units (`u_str_at` of `ulang/runtime/ulang.h`); literals are `U_LIT` of `"…"`, `u"…"`, or `U"…"` by their greatest code point (`format_str` of `ulang/compile/c.u`).
- `map` and `set`: `Map[K, V]` and `Set[A]`, abstract types of AVL trees ordered by `compare`, with `compare` and `==` by their elements and entries; `intersect(s, t)` of sets.
- `option`: `Option[A]` with `or_else`, `value_or`, `map_option`, `exists`, `forall`, and the folds of a container of at most one element, so generators and `for x in o do … end` take options, `List(for x in get(k, m) for y in f(x) yield y)`.
- `buffer`: `Buffer[A]`, the elements of a loop that adds at the end, kept as the reversed list: `empty()`, `b ++ xs` for a list `xs`, `size`, and the folds in the order of adding, so `List(for x in b)` reads it out; lexer, parser, and loops of the checker and the compiler use it where a list grows with the program, and `++` of lists where it is bounded by a construct.
- `array`: immutable `Array[A]`, kept as `VArr` of `Val` in `ulang/run/run.u`: `from_list(xs)`, `size`, `at(i, a)`, `get(i, a)`, `slice`, `contains`, and the folds.
- Lists, sets, maps, arrays, and strings share names and orders of arguments:
  - `size`, `contains`, `get` (of association lists for `list`), `remove` (elements of lists and sets, keys of maps), `empty` of sets and maps, `exists(c, p)`, `forall(c, p)`, and the folds `foldr(c, acc, f)` and `foldl(c, acc, f)`, in the order of lists and ascending for sets and maps, where `f` and `p` of maps take key and value.
  - Conversions are forms, `List(for x in c)` of the elements in order, `List(for k => v in m)` of the entries, `Set(for x in xs)`, `Map(for (k, v) in ps)`, where the last entry of a key counts, `Array(for x in xs)`, and `str(cs)` of characters.
  - `infix right 8 ++` and `infix left 7 --`: `++` concatenates lists and strings, unites sets, and joins maps, where the entries of the second count; `--` removes the elements of a list or set, and the keys of a set from a map.
- `os` declares `OsError` and the builtin procedures `os_args`, `os_read_utf8`, `os_write_utf8`, `os_read_bytes`, `os_write_bytes`, `os_library`, `os_print`, `os_print_error`, `os_exit`, `os_list` (sorted entries with whether each is a directory, without following links), `os_is_dir`, `os_cwd`, and `os_chdir`, of which those that touch files or decode names, all but `os_print`, `os_print_error`, `os_exit`, and `os_is_dir`, declare `raises OsError`, with `os_walk` of `ulang/prelude/os.u` for the files below a directory and `os_println`, which prints a string by `os_print` and then a newline, while `os_print` prints it as it is, and relative paths start from the working directory.
- `io` declares the builtin type `IO` of streams of bytes, files opened by `io_open(in path, mode, out io)` with a mode of `IoMode`, `IoRead`, `IoWrite`, or `IoAppend`, and the streams of the system by `io_stdin`, `io_stdout`, and `io_stderr`, read by `io_read_bytes` (at most n), `io_read_until` (through a delimiter), and `io_read_all`, written by `io_write_bytes`, and closed by `io_close`, after which every use raises `OsError`; `io_read_line`, `io_read_utf8`, and `io_write_utf8` of `ulang/prelude/io.u` decode and encode UTF-8 over them in ulang. A stream is passed `in`, since its state is the system's, which a `try` does not undo; streams are ordered by their openings and shown as `<io path>`, the interpreter keeps the host's own as `VIO` of `ulang/run/run.u`, the runtime as an object of `u_io_type` with its `FILE`, and the collector closes one that is unreachable.

## Overloading

- The candidates of a name are its declarations in all visible modules, its own module's no more than the others; locals hide them all, the parser builds no qualified names, and within a module, overloading is only by arity. Declared hooks `show`, `compare`, and `==` are no candidates: uses take the builtins, which reach the hooks through the types of their arguments (`is_hook` of `ulang/check/check.u`).
- An applied name infers its arguments first, then keeps the candidates of its arity whose instance unifies with them and the expected type, each tried on a copy of the substitution. One remaining candidate is committed; with several, the use gets a fresh type, a placeholder name, and a pending entry.
- Pending entries are solved to a fixpoint at the end of the command, before `zonk` replaces the placeholders, and lets do not generalize their types. A use resolves uniquely, by its types alone, without preferences: since the substitution only grows, a candidate that does not fit never fits again, so a use with one candidate left is committed, whatever the order of solving, e.g. `map.put` of a map literal, which then fixes the type of its `map.empty` when `set` and `array` are imported too. No candidate is an error, and several at the end of the command are ambiguous, both listing the candidates with their types.
- Accesses `e.f` and updates `e with f := a` resolve by the type of `e`, which must be known when the checker reaches them, else `UnknownFieldOwner`. Lambdas that are arguments wait until the other arguments and the function type are known, and then take the types of their formals from it, so `exists(xs, lambda q => q.x == 3)` and `(lambda p => p.x)(Point(1, 2))` check (`infers_first` and `infers_lambdas` of `ulang/check/check.u`); a lambda that is bound by a `let` has no expected type, while the declared type of a local, an assignment, or a result gives one, `local g: Point -> Int := lambda p => p.x`.

## Syntax and translations

- A datatype declares each of its constructors after `case`, as a match over it has its cases: `data T[A] := case C(name: A) case D`, one per line. Every argument of a constructor is a named field, `C(name: T, …)`; a name may repeat in the constructors of a datatype with the same type, and patterns bind the variables of the fields' names where they can. Fields give accessors `e.name` and updates `e with name := a, other := b`, parsed as `EField` and `EUpdate` (from the left) and resolved by the type of `e` to the accessor `T.name` and the updater `T.name:=`, so that checked programs have neither, which raise `MissingField("T.name")` for constructors without the field. The checker declares both for each field of a datatype, without definitions (`declare_fields` of `ulang/check/check.u`), exported where the constructors are, and the interpreter and the compiled code implement them by the position of the field in each constructor (`fields` of `Defs`, `u_select` and `u_update` of the runtime, or `u_field` where all constructors have the field at the same position). A comma followed by `name :=` continues the updates, also in `assign` and `local`.
- The forms `List(…)`, `Set(…)`, `Map(…)`, and `Array(…)` build containers (`parse_form` of `ulang/parse/parse.u`, `EForm` and `EFor` of `ulang/syntax/syntax.u`), capitalized as a datatype of one constructor is named as its type. Their names are forms only before `(`, in expressions and patterns, and name types elsewhere, `List[Int]`, so that no constructor, function, procedure, or pattern alias takes them, and a name of a form alone, as in `foldr(xs, Nil, List)`, is a parse error (`form_at` and `check_value_name` of `ulang/parse/parse.u`); `list`, `set`, `map`, and `array` are ordinary names:
  - `List(a, b)`, `List(a, b; r)`, `List()`; `Set(a, b)`; `Map(k => v, l => w)`; `Array(a, b)`; the rest `r` after `;` is the container that the elements are added to, where the new entries of a map win, and arrays have no rest. In patterns only `List(x, y; rest)` and `List()` occur, the constructors `Cons` and `Nil`, which are also written so, and which `format` writes as `List(…)`.
  - `List(for p in c if q yield e)` and the like, with generators `for p in c` and `for k => v in m` and guards `if q` from left to right, one after another without commas, `List(for x in xs for y in ys if q yield e)`, where a `Map` yields entries `k => v`, and `yield` is omitted after exactly one generator, which yields what its pattern binds, `Set(for x in xs)`, `Map(for k => v in m if q)`. Patterns of generators are irrefutable, else the translation is a type error.
  - The checker translates them (`generator` and `fold_expr` of `ulang/check/check.u`): a literal is unrolled, `Set(a, b)` is `set.insert(a, set.insert(b, set.empty()))`, `Map(k => v)` `map.put(k, v, map.empty())`, `List(a; r)` is `Cons(a, r)`, and `Array(…)` is `array.from_list` of a list; a generator infers its container, solves, and takes `foldr` for lists and `foldl` for the others from the module of its type, with the formals typed by the type arguments of the container, so `x.f` works in the next generators; a generator over a map with one pattern binds the pair, an unknown type is `UnknownContainer`, and a type whose module declares no such fold of three arguments `NoFold`. The accumulator has a name that users cannot write.
  - `show` writes the forms, `List(1, 2)`, `Set(1, 2)`, `Map(1 => "a")`, `Array(1, 2)`.
- `for p in c if q do … end` and `for k => v in m do … end` are the statement `SFor(gens, body)` of `ulang/syntax/syntax.u` over the elements of any container in the order of its fold, of one generator and an optional guard (`parse_for` of `ulang/parse/parse.u`), whose body assigns the variables around it and may not run, as that of a `while`. The checker gives the backends `SFor(List(GVal(pat, items)), body)`, where `items` is the list of the elements, the container itself if it is a list and else `List(for (item) in c)` by the folds of generators, and the guard is an `if` in the body (`items` of `ulang/check/check.u`), and the interpreter and the compiler walk the list. Its pattern is irrefutable like those of generators, else `NotExhaustive`.
- `if` always nests, without chains: in statements, `if c then … end` and `while c do … end` have a keyword after the condition, as `for p in c do … end` has, and `else if c then … end` is an `if` in the body of the `else`, with its own `end`, and statements may follow it there; in expressions, `if c then a else if d then b else e` nests the same way.
- Pattern aliases, `pattern And(a: Expr, b: Expr): Expr := EApp(EFun(Name(None, "and")), List(a, b))`, name a pattern whose variables are exactly the formals, each once (`AliasVariables`); `pattern` is a keyword, and an alias without formals is declared and built with `()`, `Zero()`, and matched also bare, `case Zero =>`. The checker types the pattern once in its module, after the constructors and the aliases before it, so aliases do not recur, and stores it with its constructors resolved in `Sig.pat_aliases` (`PatAlias` of `ulang/check/sig.u`, `declare_pat_aliases` of `ulang/check/check.u`); `binders` expands a use, which an alias joins as a candidate next to the constructors, by `subst_pat` of its arguments for the formals, so that exhaustiveness, `ulang/run/run.u`, and `ulang/compile/compile.u` see only constructors, and errors show the expansion. An alias without `_` is also a function of its name, whose body is `pattern_expr` of the pattern (`definition_of`), so `And(x, y)` builds the value; one with `_` only matches (`PatternOnly`). Aliases share the namespace of constructors and functions; an alias in `export` is exported whole, with its pattern, and must not match private constructors (`PrivateConstructor`), and one in `implementation` is private. `format` prints the alias at its uses as written.
- The formals of function lambdas are patterns: `lambda x, (a, b) => e` is `lambda x, (1) => match (1) case (a, b) => e end`, where the formals that are variables stay, those that are not get names that users cannot write and are matched in the body, checked for exhaustiveness as `let` is, as the formals of the folds of generators are (`lambda_match`, `formal_of`, and `matched` of `ulang/check/check.u`), and a name of a constructor or pattern alias is no variable, as `binders` resolves it (`is_pvar`), so that the backends see only variables.
- Lemmas, `lemma l[A](in x: A, …) := requires a, … ensures b`, with `requires` optional and the modes of a procedure in the head, where `out` formals are existential, given by `assign` in a proof and bound by the outs of a `call` to witnesses, locals without a value, and `ref` is rejected, state `b` for all ins that satisfy the assumptions, for the prover, with an optional proof after the contract, see `ideas/prove.md`, section 4: steps `local`, `call` of a lemma proven before or of the lemma itself as an induction hypothesis, and `assert`, then at most one split, `induction`, `match`, or `if`, whose cases are proofs (`Proof` of `ulang/syntax/syntax.u`, `parse_proof` of `ulang/parse/parse.u`, `check_proof` of `ulang/check/check.u` and of `ulang/prove/proof.u`), where `prove` reports each goal that a proof leaves open at its step, as an error of the kind `proof`, and a lemma without a proof has the default proof (`CLemma` of `ulang/syntax/syntax.u`, `parse_lemma` of `ulang/parse/parse.u`). The checker checks each assumption and `b` as a `Bool` over the formals, as the body of a function, so that the checked lemma has resolved names and folds instead of forms, and keeps lemmas in a table of their own, `Sig.lemmas`, apart from the values, whose names they may share, since only proofs cite them (`declare_lemmas` and `command` of `ulang/check/check.u`, `LemmaSig` of `ulang/check/sig.u`). Lemmas are private, in `implementation` sections and programs, `export` rejects them, and the interpreter and the compiler skip them; `lemma`, `requires`, `ensures`, and `induction` are keywords.
- Contracts of procedures, `requires a, …` over the ins and refs and `ensures b` over all formals, follow the `:=` before the examples, on the signature in `export` of an exported procedure, which its definition does not repeat (`ContractOnDefinition`, `with_contracts` and `contract` of `ulang/check/check.u`), and the checked program keeps them in `Spec` of the `CProc`; `requires` and `ensures` of a function are a parse error. A lemma `lemma l(in x: A, …, out y: B, …) := correct p(in a, …, out y, …)`, a `ClaimCorrect` of `ulang/syntax/syntax.u`, claims that every run of the call that ends normally from a state that satisfies the `requires` of `p` satisfies its `ensures`, where the outs of the call are those of the lemma in their order (`ClaimOuts`), and `p` is defined before it in its package (`ClaimOrder`); its proof is an `invariant e` per `while` of the body of `p` in the order of the source, each over the variables in scope at its loop (`loop_positions` of `ulang/syntax/syntax.u`, `with_scopes` and `claim_proof` of `ulang/check/check.u`), and none is the invariant `true` of every loop. `correct` and `invariant` are keywords. The translation runs the body over the terms of proofs (`claim_of`, `run`, and `run_loop` of `ulang/prove/translate.u`): an assignment is a definition of a new variable of its name, an `if` or `match` a split whose cases carry the rest of the body, a call the call of the contract of its procedure, which may be the procedure itself, its outs and refs values that nothing is known of without one, a `raise` the call of the contract `ensures false`, and a loop an `InvariantTerm`, which `invariant_gaps` of `ulang/prove/proof.u` checks by the invariant on entry, its preservation from new values of the variables that the loop assigns, and the rest of the body from the invariant and the negated condition; `for`, `try`, and `assert raises` in the body are gaps `Unsupported`. A claim holds only for the runs that end, so it is no fact of the lemmas after it and no lemma that a proof calls (`ClaimCalled`), else `ensures false` of a loop that does not end would prove them all, and it has no test `l.lemma`.
- Each lemma whose formals have enumerable types also gets a test `l.lemma`, which runs in both backends before the proofs (`lemma_tests` and `lemma_stmt` of `ulang/check/check.u`): it runs the statement on all values of the formals up to one depth, the largest of at most 4 at which the product of their numbers is at most 1000 (`depth_of` and `limits` of `ulang/prelude/enumerate.u`), the first formal in the outermost loop, and raises `Falsified` with the formals of the first case that satisfies the assumptions but not the conclusion, as `name = value, …`, and `Vacuous` if no case satisfies them. Values are enumerated by depth, a constructor one deeper than its deepest field, an `Int` of depth `n` from `-n` to `n`, without duplicates and without randomness, so a counterexample is among the smallest: `Int`, `Bool`, `Char`, `Str`, `List`, `Set`, `Map`, and `Array` by `Enumeration` of `ulang/prelude/enumerate.u`, tuples inline, and datatypes whose constructors the module sees and that are not abstract by a function `(enum)m.T` generated into the module of the lemma (`enum_fun` of `ulang/check/check.u`); type parameters stand for `Int`; a lemma with a formal of another type, a function, a procedure, a `Buffer`, or an abstract type, gets no test. The generated code is source with qualified names, which the checker checks after the definitions of the package, if they check without errors. Imports drop the lemmas of the modules they load, with their tests (`without_tests_of` of `ulang/parse/parse.u`).
- Examples of functions and procedures, lines `example …` after the `:=` of the head of a signature in `export` or of a private definition, before the body, where the contracts of `ideas/prove.md` will stand, document a call with its result and run as tests: the `Spec` of the declaration, a field of `CFun`, `CFunSig`, `CProc`, and `CProcSig` of `ulang/syntax/syntax.u`, where a signature with a spec is a head, `:=`, and the spec, which the next command follows (`parse_spec` of `ulang/parse/parse.u`), and an example goes as far as its expression, whatever the layout, and ends at the next `example`, a command, or what cannot continue it, so that a body after examples cannot start with `(`, `-`, an operator, `.`, or `with`, which a `let` can bind (`parse_example`), printed by `spec_text` of `ulang/format/format.u`; the checked program has no examples, and imports drop them (`without_examples` of `ulang/parse/parse.u`). An example of a function is a `Bool` expression that applies it, `example gcd(12, 18) == 6`, or an application that raises, `example chr(-1) raises NoCharacter(-1)`; one of a procedure is a call with the expected values of the outs and each ref as `before => after`, `example divmod(in 7, 2, out 3, 1)`, or one that raises, with `_` for the outs and each ref as before, `example divmod(in 7, 0, out _, _) raises DivisionByZero`. An example that does not parse fails its test, not its declaration, so that the file checks and the other examples run, keeping their numbers: the parser keeps it as an `AUnparsed` (`parse_example` of `ulang/parse/parse.u`), whose test raises the error of parsing as a `Str` (`example_body` of `ulang/check/check.u`), and `format` prints it as its tokens. The checker translates each into a test `f.example.N`, `N` from 1 per base name in the order of the source, after the definitions of the package check without errors (`example_tests` and `example_stmt` of `ulang/check/check.u`), checked as written, as a test of the module, so that its names take the declarations that overloading chooses; by convention an example applies its function, which nothing checks, so `example size(List(1)) == 1` written on `set.size` tests `list.size`. An example that raises a type its call cannot raise is `NeverRaised` at the example, while builtin exceptions, which no `raises` counts, are not checked. Examples on the definition of an exported name are `ExampleOnDefinition`, and an example of `export` is checked as an importer sees the module, without its private declarations (`example_commands`). `assert a == b` reports a failure with both sides; `example` is a keyword.
- `-n` for a number `n` is a negative literal, in expressions and patterns, e.g. `case -1 =>`. A number is decimal, or hexadecimal after `0x`, with digits of either case, `0xd800`, also negative, `-0x10`, where `0x` without digits is a parse error; the parser keeps it as `LHex` of `ulang/syntax/syntax.u`, which `format` writes with upper-case digits and without leading zeros, `0xD800` (`hex_text` of `ulang/syntax/syntax.u`), and the checker translates it to `LInt` (`checked_lit` of `ulang/check/check.u`), so that no later phase meets it, and `show` writes every `Int` in decimal.
- `let … in …` is an expression, not a statement, and the patterns of `let`, of generators, and of lambdas are irrefutable, so tests of refutable patterns, also of pattern aliases such as `And(a, _)`, use `match`.
- `let p := a, q := b in e` binds patterns in parallel (`ELet` of `ulang/syntax/syntax.u`), which are irrefutable, checked for exhaustiveness as the cases of a match where they are not all variables, and both backends bind them directly; no `let` generalizes, since only declarations have type parameters.
- Every part of an expression, statement, and pattern is an `At` of `ulang/syntax/syntax.u`: `AOk(pos, span, that)` at the position of its first token or of the token that names it, a call at its name, an operator at the operator, and with its `Span` from its first token to the end of its last, which the parser reads from the tokens, each with the stop of the code before it (`Tokens` of `ulang/parse/lex.u`, `span_from` of `ulang/parse/parse.u`), while the translations of the checker take the span of what they translate, and code that a phase makes without one the empty span `span_at(pos)`, and so is each declared formal and local, `At[Var]` at its name, which the phases after the checker read by `vars` and code that the parser did not read places by `unplaced_vars`, while the outs and refs of a `call` are plain variables; `AUnparsed(pos, span, text, error)` is a part that does not parse, which the parser makes, and `AErr(pos, span, that, errors)` a part or a command that checking rejects, with its diagnostics, whose positions may be inside it: a part, when its check ends, takes the errors reported while it was checked that none of its parts took (`take_errors` of `ulang/check/check.u`), so that a mismatch stands on the call, the `if`, or the assignment that finds it, while its diagnostic points at the part, and what manifests after the parts, the pending overloads, the errors of declarations and of raises, stands on the command that contains its position (`with_errors`), as the errors of the prover stand on the lemma and on the function whose termination is open (`with_proofs` of `ulang/prove/lemma.u`); patterns and parts at `Pos(0, 0)` take none, and the walk of errors is `cmd_errors` and `part_errors` of `ulang/syntax/syntax.u`, for the source and the checked program alike. No phase stops at an erroneous part: each treats it as it treats a part that does not parse, and the raises are checked over the commands without errors. A call that no declaration fits has the type `TError`, so that its uses make no follow-ups, while the other parts with errors keep the types of their declarations, which their consumers check (`application`, `choose`, and `unify_result` of `ulang/check/check.u`); the errors of a translation, as of a form, stand on the part that it translates (`translated`); and the commands of a package whose check raised are kept as written, as error nodes without errors of their own (`unchecked`). Errors are deferred: `run` and `test` run a program with errors if its main module is checked, which it is not if a package that it imports has errors (`is_runnable` of `ulang/ulang.u`), where a definition that its own errors make unsafe to run, all but those of raises and of proofs (`blocks_run` of `ulang/syntax/error.u`), or that has parts that do not parse, which checking keeps as written, has an error node of them as its body (`rejected` of `ulang/syntax/syntax.u`), and the interpreter raises the runtime error `Deferred` with the first of its errors where it reaches one (`require_checked` of `ulang/run/run.u`); the file fails with the status of its errors, or 3 if a test fails, `test` proves no lemmas of a unit with errors, and `check`, `lint`, `prove`, and `compile` refuse it. Positions are never stripped: the checked program keeps them, code that does not care reads `x.that`, and comparisons modulo positions, as the round trip of `format` (`same_cmds` of `ulang/ulang.u`) and the parser tests, take `strip_cmd` and the like, which set them to `Pos(0, 0)` and its empty span, as `nowhere` places code that the parser did not read.
- The parser desugars nothing: everything stays as written until the checker, `for` statements, lambdas with patterns, the forms, accesses and updates of fields, `let` of patterns, and pattern and type aliases, so that `format` keeps what the source wrote.
- `ulang/compile/compile.u` builds list comprehensions over lists and arrays, also of several generators, by nested loops without intermediate lists, array literals by `u_mk_array`, and array comprehensions by loops that fill an array sized by the first generator, grown for further generators and shrunk at the end unless it is exact.

- Comments are documentation, part of the syntax, and printed back by `format`: a run of `//` lines from the start of a line, in any column and without a blank line below it, is the doc of what follows: of a command, of a constructor of a datatype, of a statement of a body, `SBlock(locals, stmts)`, whose leading assignments from the `local` lines have none, or of a `case` of a `match` or `catch`, each a `Doc` of `ulang/syntax/syntax.u` with its `At`, so the types say where a doc may stand, and of the module if it comes first in the file and a blank line, an `import`, or `export` follows it (`Mod.doc`). The lexer gives `TDoc` (`lex_doc` of `ulang/parse/lex.u`), the parser takes it before a command, a statement, or a `case` (`parse_stmt_recovering` of `ulang/parse/parse.u`) and reports it anywhere else, a doc is `Some(text)` and `None` means none, and the printer writes it back (`doc_lines` and `indented_doc` of `ulang/format/format.u`). Each doc is the text of its lines without `//` and the space after it, joined by newlines. Docs are not checked and not compiled. Any other `//`, at the end of a line, before what ends a body or a `local` line, inside an expression, or detached by a blank line, is a parse error at the `//` (`misplaced_comment` of `ulang/parse/lex.u`), where the lexer gives a comment after code or above a blank line as `TMisplaced`, which `parse_mod` takes out of the tokens as an error, so that it does not change the parse.

## Semantics

- `raise e` is a statement, so only procedures raise, and functions fail only by the exceptions of builtins, such as `DivisionByZero`, and of accessors, `MissingField`; a failed `assert` cannot be caught. `assert raises p do … end` fails, with `AssertionNotRaised` of `ulang/syntax/error.u`, which cannot be caught either, unless its body raises an exception that the pattern `p` matches, typed as the pattern of a `catch` case and without variables (`RaisesVariables`), while another exception is raised further; the variables after it are those before, as at the start of a handler, since its body raises if it passes. `raises` after code is a pattern of what must be raised, and `raises T, …` after the formals of a procedure or the modes of a procedure type the types of what it may raise.
- What a procedure may raise is checked after its package, if it has no other errors, by `raises_errors` of `ulang/check/raises.u` over the checked commands and the tests of examples, which keep their positions, giving the first error of each command, which `check_package` of `ulang/check/check.u` adds to those of the package:
  - A raised value is of a datatype without type parameters, also a builtin one such as `Str`, else `NotAnException`, and so are the types of `raises`; the exceptions of builtin functions and accessors (`unchecked_exceptions` of `ulang/syntax/builtins.u`) are defects of the program, which no `raises` counts, as functions cannot declare them.
  - A statement raises the types of its `raise`, the `raises` of the procedures it calls, also through variables of procedure types, and what a `try` lets through: the types that its unguarded handlers do not cover, by the exhaustiveness check (`covers_all` of `ulang/check/check.u`), where `_` covers all, and what its handlers raise; `assert raises p` is a `try` of the one handler `p`. A handler of a type that its body cannot raise is `NeverRaised`.
  - A procedure with `raises`, or an exported one, which raises nothing without them, raises none of the others (`UndeclaredRaise`), and a private one without `raises` raises what its body does, inferred for all of them together as the least fixpoint (`infer_procs`).
  - Procedure types carry their raises as a set, the `TTuple` of the sorted types in `raised` of `TProc`, which unification compares exactly, without subtyping and without polymorphism over sets: a procedure used as a value, whose scheme has a parameter `(raised)` of its own (`proc_scheme`), and a lambda, `raised` of `EProc`, get an unknown, which the place of their use fixes, and the pass requires them to raise no more (`UntypedRaise`). A comma followed by `name :` ends the raised types of a procedure type, since it starts the next formal (`at_raised_type` of `ulang/parse/parse.u`), so a procedure type with raises in a list of types takes parentheses.
- The assignments of one `assign a := …, b := …` are simultaneous: `b := f(a)` reads the `a` from before, so a value that depends on another takes an `assign` of its own.
- Effects on variables are atomic: a procedure works on copies of its outs and refs, which reach the caller only when it returns, and the handlers of a `try` see the variables as before it. Compiled code copies outs and refs in and out, and saves the variables that the body of a `try` assigns before its `setjmp`.
- No formal, local, pattern variable, or formal of a lambda hides a local around it (`HiddenLocal`, `unhidden` of `ulang/check/check.u`), while locals may hide declarations, which depend on the imports; the names of the translations, such as `(acc)` and `(item)`, nest.
- Variables are read only where they are assigned on every path, and outs must be assigned on every path that does not raise, where passing a ref reads it (`Local` of `ulang/check/check.u`, joining the paths of `if`, `match`, and `try`; a `while` may not run its body, and a handler starts from the variables before its `try`). A local without a type must be initialized at the start of its block, by the assignments of one variable each that it starts with, `local x := e`, or as an out of a `call` after them, `local q, r` before `call divmod(in a, b, out q, r)` (`initialized` of `ulang/check/check.u`).
- Procedures are values of types `(in A, out B, ref C) raises E, …`: declared ones by name, and `lambda in x, out y, ref z => statements end`, which sees the variables around it by their values and assigns only its own outs and refs. The arguments of a call go by mode in the order `in`, `out`, `ref`, as in the signature, also when they come from different places, `call p(in a, out b, ref c)`. `call p(…)` calls a variable `p`, which hides a procedure `p`; compiled code calls through `u_call_proc` and the wrappers `wp_`.
- Functions without parameters are computed once, interpreted and compiled.
- Orders, equality, and show of datatypes:
  - A function `compare` or `==` of two values `T[A, …]` of a datatype `T` of its own module, with distinct type parameters, is the order or equality of `T` (`order_of` of `ulang/check/defs.u`), which the builtins `compare`, `==`, and `<` use for all values of `T`, also inside other values and in generic code; other datatypes compare structurally.
  - Only abstract types declare `==`; datatypes with visible constructors may declare `compare`, which must agree with structural equality, unchecked. With `compare` alone, `==` is `compare(a, b) == 0`.
  - Comparing values of an abstract type whose module declares no `compare` raises `Unordered`, and if it declares no `==` either, comparing and equating them raise `Incomparable`, since the structure of an abstract type is no order: the checked program keeps the abstract types as commands `CAbstract` of `ulang/syntax/syntax.u`, by which `unordered_of` of `ulang/check/defs.u` names the exception, which the interpreter raises and compiled code by `u_unordered` and `u_incomparable` of the runtime, in the descriptor of the type (`ulang/test/datatypes/orders.u`, `ulang/test/modules/modules.u`).
  - A function `show` of one value `T[A, …]` of a datatype `T` of its own module, with distinct type parameters and the result `Str`, is the show of `T`, which the builtin `show` uses for all values of `T`, also inside other values; otherwise `show` gives the text of a value, strings in quotes.
  - A function `show` of one value, or `compare` or `==` of two, must be a hook of these forms, else `MisshapenHook`, since uses do not reach it otherwise. The hooks are `Hook` of `ulang/check/defs.u`, with their names, arities, and results, from which `order_of`, the schemes of the builtins of their names, `is_hook`, and the message derive.
  - The runtime finds these through the type descriptor of each object (`struct u_type` of `ulang/runtime/ulang.h`, one `t_` per datatype, pointing to the declared functions or the structural ones), the interpreter through the maps of `Defs` of `ulang/check/defs.u` from datatypes to them.

## Style

- Formals are the parameters of functions, procedures, and lambdas; params are type parameters.
- Docs state what the code and its names do not: a rule, a reason, or a convention that holds beyond the line, e.g. that a position is in another module, or in which order a function visits. Omit those that restate the name of a declaration or the lines below. Name a piece of code by a function instead of commenting it, and put a note on the statement, `case`, or command that it explains.
- A function whose name and types leave its meaning open, such as the order of its arguments or what it does at the edges, has an example, exported or private, on the first occurrence of its signature, `example slice("abcd", 1, 3) == "bc"`, which, unlike a doc, cannot go stale. An example applies its own function to arguments of the types of its signature, since an overloaded name may otherwise take another declaration, which the checker does not catch.
- Functions only for computations that terminate; code that may not terminate, such as the evaluator of `ulang/run/run.u`, is written as procedures, unchecked.
- Functions, procedures, and locals are snake_case, e.g. `zonk_type`; constructors and types are CamelCase, e.g. `TSort`, `TypeError`.
- Records over positional tuples for anything kept in a table or passed on, with fields named by role, which uses read as selectors, `sc.typ`, `proc.ins`; tuples for pairs that are built and taken apart at once. A datatype of one constructor is named as its type, `Sig`, `Scheme`; the alternatives of a sum have the prefix of their datatype, `CFun` of `Cmd`; separate records of one family share a suffix, `ProcSig` and `ConstrSig` of `Sig` (`ulang/check/sig.u`), `FunDef`, `ProcDef`, and `ConstrDef` of `Defs` (`ulang/check/defs.u`).
- Names are descriptive but short, and one concept has one name, without short and long forms, for types, functions, and variables alike: `Constr`, `Mod`, `Sig`, `Prog`, not `Constructor`, `Module`, `Ctx`, `Program`, and a variable `constr` never has a `constructor` next to it.
- Variables are named by their type: `toks`/`tok`, `cmds`/`cmd`, `sig`, `loader`, `run`, `typ` and `types`, `fun`/`funs`, `text` for source and `offset` for positions in it, `name` for an `Id`, `cases`, `cond`, `body`, `prec`, `constr`/`constrs`, `field`/`fields`, `prog`, `expr`/`exprs`, `pat`/`pats`; `i`, `j` for plain counters.
- A variable of type `Stmt` is `stmt`, unless the declaration has another statement of that name, e.g. a pattern of `EProc` or `CProc`; parts of a statement keep their roles, `body`, `loop`, `step`.
- Patterns bind the names of the fields they match, `case EField(base, field)`, so a field is named by its role and a variable around the match by its type; where both would clash, the field name is the one to improve.
- Names carry no numeric indices, e.g. `stmt1` or `e1`: two of a kind in one scope get names by their roles, e.g. `decl` for the record of a constructor where a pattern binds `constr`, and a clash is resolved by a better name for one of them. Two conventions name the rest: what the checker makes of a part has the prefix `typed_` before the name of the part's field, `typed_expr`, `typed_pat`, `typed_guard`, `typed_args`, as `expr_branches` of `ulang/check/check.u` binds them; and the second of a pair without roles of their own has the suffix `_`, the tails `xs_` and `ys_` of two lists matched together, the types `t` and `t_` of `unify`, or the signature `params_` and `formals_` of a definition against `params` and `formals` of its export in `check_signatures`. Renaming never makes a short name long, e.g. `t` to `candidate`.
- Procedures that consume tokens start with `parse_`, except `advance` and `expect`; functions that build trees do not. Predicates on the next token are `at_X`, grouped together.
- Predicates, functions to `Bool`, are `is_X` for a property, `is_useful`, `has_X` for a part, `has_holes`, a verb in the third person for a relation, `contains`, `covers`, `occurs`, and `at_X` for the next token, never a bare adjective or noun such as `useful` or `holes`.
- `show` is text that parses back literally, never `show_X`; `format_X` prints into another language, e.g. types, values, tokens, programs, or C as source.
- Pattern aliases name a shape at the level where code works with it, by the prefix of that level, `VInt(n)` of values in `ulang/run/run.u`, `PCons(head, tail)` of patterns, `ECall(name, typ, args)` of expressions, `TBool()` of types, `HTuple()` of heads, and not names, so no guard such as `if constr == cons_name()`; they always build as well as match, so none has `_`, and a type inside, as of `Var`, is a formal, `_` where matched and `THole` where built. Aliases over names that checking resolves, such as `PNil()` and `ENil(typ)` of `ulang/syntax/builtins.u`, match only checked code; unresolved names, as the parser writes them, are matched directly, `PApp(Name(None, "Nil"), List())`. Functions such as `nil_name()` remain where a `Name` is used on its own.
- Patterns have two printers: `format_pat` of checked patterns, for messages, and `format_pattern(notation, …)` of the source, which alone keeps the round trip of `format`.
- The notation is threaded as the first parameter where it is needed, not bundled into records.
- Signatures that do not fit on one line have one parameter per line, with `in  ` padded so that names align with `out ` and `ref `.
- A match over a datatype that grows with the language, `Cmd`, `Expr`, or `Stmt`, names every constructor where a new one needs a decision, e.g. a traversal, so that the exhaustiveness check lists each place to change; a catch-all `_` stays where every other constructor means the same, as in a predicate or a selector of one constructor, or where another place decides, as `enter_section` of `ulang/parse/parse.u` does what a section holds. A named case that an earlier phase rules out raises `Unexpected` or another `InternalError` of `ulang/syntax/error.u` and says by a doc which phase rules it out, as `exposed` of `ulang/check/check.u` does.
- Write recursions with a large `match` explicitly, not as `foldl` with a step function; folds are for small steps.
- Each `local` is declared at the start of the innermost body that uses it, a case of a `match` or a branch of an `if`, and in each case that uses it, so that a reader sees which case uses which local; the top of a procedure declares only those that the code before or after its `match` uses, and those with initial values, which a case would compute at another time.
- In traversals such as `ulang/prove/simp.u`, bind every result of a recursive call by `let` before using it, keep the recursion in the traversal (`simp_term`), which passes the simplified parts to one helper per kind of term (`simp_app`, `simp_ite`) that only combines them.
- Iterate a map by `for k => v in m`, not by first making a list of its entries, `List(for x in m)`, and then taking the pairs apart; `for (k, v) in c` is for a list of pairs. This was mistaken for `for (k, v) in m` when flattening `field_table_decls` of `ulang/compile/compile.u`.
- The printer (`format`) lays out `match` and `catch` by one rule: each case body starts on the line after `=>`, and a blank line separates the cases unless there are at most two and each has a head and one line of body (`case_chain` of `ulang/format/format.u`); a `List(…)`, `Set(…)`, `Map(…)`, or `Array(…)` wider than 80 characters has one element per line, also a `List(…)` in a pattern, and so has a procedure head that is wider, with the modes `in`, `out`, and `ref` in front of the first formal of their group; the body of a function and the pattern of a pattern alias start on the line after `:=`, and the body of a `let` on the line after `in`, at the indentation of the line of the `let`; `if … then … else …` in expressions stays on one line if it fits in 80 characters, else each branch has a line of its own, one deeper, with `else if` at the level of the first `if` (`ite_text` and `spread_ite` of `ulang/format/format.u`).

# ulang

A minimal language with pure functional expressions, imperative statements, datatypes, and Hindley-Milner inference, implemented in itself in `ulang/`: parser, checker, interpreter, and a compiler to C, with a runtime in C (`ulang/runtime/`). Each phase is a package of its own, which imports those before it, so the imports check the layers: `ulang/syntax` (the syntax, the builtins, the notation, and the errors that all phases share), `ulang/format` (the printer), `ulang/parse` (lexer and parser), `ulang/expand` (the expansions of the constructs that the checked program keeps as the source wrote them, into the smaller language that the backends translate, by which the checker also builds the translations that it types forms by), `ulang/check` (signatures, definitions, the checker, the exceptions of procedures, and the messages of type errors), `ulang/run` (the interpreter), `ulang/compile` (C and the compiler to it, x86-64 assembly and the compiler to it, and the part they share), `ulang/prove` (the prover), `ulang/lint` (the lints), `ulang/refactor` (the scripted edits of `refactor`), and `ulang/test` (the tester, the files at the top of `ulang/test/`, whose subdirectories hold the tests of the language: the tests of lemmas that it generates, and the running of tests), with the driver `ulang/ulang.u`, a program that imports them all but `ulang/prove`, which it reaches through `ulang/test`. The Scala 3 implementation it started from is on the branch `scala-baseline`.

This file has three parts: Workflow, the rules of working in this repository, the build and its commands, and the tests; Language, what ulang means and where its implementation decides it, from the habits of other languages that fail to the syntax, the specifications, the semantics, overloading, modules, the library, and errors; and Style, the conventions of the sources. A new fact goes into the section of its topic.

# Workflow

## Working rules

- A question asks for an answer, not an action: answer it, propose what suggests itself, and act only on an explicit go-ahead. Read-only lookups are fine.
- Checks:
  - After a refactor that keeps behaviour, `out/ulang.sh check ulang/ulang.u` and `check --test` of the changed files are enough: `check ulang/ulang.u` runs no tests of the packages it imports, which imports drop, so it misses the tests that build the changed datatypes.
  - After each edit, `ulang.sh format` the edited files and `ulang.sh check --test --prove` them, which takes seconds; `make` only when the built tool is needed, such as for `format` of a changed printer.
  - Run `make test` after changes of behaviour, in the worktree of the work, or when asked, and say that it ran; it runs the tests interpreted only, and the handover to `main` then runs only the tests that the work touches. Work split among sub-agents in worktrees runs it once, on the merge, by the session that merges their branches, while each agent runs only the checks of the point above. A small item, a few lines in one place, is done inline rather than by an agent, which must first read this file and the code around it.
  - Compiled tests and checks, `make testerrors`, `make testc`, `make testelf`, and `make testdocs`, only after asking, also the run that a new case of `ulang/test/errors/` takes its expected exception from. The machine is shared by several sessions, so run nothing only to measure, and run checks under `nice -n 19`.
  - Run tests and checks in a worktree of your own, never against the `out/ulang.bin` of the main tree, which other sessions rebuild while it runs, so that a test fails with internal errors such as `++ is not initialized`.
  - `make testc` only with a strong reason, e.g. changes to `ulang/compile/compile.u`, the runtime, or what the generated C depends on, and only after asking; a change of `ulang/compile/compile.u`, `ulang/compile/x86.u`, `ulang/compile/lower.u`, or the runtime runs `make testelf` next to it, so that both backends keep the same outcome.
  - Time every phase of a run of checks and keep the output, so that questions about durations are answered from it; never rerun only to measure.
  - Redirect the output of `make` to a file, never pipe it into a command that may exit first, such as `tail -0` or `head`: `make` then dies of the broken pipe before linking, and a stale `out/ulang.bin` runs the next checks.
- Edit `.u` files through `ulang.sh refactor`, by its scripts of actions, not by text edits, `sed`, or rewriting the file, and brief sub-agents to do the same: its uses are how the tool improves, so each friction with it, an unclear refusal, a missing action, a slow or misleading reply, or a workaround, goes into `ideas/refactor.md` as an item, with the script and the reply.
- Edits by script: a replacement scripted against the text before `format` misses where `format` changed the layout, so a script asserts that each replacement matches exactly once and writes nothing otherwise; and `git add` with one path that does not exist stages nothing, so check what a commit holds.
- When `check` passes plainly wrong code, compare the errors that `check_all` of `ulang/check/check.u` returns with `diagnostics` of the checked program, which shows an error that the tree lost.
- Samples with lemmas over functions that may not terminate run under `ulimit -v` and `timeout`, since their tests grow memory without bound under `ulimit -s unlimited` (Testing 6 of `ideas/testing.md`).
- Commits: no `Co-Authored-By` for Claude; end the message with `Agentic Coding (<model>)`, e.g. `Agentic Coding (Claude Opus 5.5)`. Run `make` after every commit, so that `out/ulang.bin` is current.
- Other sessions may edit the same files, also those of `ideas/` and `CLAUDE.md`, at the same time: commit only the hunks of your own work, applied to the committed version, and leave theirs in the working tree.
- `ideas/` holds the open items, one file per area, listed in `ideas/index.md`, each item as the problem and the desired solution, named by its area and number, Testing 1 for item 1 of `ideas/testing.md`; delete an item when it is done. Explanations go into this file or `README.md`.
- Plans and guides of work in progress, such as `ideas/gui.md`, are files of `ideas/`, versioned as all files are, and listed in `ideas/index.md`; delete each when its work is done, and what stays true afterwards goes into this file, `README.md`, or the items of `ideas/`.
- Before making a word a keyword, search the sources for it as a name and rename those uses: the seed still takes it as a name, so `make` builds, and only the new lexer of `make test` rejects it.
- When working on ulang code, record in `unclear.md` each trip-up and unclear point: a wrong guess, a search that led nowhere, a doc that was stale or misleading, each as what was wrong and what is so, so that the documentation can be fixed from it.
- To compare a compiler before and after a change, e.g. the C that both compile from the same files, build the one before from the committed sources in a worktree of its own, never take the `out/ulang.bin` of the main tree, which other sessions rebuild from their uncommitted edits; the binary finds the library by the path that `-DULANG_LIB` compiled in, no variable of the environment, so its worktree stays until the comparison is done, and the outputs of two compilers also differ by their libraries if the change touches `ulang/prelude/`.
- No auto-memory: rules for later sessions go into this file, and only if it does not already say them.
- Finished work goes onto `main`, never left on a branch, in a worktree, or as a patch; a reverted experiment is no work, so say where its patch is. Work of several steps runs in a worktree below `.claude/worktrees/` on a branch of its own, each step committed there; to hand it over, merge `main` into the branch, run `make` and only the tests that the work touches, the files and cases it changed or affects, never all of `make test` again, then `git merge --ff-only` the branch in the main tree and `make`, and remove the worktree and the branch when the work is done.
- A new lint rule is run over the project before it is committed, each warning classified as a mistake or intended, and proposed with its count and samples of its sites, since false positives sink a rule; warnings that have an edit are fixed by `ulang.sh refactor @fix`, not by hand.
- Never add `volatile` to the generated C or to the runtime, not even as an experiment, and never propose it as a fix: it is not the solution to the miscompilations of `setjmp` by clang -O2, which are known, see `BUGS.md`. If a problem appears to have a real reason for `volatile`, stop and ask the user before writing it anywhere.
- Profile compiled programs with gprof, not perf, which cannot record call graphs here: build with `-pg`, run with `GLIBC_TUNABLES=glibc.gmon.maxarcs=50000000:glibc.gmon.minarcs=1000000`, and sum several runs by `gprof -s` if one has too few samples; gprof does not see time in shared libraries such as libgc.

## Build

- `make` builds the tool `out/ulang.bin`, the compiler of the current sources `ulang/*.u` and `ulang/*/*.u`, with the library in `ulang/prelude/`: the seed `bootstrap/ulang.bin`, built from `bootstrap/ulang.c`, the C of the last compiler that compiled itself to the same C, translates them to `out/ulang.c`. Each binary is linked with the runtime, GMP, and the Boehm collector, and rebuilt when its inputs change: about 15 seconds from nothing, 7 after an edit of the sources; `rm -rf out` loses nothing that `make` cannot rebuild. `ULANG_LIB` is the directory `ulang/prelude/` of the library, for imports and `os_library`. Commands exit with status 0 if all succeeds, 1 for errors of the sources, 2 for a usage error, 3 for a run, test, or lemma that fails, and 4 for an internal error, the worst of several, the greatest (`load_status` of `ulang/ulang.u`, `has_errors` of `ulang/parse/parse.u` and of `ulang/check/check.u`, where the parsed modules hold their errors as the parts that do not parse and the checked program as its parts and commands that checking rejects, `AErr`, read by `diagnostics` of `ulang/check/check.u`). The interpreter and the compiler recurse as deeply as the programs they run, so each binary is run by a copy of `bootstrap/ulang.sh` of its name next to it, `out/ulang.sh` for `out/ulang.bin`, which `make` makes and calls, and copies with the binary to the root, `ulang.sh` and `ulang.bin`, which are not versioned, and which sets `ulimit -s unlimited`, else the hard limit, before it runs the binary; so the commands below are `out/ulang.sh run …` and the like, never `out/ulang.bin` directly. Compiled programs need the same limit, so the binaries of the Makefile have copies of the script, too.
  - The commands are those of `usage` of `ulang/ulang.u`, read by `request` into a `Request`, where a usage error exits with status 2 and prints the usage, also an option that a command does not take (`paths_request`), and `ulang.sh help <command>` describes one. Only `format` and `refactor` write sources: `check` reports, and the edits that lints propose, `Edit` of `ulang/syntax/syntax.u` in each `Warning` of `ulang/lint/lint.u`, are applied by `refactor @fix`, which a lint never bypasses, while those of errors are planned (Diagnostics 2 of `ideas/diagnostics.md`). A target `file.u:name` selects a declaration of a file, where only a path ending in `.u` is split at its last `:`.
  - `ulang.sh run <file>[:<procedure>] [-- args]` calls the procedure, by default `main`, without parameters, in the interpreter `ulang/run/run.u`, also in a program with errors, after reporting them, as far as they allow (deferred errors, under Errors); `os_args` gives the arguments after `--`.
  - `ulang.sh check [--lint] [--test [--timeout <seconds>]] [--prove] [--overlay F=<path> …] [<path>[:<name>] …] [-- args]` loads and checks the `.u` files of the paths, by default the root of the project of the working directory, directories walked in the order of names without the hidden ones and those named `out`, and with `--test` without the directories that `project.u` runs only compiled (`targets_of`, `walk_all`, and `compiled_only_of` of `ulang/ulang.u`), reporting the errors of parsing, of types, and of format, and adds the phases of its options to each unit that loads, also with errors where it is runnable, as far as the errors allow (`check_targets` and `check_unit` of `ulang/ulang.u`). The files are grouped into units, the packages of their directories, whose members load together (`units_of`); each unit is loaded and checked once, also for several phases, where the parser keeps the tests of all members of the package of the loaded file. A file passes if its unit loads and its phases pass, the status is that of the worst (`load_status`), and with several files `check` prints the files that do not pass, `file: failed` after their failed tests, or the errors of their unit, as JSON lines of its first file, and `N of M files passed`; the errors of a single file that fails to load go to stderr, as JSON lines. Names select tests and lemmas, so a target with a name needs `--test` or `--prove`, and with both, each name selects the test or the lemma of its name, where one that is neither is an error; a file named alone runs only its own tests, though its package loads whole. `--overlay F=<path>`, repeated for several files, takes the text of the file at path as that of `F`, as of an unsaved buffer of an editor, which the loader reads instead of the file, also for the format and the grouping into units, so that the errors are reported against `F` (`overlay_texts`, `visit_units`, and `units_of` of `ulang/ulang.u`, `overlaid_text` of `ulang/parse/parse.u`), as `hints` and `refactor` take it.
    - `--lint` prints the warnings of the lints of each file that loads, as `file: warning[Code]: message, write replacement at L.C`, which do not fail it, where `Code` is the rule, a constructor of `Lint` of `ulang/lint/lint.u`, and a rule without a replacement omits `, write …`. The rules are walks of the parsed module, which keeps the positions and the source that `format` prints, each with a test in `ulang/test/lint/`: rewrites from a pattern to a simpler expression with the same meaning (`placed_lints`, `iterated_list`, and `collecting_loops`), printed by `format_module_expr` of `ulang/format/format.u`; locals and pattern variables that are never read, also locals that only receive outs, which `out _` drops, locals declared above the one branching statement that uses them, and a `var` that nothing assigns after its value (`locals_lints`, `declared_lints`, and `binder_lints`); private declarations that no export, test, lemma, example, hook, or procedure without formals reaches (`unused_privates`); handlers that only `skip` (`swallowed`); and names with numeric indices or `show_` (`name_lints`), where a digit after the last `_` of a standard name, such as `utf8` or `md5`, is no index (`standard_names` of `ulang/lint/lint.u`). The walks judge names as written: a pattern names the library as written, e.g. `Some` and `value_or`, so a module that declares such names again may get a lint that does not check, and declarations count by their base names, so an overload that is used keeps the others.
    - `--test` runs the tests of each file, each on its own, in the working directory, so that tests give paths from the root, where `make` runs them, printing `test name passed` or `test name failed: …` per test as it runs, labeled `file: ` if there are several files (`test_module` of `ulang/test/runner.u`), where `os_args` gives the arguments after `--`; the tests of a unit with errors run too, failing where they reach one (deferred errors, under Errors), which a test that fails so names only by its position, `test t failed by reaching file.u:L.C, listed above`, as the reply of `refactor` does (`failure_text` of `ulang/test/runner.u`); with `--timeout`, a test that runs longer than its seconds fails with `ran longer than its limit of N s`, by a deadline that the interpreter checks at each call and each round of a `while` (`Deadline` and `require_time` of `ulang/run/run.u`).
    - `--prove` proves all or the named lemmas of each file, after its tests, printing `lemma name proved` or `lemma name open`, the latter with an error of the kind `proof` for each goal that its proof leaves open, at its step and with the goal as a detail (`gap_diagnostic` of `ulang/prove/lemma.u`), by the default proof of `ulang/prove/lemma.u`: simplification, else induction on one of the formals, with the lemmas proven before as facts; a recursive function that the lemmas reach, also one that reaches itself only through a function value that a reflexive datatype holds, such as `Box(f: (Box, Int) -> Int)` (`reflexive_sorts` of `ulang/prove/translate.u`), unfolds only if the prover proves that it terminates (`terminations` of `ulang/prove/termination.u`), else it stays uninterpreted and an error of the kind `proof` names the call that no measure decreases (`termination_diagnostic` of `ulang/prove/lemma.u`); the checked program is translated by `translate` of `ulang/prove/translate.u`, which keeps its resolved names, since the builtins of the prover are pattern aliases over the names that checked programs carry (`ulang/prove/syntax.u`), while the sequents `Seq` and `Concl` are declared in `ulang/prove/simp.u`. `out/ulang.bin` contains the prover. A lemma whose test `l.lemma` finds a counterexample is reported as `lemma l falsified` and not proven, nor a fact of those after it; a lemma with errors of its own is not proven, and none is if code that the lemmas may reach has errors that block a run (`blocks_proofs` of `ulang/ulang.u`).
  - `ulang.sh hints [--overlay F=<path> …] <file>` checks the file as `check` does, with the overlays as those of `check`, without requiring its format, prints its errors to stderr, and then prints the findings of the check in its main module to stdout, one JSON object per line in the shapes of `Hover` and `InlayHint` of LSP, `{"kind": "hover", "line": L, "column": C, "end_line": …, "end_column": …, "text": "prelude.list.size: List[Int] -> Int"}` over each use of a name with its qualified name and its type at the use, and over each local, formal, and pattern variable with its type, `{"kind": "inlay", "line": L, "column": C, "label": ": Int"}` after a declared name whose type the source does not write, unless the type has an unknown, of an error or of a use that stays open, which a hover shows as `?` (`unknowns_hidden` and `has_unknown` of `ulang/check/hints.u`), and `" raises T"` after the formals of a private procedure without `raises`, as inferred, where columns count code points from 1 and an end is just after the span (`hints` and `format_hint` of `ulang/check/hints.u`, `print_hints` of `ulang/ulang.u`). The table is read from the checked program, which keeps the resolved names, the types after the pending uses are solved, the spans, and the inferred raises (`with_inferred` of `ulang/check/check.u`, `Exceptions` of `ulang/check/raises.u`); a part counts only if the parser placed it, which the text tells, a name written over its span, so the parts that translations make at the span of what they translate, and the inner parts of pattern aliases at the spans of their declarations, have none, and neither have the calls of procedure values, whose types the table does not know, while a use of a pattern alias in a pattern, which the checked program keeps, has the type of the alias as a function of its formals (`constr_types` of `ulang/check/hints.u`). The VS Code extension runs it on the file, with an unsaved buffer written to a file of a temporary directory and passed by `--overlay`, keeps its findings per version of the document, and shows them as hover and inlay hints, refreshed on save and half a second after the last edit of a buffer, while a version before that has none (`parseHint`, `hintsOf`, and `refreshLater` of `vscode/extension.js`).
  - `ulang.sh refactor [--dry] [--overlay F=<path> …] [<script> | @<action> …]` edits sources by declaration, from a script of actions, lines that start with `@`, each followed by its fragment; the actions, the forms of a node, an example, and the reply are in Refactoring of `README.md`, and the actions on the command line are a script of a line each, from each word that starts with `@`, where the last, if it is a `@put` or `@patch`, takes its fragment from stdin (`inline_script` of `ulang/ulang.u`). Prefer it to text edits of `.u` files: a script is one transaction, writes formatted files, and replies with the state, `applied, clean` or its errors and warnings, each with how many are new if the script changed a file, `applied, 2 errors (1 new), 1 warning (0 new)`, and its tests, exiting 1 while errors remain and 3 if a test failed, and with the diagnostics and the warnings of the lints that are new or gone in the files it checked, the format of every member of their units included (`checked_diagnostics` and `format_errors` of `ulang/ulang.u`), which are the files that it changed or names by `@check` and the importers of their packages that name a declaration whose lines in the export or builtin section it changed, read from the texts, with the constructors and fields of a datatype (`importer_files` and `changed_exports` of `ulang/refactor/refactor.u`), whose number the first line then gives, `clean in 3 files`, each new one with the handle of its node, once per file, position, and code (`deduplicated` of `ulang/refactor/refactor.u`), so that the follow-ups of a change are its list of work; `@check test` runs the tests in the reply, but not those of the files in the directories that `project.u` runs only compiled, which it names (`compiled_only_files` of `ulang/ulang.u`), and counts the tests of examples on definitions, which `ExampleOnDefinition` reports, as not run, not those of the importers, and names the tests of the packages of its files that the errors of an earlier script left out and that no script has run since, kept in `out/refactor/unrun.txt` (`refactor_tests` of `ulang/ulang.u`, `test_outcomes` of `ulang/test/runner.u`, `run_actions` and `load_unrun` of `ulang/refactor/refactor.u`). It splices the text of whole declarations and nodes by the spans of the parsed file, since comments are not in the tree (`run_script` of `ulang/refactor/refactor.u`). Its parses and checks read the texts that the script has edited as overlays, which the loader takes instead of their files, also in directories that do not exist yet, so that a new package and its first import are one script (`parse_file_overlaid` and `overlaid_files` of `ulang/parse/parse.u`, `parsed` of `ulang/refactor/refactor.u`), and `--dry` checks the texts that it would write, so its reply has the diagnostics of a real run, without handles, which would name nodes of unwritten files, and without tests, which run on the files; `--overlay F=<path>` takes the text of the file at path as that of `F`, as of an unsaved buffer of an editor, for the actions and both checks, and writes it only if the script changes it (`refactor_request` of `ulang/ulang.u`). Handles are nodes that start their lines, each a statement, a case, an expression, or a constructor (`kinded_nodes` of `ulang/refactor/nodes.u`), kept in `out/refactor/handles.txt` of the root by their paths from the root, normal, as the paths of every action are (`normal_words`), and by the index and the hash of the text of each, and the edits of a script move those of their declaration to its new nodes, at their places where `format` moved nothing around the edit (`rebase` and `aligned`), while an edit from outside makes them stale; a node is also addressed by its declaration and a text, read with the escapes of string literals, or a position (`resolved_address`, `node_by_text`, and `unescaped`), and is shown with the comments above it (`with_comments`); the journal of `@undo` is `out/refactor/journal/` (`state_dir`). `@put` writes a new module whole, also into a directory that does not exist yet, which the loader then takes as a package of no other members (`package_files` of `ulang/parse/parse.u`), and otherwise merges the imports and the parts after `export` or `builtin` of a fragment into their sections, making them where missing, also before or after a declaration, into its section, or in its place whatever its arity, where a declaration that the file has is replaced where it stands, whatever section the fragment names, the doc of a definition goes to its signature in `export`, and a private procedure that it exports gets the raises that the check inferred, as `@export` does (`put_into`, `put_anchored`, and `with_exported_raises` of `ulang/refactor/refactor.u`); `@rename` resolves uses by `hints` of `ulang/check/hints.u`, writes the edits of the script before it and its own at once, and undoes the script unless every use resolves after its writes as before (`flush` and `commit_rename`), and it renames no types, fields, locals, or modules yet; `@outline`, `@refs`, `@sig`, and `@resolve` are queries (`outline`, `refs`, `name_sig`, `module_sig`, and `resolve` of `ulang/refactor/refactor.u`), as `@show` is, whose refusal is a note of the reply, so that the script goes on (`is_query`), where `@sig` of a name parses the files of the project and the library whose export sections name it outside comments, each with its package and imports unless an earlier parse loaded it, and `@resolve` reads the table of `hints` of `ulang/check/hints.u`; `@export` and `@unexport` move the doc, contract, and examples between a definition and its signature, with the raises that the check infers (`export_target` and `unexport_target`); `@fix` applies the `Edit` that each `Warning` of `ulang/lint/lint.u` carries, unless it adds an error to the unit, which the reply names (`fix`, `tried_splices`, and `local_splices` of `ulang/refactor/refactor.u`); `@patch` of several lines takes a block, the old lines, a line `=>` alone, and the new lines (`patch_block`), and its old texts occur at most once in each part of the target, the signature and the definition of a declaration, or of a file each declaration and each run of lines of no declaration, the header above the imports included (`file_parts` and `patch_line`). Its scripts are tested in `ulang/refactor/test/`, which `check --test` skips when it walks the project, since `project.u` runs it only compiled, as each parse loads the library, while a file there named to `check --test` runs interpreted, far too slowly; the rest of `ideas/refactor.md` is planned.
  - `ulang.sh compile <file>[:<procedure>] -o <target.c>` translates the program to C, whose `main()` calls the procedure, by default `main`, as the entry `EntryProc` of `ulang/compile/compile.u`, also with errors that generate no code, those that do not block a run and those of lemmas, tests, and contracts, also of parsing in a lemma or test, which an unparsed command is if the keyword that starts it is `lemma` or `test`, which the parser records in its error (`started_by` of `ulang/parse/parse.u`, `unparsed_command` of `ulang/syntax/syntax.u`), which it leaves out of the program and reports as warnings, while it refuses every other error (`compile_target` of `ulang/ulang.u`, `code_free_errors` of `ulang/syntax/syntax.u`); the C is `static` except `main` and what `ulang/runtime/ulang.h` declares extern (`runtime_referenced` of `ulang/compile/lower.u`), so the C compiler drops the parts of the library that nothing reaches; compile it by `cc -DULANG_LIB='"'$PWD/ulang/prelude'"' -I ulang/runtime target.c ulang/runtime/ulang.c -lgmp -lgc`. A target ending in `.s` is x86-64 assembly for Linux instead, by `assemble_program` of `ulang/compile/x86.u` from the checked program, in the instructions of `ulang/compile/asm.u`, with the names and analyses that both backends share in `ulang/compile/lower.u`; link it by `cc target.s out/asm/ulang.o -lgmp -lgc`, the runtime that `make out/asm/ulang.o` compiles; a target ending in `.o` is an ELF object of the same assembly, encoded by `encode_object` of `ulang/compile/elf.u`, which only the linker needs, `cc target.o out/asm/ulang.o -lgmp -lgc`, the path of the backend, while `.s` is a view for debugging: `make testelf` runs the tests of the project as `make testc` does, compiled to objects, and `make selfcompileelf` checks that the compiler linked from its object compiles itself to the same object and C, without replacing the seed. The assembly backend stays and grows with the language, toward registers, ARM64, and unboxed integers (Compiler 2 and 3 of `ideas/compiler.md`), so the walks over expressions and statements are written twice, in `ulang/compile/compile.u` and `ulang/compile/x86.u`, as its cost; `make` and `make selfcompile` build from C until the assembly build is as fast, since the interpreter of an assembly build runs about 5 % slower, and C stays the portable backend, also of ARM64 and macOS, and the seed `bootstrap/ulang.c`. The assembly is position-independent, calling the runtime and the C library by `@PLT`, and keeps every variable and temporary in a slot of its frame, so that no value stays in a register across a `setjmp`, where a `try` saves the variables that its body assigns in slots of their own, which its handler restores; the layouts of the structures of `ulang/runtime/ulang.h` that it reads are written once in `ulang/compile/x86.u` and checked by the `_Static_assert`s of `ulang/runtime/ulang.c`, so that a change of the header fails when the runtime compiles instead of breaking programs. The runtime sets the free-space divisor of the collector to 1, which collects less often than the default 3 at a larger heap and took `make test` from 89 to 63 seconds, unless `GC_FREE_SPACE_DIVISOR` of the environment is set, e.g. to 3 by a session short of memory.
  - `ulang.sh compile --tests [<dir>] -o <target.c>` translates the tests of all `.u` files below the directory, by default the root of the project, with its packages and subpackages, also of the directories that `check --test` skips, into one program, and refuses a file, each unit checked as `check --test` checks it and each module taken from its own unit (`compile_tests` of `ulang/ulang.u`), whose `main()` takes the targets of `check --test`, files with their names and directories, and the arguments after `--`, but none of its options, not `--timeout`, at the root, and runs the selected tests as `check --test` does, with the tests of lemmas but without their proofs (`EntryTests` of `ulang/compile/compile.u`, `u_run_tests` of `ulang/runtime/ulang.c`); a unit that does not load fails the compilation.
  - `ulang.sh format [<path> …]` rewrites the files of the paths, by default the project, as source (`format_program` of `ulang/format/format.u`), in place, and refuses a file whose source does not parse to the same commands. `check` fails on a file that `format` would change, with a `format error` at the first line that differs, after the errors of parsing and checking (`check_file` of `ulang/ulang.u`, `require_formatted` of `ulang/format/format.u`), also of each member of the unit, so every file that parses and checks is formatted, which tests parser and printer by their round trip; `format` keeps the imports in their order, which is the order of loading. Run `ulang.sh format` on each `.u` file after editing it, and `make reformat` after a change of the printer, which formats the project.
- Every command runs the built `out/ulang.bin`, but the tests that `check --test` runs are interpreted, with the current sources of what they load, also of the compiler: after an edit of `ulang/`, its tests see the edit at once, while `run`, `format`, `hints`, and the checking by `check` itself see it only after `make`.
- The repository is one project, whose root has `project.u`, so that the modules of `ulang/` and of the tests are known by their paths from it, and tests import their helpers by such paths. `project.u` declares what convention cannot decide, the function `project(): Project` of the type `Project` of `ulang/prelude/os.u`, here the directory of programs that run only compiled, `ulang/test/errors/`, which `ulang.sh check --test` does not run when it walks it; no directory below a root may have a file `project.u`, which would be a root of its own.

A new syntax reaches the sources one step after the commit that teaches it: that commit, then `make selfcompile`, which replaces the seed, and only then the sources that use it; and branches that teach the seed merge one at a time, each followed by `make selfcompile`. Both replace the seed, `bootstrap/ulang.c` and `bootstrap/ulang.bin`, only if the new compiler compiles itself to the same C, keep the previous pair in `bootstrap/<time stamp>/`, and then rebuild `out/ulang.bin`. Their stages are in a directory `out/stage-*` of each run, removed if it succeeds. The C of the seed is versioned, the binaries are not, and of the backups only those worth keeping are committed. `make selfcompile` takes about 15 seconds, `make bootstrap` about 4 minutes. A module moved out of the library keeps its file until `make selfcompile`, since the seed reads the modules of the library that it has compiled in.
- `make test` is `out/ulang.sh check --test --prove` of the whole project, interpreted, about 65 seconds on a quiet machine (7f5a990), 80 at a load of 2.5, and up to 110 while other sessions build in their worktrees, where each unit loads and checks its package and the packages it imports. `make testerrors` builds the binary of the tests of `ulang/test/errors/` alone, `out/errors/errors.bin`, by `compile --tests ulang/test/errors` and `cc -O1`, and runs them; `make testdocs` builds and runs `checks/docs.u`, about 4 seconds.

## Tests

- Tests are named, `test name() := …` of `assert` statements, in the `implementation` sections of the members, where they reach private declarations, and in files without sections in the subfolder `test/` of the package they test: `ulang/test/` of the language, which the whole of `ulang/` implements, `ulang/prove/test/` of the prover, and `ulang/prelude/test/` of the library. Every file passes: the errors that a phase must raise are cases of `ulang/test/errors/`, see below. Names are distinct. A test with formals, `test append_size(xs: List[Int], ys: List[Int]) := assert …`, is a property: the checker checks its body with the formals of their types, and the tester runs it on their enumerated values, as the test of a lemma, where each `assert` outside the body of a `try` or an `assert raises`, whose handlers could catch it, raises `Falsified` with the values of the formals and, of an equation, both sides, and a formal of a type that is not enumerable fails it with `Unenumerable` (`property_stmt` and `with_counterexamples` of `ulang/test/generate.u`); the runners and the backends skip the test with formals, which runs as the test of its name that the tester generates. Runs are entered by procedures without parameters, e.g. `procedure main() := …`. The examples of functions and procedures and the lemmas run as tests too, `f.example.N` and `l.lemma`, in the files that declare them, also of the library, see Specifications; a test of one call of a function is an example of it, `ulang/test/examples/` has those of the language.
- No test sits at the top of a `test/` but the lemmas of `ulang/prove/test/`: the programs that succeed are grouped by feature, one file per feature where their declarations do not clash, `ulang/test/expressions/`, `ulang/test/statements/` (also `for` and exceptions), `ulang/test/datatypes/` (also pattern aliases and orders, with their helper packages), `ulang/prelude/test/containers/`, `ulang/test/modules/`, `ulang/test/examples/`, a package whose examples run as its tests, `ulang/test/properties/`, of tests with formals, `ulang/prelude/test/os/`, whose `files.u` writes its files below `out/test/os/` of the root, since no directory of the sources but the root has an `out/`, and `ulang/prove/test/`, of lemmas; a new test joins the file of its feature, under a name that tells it apart there. A test that parses a text takes `parse_text_recovering` of `ulang/parse/parse.u`, which reads no files and parses with `builtin_notation` of `ulang/syntax/notation.u`, so the text declares the other operators it uses, as `ulang/test/format/comments.u` does; `parse_file_text` of `ulang/parse/parse.u` loads the package of its path with the library, about 13 s per call in the interpreter, which two such tests took of `make test`.
- A test expects an exception by `assert raises p do … end`, in the file of its feature, and one whose parts it computes by a guard, `assert raises OsError(text) if text == "closed listener " ++ path do … end`. No file fails: an error that a phase must raise is a case, the lines of a source text in a test of `ulang/test/errors/`, one file per kind, `parse.u`, `types.u`, `assignment.u`, `matches.u`, `runtime.u` (failed assertions, uncaught exceptions, and the errors of the evaluator), `modules.u`, and `lemmas.u` (lemmas that the default proof leaves open, and those whose tests fail, by `run_text`), which runs the case through the phases by `check_text`, `run_text`, or `prove_text` of `ulang/test/cases/cases.u` and expects by `assert raises` the exception of the phase where it fails, `ParseError` or `ImportError` of `ulang/parse/parse.u`, `Located` of `ulang/check/check.u`, `Unformatted` of `ulang/format/format.u`, the `RuntimeError` of `ulang/syntax/error.u`, or `OpenLemma` of `ulang/prove/lemma.u`, with `_` for the parts that hold types. A case sits at a path of `ulang/test/errors/`, so it imports the helper packages of the project from their files; a case of several modules of one package gives their texts to `check_texts` or `run_texts`, which parse them by `parse_texts` of `ulang/parse/parse.u`, so that no package on disk fails, also for cycles and broken siblings. The cases each load the library, too slowly for the interpreter, so `project.u` runs `ulang/test/errors/` only compiled, by `make testerrors`, after asking. The texts of the messages are tested apart, by `messages` of `ulang/check/message.u` and `ulang/syntax/error.u`; a hint of `hint_of` of `ulang/check/message.u` is no `Hinted` of `ulang/check/check.u`, so a case reads such a hint by `located_message` of `ulang/check/message.u`, and the message of `OpenLemma` of a gap ends with ` at L.C`. A single case runs in the interpreter too, `check --test ulang/test/errors/types.u:<name>`, since only the walk of `check --test` skips the directory.
- Tests of modules follow the packages: a directory is one package, so a test that is a module, or that expects an error in the sections of a module, has a directory of its own with the siblings it needs, e.g. `ulang/test/modules/siblings/`, and a helper that tests import is a package of its own, imported by its path from the root, `import ulang.test.modules.hiding`. The directory of an imported package needs a name of letters, digits, and `_`, `notation_right/`, as does every name of a path that a qualified name writes, the file of the module included: as in Java, `-` is no part of a name, since it is an operator, so `own-int.Int` reads as a subtraction, and a module of a file or directory with `-` cannot be qualified, which the files of programs and the cases of `ulang/test/errors/` with their ids such as `ulang/test/errors/own-type-clash` do not need.
- `checks/` holds the checks of the repository, programs whose `main` runs compiled at the root, since they parse the sources of the compiler, which the interpreter does too slowly, while their tests are of their own functions and run as all others do; `make testdocs` builds and runs them, after asking. `checks/docs.u` checks that each reference of `CLAUDE.md`, `README.md`, and the files of `ideas/`, a list of names in backticks, separated by commas, `and`, or `or`, then `of` and a file, names declarations of that file, so lists of other things are separated by `;`, and a name that is only planned is written with `in`, not `of`. A list of names is read backwards from `of`, each name before a separator, so a word between two names that is no separator ends it: "by default `main`, `EntryProc` of …" names `main` in that file. It also checks that the keywords that `LANGUAGE.md` lists are those of `keywords` of `ulang/parse/lex.u`, by `keyword_problems` of `checks/docs.u`, and runs each fenced block of the language u in `LANGUAGE.md` as a case of `run_text` of `ulang/test/cases/cases.u`, a formatted file whose tests pass (`block_problems` of `checks/docs.u`), while blocks without `u` are fragments. `make termination` builds and runs `checks/termination.u`, a report, not a test, of the recursive functions of `ulang/` and the library whose termination the prover does not prove, about 9 seconds.
- Take the expected exception of a case from a run of it, never guess it, e.g. by a pattern that matches nothing, such as `OsError("?")`, so that the exception is raised further and shows its value; positions count in the text of the case, which must be formatted if it parses and checks.

# Language

## Writing ulang

`LANGUAGE.md` is the language for writers of programs, by example: the habits of other languages that fail, the constructs, the semantics of effects and exceptions, and the library with its shared names; read it before writing ulang. The sections below are how the implementation decides it. The errors give the form to write after `; ` for the habits that they recognize (`hint_at` and `operator_hint` of `ulang/parse/parse.u`, `hint_of` of `ulang/check/message.u`, and `Hinted` of `ulang/check/check.u`, with the cases `habits` of `ulang/test/errors/parse.u` and `hints` of `ulang/test/errors/types.u`). The habits of other languages that fail, which `LANGUAGE.md` gives with more:

- Statements are `let x := e` of a name bound once, `var x := e` of a variable, `x := e` of an assignment, whose commas are sequential, `a := 1, b := a`, `p(in a, out b)` of a call, also `p(in a, out _)`, which drops the out, `raise e`, `skip`, and the blocks, where `let` and `var` stand anywhere in a body, up to its end, and a `let` is assigned by nothing, so `x := 1` of a `let` is `x is not assignable`; no `return`, `break`, or `+=`, so a procedure gives results by its `out` formals, and a loop ends by its condition or an exception.
- The keywords that `LANGUAGE.md` lists are no names, also not of fields, formals, or locals; `and`, `or`, `not`, `show`, and `compare` are names, and the forms `List`, `Set`, `Map`, and `Array` are names of types, forms only before `(`.
- `if c then … end` and `while c do … end` in statements, `if c then a else b` in expressions, which always has its `else`; `else if` opens an `if` of its own, with its own `end`, and no `elif`; a missing `end` is reported at the construct still open where the parse ends, `the if, or a construct inside it, has no end`, which may be at the end of the input (`expect_end` of `ulang/parse/parse.u`).
- Cases with the same body share one head, `case TPlus | TMinus =>`, also nested, `Some(1 | 2)`, where every alternative binds the same variables; `||` is no operator, Bool has `and`, `or`, and `not`.
- Containers are forms, `List(1, 2)`, `List(x; rest)` also in patterns, `Set(…)`, `Map(k => v)`, `Array(…)`, never `[1, 2]` or `x :: rest`; `[…]` is only for type arguments, `List[Int]`.
- Tuple types are written as tuples are, `(Int, Str)`, also as type arguments, `List[(Int, Str)]`, and `()`; since `(A, B) -> C` is a function of two arguments, a function of one pair is `((A, B)) -> C` (`as_type` and `type_apply` of `ulang/parse/parse.u`).
- Strings join by `++`, never `+`, which is of `Int` only, and `show` gives the text of any value.
- `//` starts a comment to the end of the line, anywhere, which `format` keeps where it stands: on a line of its own above the next part, at the indentation of that part, or at the end of the line of the part before it; one that the layout of its part has no place for, such as inside an operand, moves above the line of the part. The doc of a declaration is the run of comments right above it.
- Functions are expressions without `raise`, failing only by the exceptions of builtins, so code that raises, may not terminate, or reads files is a procedure.
- An exported procedure that raises says so after its formals, `procedure load(in path: Str, out text: Str) raises OsError, ParseError`, in `export` and `implementation` alike, and a formal of a procedure type says what its values may raise, `step: (in Int, out Int) raises Failed`, and so does an entry, a procedure without formals such as `procedure main() raises OsError`, so that no checked exception escapes a run that its raises do not declare; private procedures with formals infer it, so the errors name each place to change: `p raises T, which its raises omit` at the raise or call, `the procedure value q raises T, which its type omits` where `q` is passed, and `the handler of T is unreachable` for a handler that nothing in its `try` can reach.
- Layout is not written by hand: `ulang.sh format` gives it, and `check` rejects any other.

Check after each small edit; which declaration an overloaded name such as `size` takes depends on the imports and the types, so read the `export` sections of the imported packages. Within one module a name is overloaded only by arity, so a `lower(s: Str): Str` beside a `lower(c: Char): Char` is no overload, and `refactor @put` of it replaces the other; and `get(k, xs)` of a list looks up an association list, while `at(i, xs)` takes the element at an index.

## Syntax and translations

- A datatype declares each of its constructors after `case`, as a match over it has its cases: `data T[A] := case C(name: A) case D`, one per line. Every argument of a constructor is a named field, `C(name: T, …)`; a name may repeat in the constructors of a datatype, and must have the same type in each, else a parse error, and patterns bind the variables of the fields' names where they can. Fields give accessors `e.name` and updates `e with name := a, other := b`, parsed as `EField` and `EUpdate` (from the left) and resolved by the type of `e` to the accessor `T.name` and the updater `T.name:=`, the names `Owned(m, List("T"), "name")` and `Owned(m, List("T"), "name:=")` whose owner is the datatype (`accessor_name`, `updater_name`, `accessor_field`, and `field_of` of `ulang/check/defs.u`), so that checked programs have neither, which raise `MissingField("T.name")` for constructors without the field. The checker declares both for each field of a datatype, without definitions (`declare_fields` of `ulang/check/check.u`), exported where the constructors are, and the interpreter and the compiled code implement them by the position of the field in each constructor (`fields` of `Defs`, `u_select` and `u_update` of the runtime, or `u_field` where all constructors have the field at the same position). A comma followed by `name :=` continues the updates, also in `assign` and `local`.
- The forms `List(…)`, `Set(…)`, `Map(…)`, and `Array(…)` build containers (`parse_form` of `ulang/parse/parse.u`, `EForm` and `EFor` of `ulang/syntax/syntax.u`), capitalized as a datatype of one constructor is named as its type. Their names are forms only before `(`, in expressions and patterns, and name types elsewhere, `List[Int]`, so that no constructor, function, procedure, or pattern alias takes them, and a name of a form alone, as in `foldr(xs, Nil, List)`, is a parse error (`form_at` and `check_value_name` of `ulang/parse/parse.u`); `list`, `set`, `map`, and `array` are ordinary names:
  - `List(a, b)`, `List(a, b; r)`, `List()`; `Set(a, b)`; `Map(k => v, l => w)`; `Array(a, b)`; the rest `r` after `;` is the container that the elements are added to, where the new entries of a map win, and arrays have no rest. In patterns only `List(x, y; rest)` and `List()` occur, the constructors `Cons` and `Nil`, which are also written so, and which `format` writes as `List(…)`.
  - `List(for p in c if q yield e)` and the like, with generators `for p in c` and `for k => v in m` and guards `if q` from left to right, one after another without commas, `List(for x in xs for y in ys if q yield e)`, where a `Map` yields entries `k => v`, and `yield` is omitted after exactly one generator, which yields what its pattern binds, `Set(for x in xs)`, `Map(for k => v in m if q)`. Patterns of generators are irrefutable, else the translation is a type error.
  - The checker types them directly and keeps them as written: a form by the type of its elements and the container of its name, `List[A]`, `Set[A]`, `Map[K, V]` of elements `(K, V)`, or `Array[A]`, reporting a part of another type as `an element of List` or `the rest of List` (`form_types`, `yields`, and `form_rest` of `ulang/check/check.u`), and a generator by the scheme of the fold of the module of the type of its container, whose function gives the type of its items, a pair of key and value for a map, and whose accumulator is the container that the form builds (`generators` and `fold_items`), each generator in the scope of the patterns of those before it, with the type of the container of each generator recorded in the field `typ` of its constructor, which the parser leaves `THole` (`GVal` and `GPair` of `ulang/syntax/syntax.u`); `k => v` over a container that is no map matches its items as pairs, as `for` statements do; `expanded` of `ulang/expand/expand.u` translates them for the backends from the recorded types (`for_expansion`): a literal is unrolled, `Set(a, b)` is `set.insert(a, set.insert(b, set.empty()))`, `Map(k => v)` `map.put(k, v, map.empty())`, `List(a; r)` is `Cons(a, r)`, and `Array(…)` is `array.from_list` of a list; a generator infers its container, solves, and takes `foldr` for lists and arrays and `foldl` for the others from the module of its type (`fold_items` of `ulang/check/check.u`), with the formals typed by the type arguments of the container, so `x.f` works in the next generators; a generator over a map with one pattern binds the pair, an unknown type is `UnknownContainer`, and a type whose module declares no such fold of three arguments `NoFold`. The accumulator has a name that users cannot write.
  - `show` writes the forms, `List(1, 2)`, `Set(1, 2)`, `Map(1 => "a")`, `Array(1, 2)`.
- `ulang/compile/compile.u` builds list comprehensions over lists, arrays, and strings, also of several generators, by nested loops without intermediate lists, array literals by `u_mk_array`, and array comprehensions by loops that fill an array sized by the first generator, grown for further generators and shrunk at the end unless it is exact, and an array comprehension over other sources, sets, maps, options, buffers, and the types of programs, inside the `foldr` of each, whose function pushes each element into an array that grows, reversed once at the end, since a strict `foldr` applies its function from the last element to the first, and which assumes that a fold passes its accumulator on once (`built_array` of `ulang/compile/lower.u`, `u_array_start`, `u_array_push`, and `u_array_reversed` of the runtime, by internal names of `builtin_functions` of `ulang/compile/lower.u`), in both backends. The order in which a comprehension evaluates its parts is unspecified, since only which of two builtin exceptions it raises can tell it: the loops take the elements first to last and then the rest after `;`, while the `foldr` of its translation, which the interpreter runs, takes the rest first and then the elements from the last, so tests expect no exception of a comprehension where two of its parts raise different ones.
- `for p in c if q do … end` and `for k => v in m do … end` are the statement `SFor(gens, body)` of `ulang/syntax/syntax.u` over the elements of any container in the order of its fold, of one generator and an optional guard (`parse_for` of `ulang/parse/parse.u`), whose body assigns the variables around it and may not run, as that of a `while`. The checked program keeps its generator and guard, with the type of the container (`items` and `loop_gens` of `ulang/check/check.u`), and `expanded` of `ulang/expand/expand.u` gives the backends `SFor(List(GVal(pat, items, typ)), body)`, where `items` is the list of the elements, the container itself if it is a list and else `List(for (item) in c)` by the folds of generators, and the guard is an `if` in the body (`loop_expansion` of `ulang/expand/expand.u`), and the interpreter and the compiler walk the list, where the compilers walk an array or a string by index instead of the list of its items (`indexed_items` of `ulang/compile/lower.u`). Its pattern is irrefutable like those of generators, else `NotExhaustive`.
- `if` always nests, without chains: in statements, `if c then … end` and `while c do … end` have a keyword after the condition, as `for p in c do … end` has, and `else if c then … end` is an `if` in the body of the `else`, with its own `end`, and statements may follow it there; in expressions, `if c then a else if d then b else e` nests the same way.
- Pattern aliases, `pattern And(a: Expr, b: Expr): Expr := EApp(EFun(Name(List(), "and")), List(a, b))`, name a pattern whose variables are exactly the formals, each once (`AliasVariables`); `pattern` is a keyword, and an alias without formals is declared and built with `()`, `Zero()`, and matched also bare, `case Zero =>`. The checker types the pattern once in its module, after the constructors and the aliases before it, so aliases do not recur, and stores it with its constructors resolved in `Sig.pat_aliases` (`PatAlias` of `ulang/check/sig.u`, `declare_pat_aliases` of `ulang/check/check.u`); a use, which an alias joins as a candidate next to the constructors, stays in the checked pattern as `PApp` of the alias (`constructor_binders` of `ulang/check/check.u`), whose uses of the modules of the pattern count for `UnusedImport` (`pattern_aliased`); exhaustiveness expands it by its arguments for the formals (`alias_free` of `ulang/check/check.u`), so that errors show the expansion, and so does `expanded` of `ulang/expand/expand.u` for the backends (`alias_expansion`), from the `CPatAlias` of each alias in the checked program, which has its resolved pattern, free of aliases, and follows the function of an alias that builds (`with_alias` of `ulang/check/check.u`), so that `ulang/run/run.u`, which keeps them in `Run` for the tests that it expands, and `ulang/compile/compile.u` see only constructors. An alias without `_` is also a function of its name, whose body is `pattern_expr` of the pattern (`definition_of`), so `And(x, y)` builds the value; one with `_` only matches (`PatternOnly`). The alternatives at the top of the pattern of an alias follow `case`, one on each line, as the constructors of a datatype do, `pattern CSig(): Cmd := case CFunSig(…) case CProcSig(…)`, where `|` at the top is a parse error and stays for alternatives inside, `case Some(1 | 2)` (`parse_alias_cases` and `require_cases` of `ulang/parse/parse.u`, `alias_pattern_text` of `ulang/format/format.u`); such an alias only matches, as one with `_` does. Aliases share the namespace of constructors and functions; an alias in `export` is exported whole, with its pattern, and must not match private constructors (`PrivateConstructor`), and one in `implementation` is private. `format` prints the alias at its uses as written.
- The formals of function lambdas are patterns: the checker types those that are no variables as the patterns of one case, checked for exhaustiveness as `let` is, and keeps each, annotated by its type, `PAnnotated` (`lambda_patterns` of `ulang/check/check.u`), where a name of a constructor or pattern alias is no variable, as `binders` resolves it (`is_pvar`); the backends take the variables and the body of `expanded_lambda` of `ulang/expand/expand.u`, by which `lambda x, (a, b) => e` is `lambda x, (1) => match (1) case (a, b) => e end`, with formals of names that users cannot write, as the folds of generators match theirs, so that the backends bind only variables.
- `-n` for a number `n` is a negative literal, in expressions and patterns, e.g. `case -1 =>`. A number is decimal, or hexadecimal after `0x`, with digits of either case, `0xd800`, also negative, `-0x10`, where `0x` without digits is a parse error; the parser keeps it as `LHex` of `ulang/syntax/syntax.u`, which `format` writes with upper-case digits and without leading zeros, `0xD800` (`hex_text` of `ulang/syntax/syntax.u`), and the checker translates it to `LInt` (`checked_lit` of `ulang/check/check.u`), so that no later phase meets it, and `show` writes every `Int` in decimal.
- `let … in …` is an expression, and the statements `let` and `var` declare locals; the patterns of `let`, of `var`, of generators, and of lambdas are irrefutable, so tests of refutable patterns, also of pattern aliases such as `And(a, _)`, use `match`.
- `let p := a, q := b in e` binds patterns one after another, each in the scope of those before it, and a tuple binds in parallel, `let (a, b) := (b, a) in e` (`ELet` of `ulang/syntax/syntax.u`); the patterns are irrefutable, checked for exhaustiveness as the cases of a match where they are not all variables, and the checker checks the bindings one after another and keeps them in one `let`, while `expanded` of `ulang/expand/expand.u` gives the backends one binding per `let` (`let_expansion`), which they bind directly; no `let` generalizes, since only declarations have type parameters.
- The statements `let p := e, …` and `var p := e, x: T, y, …` are `SLocal(mutable, decls)` of `ulang/syntax/syntax.u`, which declare the variables of their patterns from there to the end of the body, one after another as the `let` of expressions, where a `let` has a value for each and binds what nothing assigns after, and a `var` declares variables, also without a value; the checker checks each declaration in the scope of those before it, for the statements after it in its block, where the variables of a `var` are assignable and those of a `let` are not, and a pattern that is no variable is irrefutable, checked for exhaustiveness as the cases of a match (`local_block` and `statement_node` of `ulang/check/check.u`), and keeps them as written, each pattern with the types of its variables and each value checked; `expanded` of `ulang/expand/expand.u` gives the backends those blocks (`block_expansion`).
- Every pattern may have a type, `p: T`, `PAnnotated` of `ulang/syntax/syntax.u`, also inside, `(x: Int, y)`, and the formals of function lambdas, `lambda p: Point => p.x`, as patterns, which the checker unifies with the type that the pattern matches before it checks the pattern, so that the annotation resolves the fields and constructors inside, and drops (`pattern_binders` of `ulang/check/check.u`).
- An expression may have a type in parentheses, `(e: T)`, an ascription, `EAnnotated` of `ulang/syntax/syntax.u`, which the parser tells from a tuple by the `:` after the first expression, and which stands alone in its parentheses, so that a component of a tuple or an argument of a call is ascribed in parentheses of its own, `((a: T), b)`, while `(a: T, b)` and `f(a: T)` are parse errors with a hint (`ascription_hint` of `ulang/parse/parse.u`): one form, which `format` prints as it is (`node_out` of `ulang/format/format.u`), where a component could not tell its ascription from the tuple. The checker checks the expression against the type, which it passes down, so that a part of another type is reported at the part, and the ascription resolves accesses, overloads, and the formals of lambdas, `(p: Point).x`, `size((empty(): Set[Int]))`; the checked program keeps it with the normalized type, as the checker expands nothing for the backends, and the interpreter, the compilers, and `translate` of the prover take it as its expression (`infer_node` of `ulang/check/check.u`).
- Alternatives, `p | q`, `POr` of `ulang/syntax/syntax.u`, are a pattern anywhere, also nested, `Some(1 | 2)`, where each binds the same variables with the same types, else `OrVariables` at the alternative, and `|` binds tighter than `: T`, which `format` writes around alternatives in parentheses; a case head wider than 80 characters puts each alternative after the first on a line of its own, under it after `| ` (`case_head` of `ulang/format/format.u`). The checked program keeps them, one case with one guard and one body, so that the checker, the raises, and the hints see the case as written: `binders` types each alternative, and the exhaustiveness check splits a row of alternatives into a row per alternative, as Maranget's matrices do, so that `Unreachable` stands at an alternative (`or_rows` and `reachable` of `ulang/check/check.u`). A case with alternatives means the cases of its alternatives in order, multiplied out from the left where they nest, each with the guard and the body (`alternatives` and `expanded_cases` of `ulang/syntax/syntax.u`), so a guard that fails on one alternative tries the next, and only the backends take them apart: the compilers test the alternatives where they stand, taking at each `|` the first that matches, which is the first of the expansion, since the tests of a pattern are a conjunction over the paths of the value and none depends on a variable, and declare the variables of the case before a test that assigns them, in C as the operands of one expression, which hold since no value is `NULL` (`match_expr` of `ulang/compile/compile.u`), and in assembly into slots of the case (`match_pat` of `ulang/compile/x86.u`); only a case with a guard is multiplied out, and only at the alternatives that bind variables, since a guard that fails on the variables of one tries the next (`tested_alternatives` of `ulang/syntax/syntax.u`), into alternatives tested one after another, each assigning the variables of the case and repeating the guard, while the body is compiled once (`case_stmts` of `ulang/compile/compile.u`, `shared_alternatives` of `ulang/compile/x86.u`); and the last case of a match without a guard, which exhaustiveness makes match what the cases before leave, and the irrefutable pattern of a `let` or `for` test only all but the last alternative at each `|`, as a `case _` tests nothing (`case_alternatives` of `ulang/compile/compile.u`, `case_test` of `ulang/compile/x86.u`), and compile a `let` of a pattern with alternatives as a match of one case; `translate` of the prover gives a branch per alternative, each binding the variables in its own order; and the interpreter binds by the first alternative that matches (`match_into` of `ulang/run/run.u`), which gives the first of those cases, and tries the cases of the alternatives only if the guard fails, from the first, so the guard of the alternative that matched runs twice (`select` of `ulang/run/run.u`). The alternatives at the top of a handler, of `catch` and `assert raises`, match exceptions of their own types, `case Refused(text) | text =>`, each annotated in the checked program by its type, while the handler has the type `THole` (`handler_pattern` of `ulang/check/check.u`), so every reader of the type of a handler takes it apart first, into a handler per alternative of its type (`expanded_handlers` of `ulang/syntax/syntax.u`): the interpreter, and the raises, which cover a `try` and report `NeverRaised` per alternative (`handler_alternatives` of `ulang/check/raises.u`), while the compilers split it only at the top, by the types, and each part as the pattern of a case, so that the alternatives inside stay where they stand (`tested_handlers` of `ulang/syntax/syntax.u`). `|` is no operator: the lexer rejects `||` and a `|` next to a character of operators, with their hints (`is_glued_bar` and `character_hint` of `ulang/parse/lex.u`), and the parser hints at a `|` after an expression (`hint_at` of `ulang/parse/parse.u`).
- The parser desugars nothing: everything stays as written until the checker, `for` statements, lambdas with patterns, the forms, accesses and updates of fields, `let` of patterns, pattern and type aliases, and ascriptions, so that `format` keeps what the source wrote. The checker resolves names, accesses and updates of fields, and type aliases, and keeps the other constructs as written, with what their expansions need recorded, such as the type of the container of a generator or of a formal that is a pattern, while checks such as exhaustiveness expand them internally; the backends expand them, the interpreter, the compilers, and `translate` of `ulang/prove/translate.u` each by `expanded` of `ulang/expand/expand.u` on the checked program first, and a lambda of patterns where they meet it (`expanded_lambda`). The checked program says what the source wrote, so that the hints, the raises, and the lints read the constructs, not their translations.
- Comments are not in the tree, as in gofmt and rustfmt: the lexer gives every line of a comment as a `Comment` of `ulang/syntax/syntax.u`, with its position, whether it stands on a line of its own and above a blank line, and the next token of code (`lex_all` of `ulang/parse/lex.u`), which the parsed module holds in the order of the source, `Mod.comments`, while the tokens and the parts have none, so the parse and the phases after it do not depend on them. `format` puts each back by the spans of the parts (`lined` of `ulang/format/format.u`): a sequence of lines, the commands, constructors, statements, cases, spread elements and arguments, or the lines of a spec, takes the comments of its region, each before the first item that starts after it, at its indentation, or at the end of the line of the item that ends before it, those after the last item before what ends the sequence, and those inside an item that its text does not place above the item; the printer writes each as a marker, by which a sequence finds those that the texts of its items place, and which `format_module` replaces by the comments. A comment that a flat layout cannot place, between the elements of a form, the arguments of a call, or the branches of an `if` expression, spreads the layout, one part per line, and a comment inside an operand stands above the line of its part, where it stays. Each comment is the text of its line without `//` and the space after it, and a blank line follows it if one did. The doc of a declaration, which hover will show, is the run of comments on the lines right above its span, without a blank line between (`doc_of` of `ulang/syntax/syntax.u`); the round trip of `format` compares the texts of the comments in their order (`same_mod` of `ulang/ulang.u`).

## Specifications

- Examples of functions and procedures, lines `example …` after the `:=` of the head of a signature in `export` or of a private definition, before the body, after the contracts of a procedure, document a call with its result and run as tests: the `Spec` of the declaration, a field of `CFun`, `CFunSig`, `CProc`, and `CProcSig` of `ulang/syntax/syntax.u`, where a signature with a spec is a head, `:=`, and the spec, which the next command follows (`parse_spec` of `ulang/parse/parse.u`), and an example goes as far as its expression, whatever the layout, and ends at the next `example`, a command, or what cannot continue it, so that a body after examples cannot start with `(`, `-`, an operator, `.`, or `with`, which a `let` can bind (`parse_example`), printed by `spec_text` of `ulang/format/format.u`; the checked program has no examples, and imports drop them (`without_examples` of `ulang/parse/parse.u`). An example of a function is a `Bool` expression that applies it, `example gcd(12, 18) == 6`, or an application that raises, `example chr(-1) raises NoCharacter(-1)`; one of a procedure is a call with the expected values of the outs and each ref as `before => after`, `example divmod(in 7, 2, out 3, 1)`, or one that raises, with `_` for the outs and each ref as before, `example divmod(in 7, 0, out _, _) raises DivisionByZero`. An example that does not parse fails its test, not its declaration, so that the file checks and the other examples run, keeping their numbers: the parser keeps it as an `AUnparsed` (`parse_example` of `ulang/parse/parse.u`), whose test raises the error of parsing as a `Str` (`example_body` of `ulang/check/check.u`), and `format` prints it as its tokens. The checker translates each into a test `f.example.N`, the name `Owned(m, List("f", "example"), "N")` that `owned_text` of `ulang/syntax/syntax.u` shows, as it shows the test `l.lemma` of a lemma, `Owned(m, List("l"), "lemma")`, `N` from 1 per base name in the order of the source, after the definitions of the package, also with errors, but none of a function or procedure whose definition has errors, whose examples would be follow-ups of them, so that a change that breaks a definition and makes an example stale shows both at once (`example_tests`, `failed_owners`, and `example_stmt` of `ulang/check/check.u`), checked as written, as a test of the module, so that its names take the declarations that overloading chooses; by convention an example applies its function, which nothing checks, so `example size(List(1)) == 1` written on `set.size` tests `list.size`. An example that raises a type its call cannot raise is `NeverRaised` at the example, while builtin exceptions, which no `raises` counts, are not checked. Examples on the definition of an exported name are `ExampleOnDefinition`, and an example of `export` is checked as an importer sees the module, without its private declarations (`example_commands`). `assert a == b` reports a failure with both sides; `example` is a keyword.
- Lemmas, `lemma l[A](in x: A, …) := requires a, … ensures b`, with `requires` optional and the modes of a procedure in the head, where `out` formals are existential, given by an assignment `y := e` in a proof and bound by the outs of a call `l(in a, out q)` to witnesses, locals `var q: T` without a value, and `ref` is rejected, state `b` for all ins that satisfy the assumptions, for the prover, with an optional proof after the contract, see `ideas/verification.md`, section 4: steps `let` and `var`, calls of a lemma proven before or of the lemma itself as an induction hypothesis, assignments, and `assert`, then at most one split, `induction`, `match`, or `if`, whose cases are proofs (`Proof` of `ulang/syntax/syntax.u`, `parse_proof` of `ulang/parse/parse.u`, `check_proof` of `ulang/check/check.u` and of `ulang/prove/proof.u`), where `check --prove` reports each goal that a proof leaves open at its step, as an error of the kind `proof`, and a lemma without a proof has the default proof (`CLemma` of `ulang/syntax/syntax.u`, `parse_lemma` of `ulang/parse/parse.u`). The checker checks each assumption and `b` as a `Bool` over the formals, as the body of a function, so that the checked lemma has resolved names and folds instead of forms, and keeps lemmas in a table of their own, `Sig.lemmas`, apart from the values, whose names they may share, since only proofs cite them (`declare_lemmas` and `command` of `ulang/check/check.u`, `LemmaSig` of `ulang/check/sig.u`). Lemmas are private, in `implementation` sections and files without sections, `export` rejects them, and the interpreter and the compiler skip them; `lemma`, `requires`, `ensures`, and `induction` are keywords.
- Each lemma whose formals have enumerable types also gets a test `l.lemma` where `check --test` and `compile --tests` load the file, a step before its proof, which can falsify the lemma but never establish it, so the checker generates no such tests and only `check --prove` decides, which runs in both backends before the proofs (`enumerated_tests` and `lemma_stmt` of `ulang/test/generate.u`, passed to `check_all` of `ulang/check/check.u`, which checks the generated commands of each package after its definitions): it runs the statement on all values of the formals up to one depth, the largest of at most 4 at which the product of their numbers is at most 1000 (`depth_of` and `limits` of `ulang/test/enumerate/enumerate.u`), the first formal in the outermost loop, and raises `Falsified` with the formals of the first case that satisfies the assumptions but not the conclusion, as `name = value, …`, and `Vacuous` if no case satisfies them. Values are enumerated by depth, a constructor one deeper than its deepest field, an `Int` of depth `n` from `-n` to `n`, without duplicates and without randomness, so a counterexample is among the smallest: `Int`, `Bool`, `Char`, `Str`, `List`, `Set`, `Map`, and `Array` by `Enumeration` of `ulang/test/enumerate/enumerate.u`, tuples inline, and datatypes whose constructors the module sees and that are not abstract by a function `(enum)m.T` generated into the module of the lemma (`enum_fun` of `ulang/test/generate.u`); type parameters stand for `Int`; a lemma with a formal of another type, a function, a procedure, a `Buffer`, or an abstract type, gets no test. The generated code is source with qualified names, which the checker checks after the definitions of the package, if they check without errors. The enumeration is a package of this project, whose examples run as its tests, and the tester loads it into the program under test, after the library, as the module `(test).enumerate` of `enumerate_module` of `ulang/test/generate.u`, which no path names and no module sees, read by `os_library` from the directory next to the library (`load_tester` of `ulang/test/runner.u`, `load_after_library` of `ulang/parse/parse.u`), so its names are no candidates of overloading, and the generated tests name them by their qualified names, which the checker resolves without visibility (`overloads` of `ulang/check/check.u`). Imports drop the lemmas of the modules they load, with their tests (`without_tests_of` of `ulang/parse/parse.u`).
- Contracts of procedures, `requires a, …` over the ins and refs and `ensures b` over all formals, follow the `:=` before the examples, on the signature in `export` of an exported procedure, which its definition does not repeat (`ContractOnDefinition`, `with_contracts` and `contract` of `ulang/check/check.u`), and the checked program keeps them in `Spec` of the `CProc`; `requires` and `ensures` of a function are a parse error. A lemma `lemma l(in x: A, …, out y: B, …) := correct p(in a, …, out y, …)`, a `ClaimCorrect` of `ulang/syntax/syntax.u`, claims that every run of the call that ends normally from a state that satisfies the `requires` of `p` satisfies its `ensures`, where the outs of the call are those of the lemma in their order (`ClaimOuts`), and `p` is defined before it in its package (`ClaimOrder`); its proof is an `invariant e` per `while` of the body of `p` in the order of the source, each over the variables in scope at its loop (`loop_positions` of `ulang/syntax/syntax.u`, `with_scopes` and `claim_proof` of `ulang/check/check.u`), and none is the invariant `true` of every loop. `correct` and `invariant` are keywords. The translation runs the body over the terms of proofs (`claim_of`, `run`, and `run_loop` of `ulang/prove/translate.u`): an assignment is a definition of a new variable of its name, an `if` or `match` a split whose cases carry the rest of the body, a call the call of the contract of its procedure, which may be the procedure itself, its outs and refs values that nothing is known of without one, a `raise` the call of the contract `ensures false`, and a loop an `InvariantTerm`, which `invariant_gaps` of `ulang/prove/proof.u` checks by the invariant on entry, its preservation from new values of the variables that the loop assigns, and the rest of the body from the invariant and the negated condition; `for`, `try`, and `assert raises` in the body are gaps `Unsupported`. A claim holds only for the runs that end, so it is no fact of the lemmas after it and no lemma that a proof calls (`ClaimCalled`), else `ensures false` of a loop that does not end would prove them all, and it has no test `l.lemma`.

## Semantics

- `raise e` is a statement, so only procedures raise, and functions fail only by the exceptions of builtins, such as `DivisionByZero`, and of accessors, `MissingField`; a failed `assert` cannot be caught. `assert raises p do … end` fails, with `AssertionNotRaised` of `ulang/syntax/error.u`, which cannot be caught either, unless its body raises an exception that the pattern `p` matches, typed as the pattern of a `catch` case, and for which its optional guard holds, `assert raises OsError(text) if text == "cannot connect to " ++ host do … end`, while another exception is raised further, as from a handler whose guard fails; the variables of `p` are those of the guard only, so a pattern without a guard has none (`RaisesVariables`), and the variables after it are those before, as at the start of a handler, since its body raises if it passes. `raises` after code is a pattern of what must be raised, and `raises T, …` after the formals of a procedure or the modes of a procedure type the types of what it may raise.
- What a procedure may raise is checked after its package, if it has no other errors, by `raises_errors` of `ulang/check/raises.u` over the checked commands and the tests of examples, which keep their positions, giving the first error of each command, which `check_package` of `ulang/check/check.u` adds to those of the package:
  - A raised value is of a datatype without type parameters, also a builtin one such as `Str`, else `NotAnException`, and so are the types of `raises`; the exceptions of builtin functions and accessors (`unchecked_exceptions` of `ulang/syntax/builtins.u`) are defects of the program, which no `raises` counts, as functions cannot declare them.
  - A statement raises the types of its `raise`, the `raises` of the procedures it calls, also through variables of procedure types, and what a `try` lets through: the types that its unguarded handlers do not cover, by the exhaustiveness check (`covers_all` of `ulang/check/check.u`), where `_` covers all, and what its handlers raise; `assert raises p if g` is a `try` of the one handler `p if g`, which covers nothing with a guard. A handler of a type that its body cannot raise is `NeverRaised`.
  - A procedure with `raises`, an exported one, or one without formals, an entry of `run` and `compile`, which raise nothing without them, raises none of the others (`UndeclaredRaise`), and a private one with formals and without `raises` raises what its body does, inferred for all of them together as the least fixpoint (`infer_procs`), which its `CProc` in the checked program carries as its raises (`with_inferred` of `ulang/check/check.u`).
  - Procedure types carry their raises as `Raises` of `ulang/syntax/syntax.u`, `RWritten` of the source, which the checker makes `RSet` of the exceptions by name, and `RUnknown` of inference, without polymorphism over sets: a procedure used as a value, whose scheme has `RPending`, which each instance numbers (`proc_scheme` and `instantiate` of `ulang/check/check.u`), and a lambda, `raised` of `EProc`, get an unknown, numbered across the package. Unification compares two sets at once and records the other pairs as `Bound` of `ulang/check/raises.u`, where `expect` gives subtyping, the raises of the type found within those expected, flipped for the arguments of functions and the ins of procedures, and both ways for refs and the params of datatypes that a field takes where values flow in, an argument of a function or an in or ref of a procedure, while the others are covariant (`unify_toward` and `Direction`, `with_variances` of `ulang/check/check.u`, `fixed_of` of `ulang/check/sig.u`), and an unknown of a type that values reach from several places, the cases of a `match`, the branches of an `if`, or the elements of a form, is bound to a copy whose raises are unknowns of their own, so that it raises what each of them raises (`bind_toward`); the pass solves each unknown as the least that the procedure values and lambdas of its type and the bounds give it, and reports what a value raises that a set of its bounds omits, `UntypedRaise` at the value or the raise in the lambda, and `WiderRaise` where a value of a fixed type brought it in, and `check_package` writes the solutions into the checked program, an unknown without bounds as none (`zonked` and `solved_type` of `ulang/check/check.u`), so that the hints show them and no unknown reaches a later phase. So a procedure value bound without a type raises what it raises, and one of a type that raises less fits a place that allows more. A comma followed by `name :` ends the raised types of a procedure type, since it starts the next formal (`at_raised_type` of `ulang/parse/parse.u`), so a procedure type with raises in a list of types takes parentheses.
- The assignments of one `a := …, b := …` are sequential, as the declarations of one `let` or `var` are: `b := f(a)` reads the `a` that the statement assigned, which the checker checks one after another (`statement_node` of `ulang/check/check.u`) and each backend and `translate` of the prover assign so, and a swap takes a `let`, `let t := x` and then `x := y, y := t`; there is no parallel assignment, since a statement `(x, y) := …` would make the parse depend on the layout, the `(` at the start of a line being otherwise the arguments of a name that ends the line before it.
- Effects on variables are atomic: a procedure works on copies of its outs and refs, which reach the caller only when it returns, and the handlers of a `try` see the variables as before it. Compiled code copies outs and refs in and out, and saves the variables that the body of a `try` assigns before its `setjmp` in the slots of its handler, `saved` of `struct u_handler` of `ulang/runtime/ulang.h`, never in locals of C, whose copy and restore clang -O2 and gcc -O3 drop (`save_vars` of `ulang/compile/compile.u`).
- No formal, local, pattern variable, or formal of a lambda hides a local around it (`HiddenLocal`, `unhidden` of `ulang/check/check.u`), while locals may hide declarations, which depend on the imports; the names of the translations, such as `(acc)` and `(item)`, nest.
- Variables are read only where they are assigned on every path, and outs must be assigned on every path that does not raise, where passing a ref reads it (`Local` of `ulang/check/check.u`, joining the paths of `if`, `match`, and `try`; a `while` may not run its body, and a handler starts from the variables before its `try`). A local without a type gets it from its value, `var x := e`, or as an out of the call right after its declaration, `var q, r` before `divmod(in a, b, out q, r)` (`initialized` of `ulang/check/check.u`), else it is `MissingType` with a hint that says so (`untyped`), since `var a, b` before two calls types only the outs of the first.
- Procedures are values of types `(in A, out B, ref C) raises E, …`: declared ones by name, and `lambda in x, out y, ref z => statements end`, which sees the variables around it by their values and assigns only its own outs and refs, where an in may be `_`, a value that the body does not read, the variable of `dropped_out` of `ulang/syntax/syntax.u`, which the checked program keeps and the compilers do not bind. The arguments of a call go by mode in the order `in`, `out`, `ref`, as in the signature, also when they come from different places, `p(in a, out b, ref c)`. An out of a call may be `_`, `p(in a, out _, x)`, which drops its value, no variable of the source: the parser keeps it as the variable of `dropped_out` of `ulang/syntax/syntax.u`, named by the keyword `_`, which the checked call keeps, typed as its out (`out_variables` of `ulang/check/check.u`), and `expanded` of `ulang/expand/expand.u` makes the call a block around it with a local of a name that users cannot write for each `_` (`call_expansion`), so that the backends see ordinary locals; a ref, an out of a claim `correct p(…)`, and an out of a call of a lemma in a proof cannot be `_`. `p(…)` calls a variable `p`, which hides a procedure `p`; compiled code calls through `u_call_proc` and the wrappers `wp_`.
- Functions without parameters are computed once, interpreted and compiled.
- Orders, equality, and show of datatypes:
  - A function `compare` or `==` of two values `T[A, …]` of a datatype `T` of its own module, with distinct type parameters, is the order or equality of `T` (`order_of` of `ulang/check/defs.u`), which the builtins `compare`, `==`, and `<` use for all values of `T`, also inside other values and in generic code; other datatypes compare structurally.
  - Only abstract types declare `==`; datatypes with visible constructors may declare `compare`, which must agree with structural equality, unchecked. With `compare` alone, `==` is `compare(a, b) == 0`.
  - Comparing values of an abstract type whose module declares no `compare` raises `Unordered`, and if it declares no `==` either, comparing and equating them raise `Incomparable`, since the structure of an abstract type is no order: the checked program keeps the abstract types as commands `CAbstract` of `ulang/syntax/syntax.u`, by which `unordered_of` of `ulang/check/defs.u` names the exception, which the interpreter raises and compiled code by `u_unordered` and `u_incomparable` of the runtime, in the descriptor of the type (`ulang/test/datatypes/orders.u`, `ulang/test/modules/modules.u`).
  - A function `show` of one value `T[A, …]` of a datatype `T` of its own module, with distinct type parameters and the result `Str`, is the show of `T`, which the builtin `show` uses for all values of `T`, also inside other values; otherwise `show` gives the text of a value, strings in quotes.
  - A function `show` of one value, or `compare` or `==` of two, must be a hook of these forms, else `MisshapenHook`, since uses do not reach it otherwise. The hooks are `Hook` of `ulang/check/defs.u`, with their names, arities, and results, from which `order_of`, the schemes of the builtins of their names, `is_hook`, and the message derive.
  - The runtime finds these through the type descriptor of each object (`struct u_type` of `ulang/runtime/ulang.h`, one `t_` per datatype, pointing to the declared functions or the structural ones), the interpreter through the maps of `Defs` of `ulang/check/defs.u` from datatypes to them.

## Overloading

- The candidates of a name are its declarations in all visible modules, its own module's no more than the others; locals hide them all, where a call of a local, formal, or out whose type is no function of its arity, while functions of its name and arity are visible, is a `CannotUnify` with the hint that names those the arguments fit, without reading the variable, so that no `Unassigned` follows (`hidden_functions` and `hiding_hint` of `ulang/check/check.u`), and within a module, overloading is only by arity. A qualified name `p.x` has as its candidates the visible declarations of `x` of the module of the path `p` and of the members of the package of `p`, which may both exist, as for `ulang.test.modules.paths` of `ulang/test/modules/paths.u`, so it reaches no private declaration of another module, and a path that users cannot write, such as `(test).enumerate`, without visibility (`overloads`, `visible_names`, and `is_qualified_by` of `ulang/check/check.u`); the names that the checker makes, such as the folds of generators, are qualified by the paths of their modules and resolve by the same rule. The parser reads a qualified name in types, `ulang.syntax.Expr`, and in patterns, `case prelude.option.Some(n) =>`, also bare, which is then never a variable (`parse_qualified_name` of `ulang/parse/parse.u`), and in expressions as accesses of fields, `ulang.syntax.size(xs)`, which the checker reads as a qualified name where the first name is no local and the longest prefix names a path that the module sees, the base the name after it and the rest accesses (`qualified` of `ulang/check/check.u`), so a formal, local, or pattern variable named as the first name of such a path is `QualifierLocal`, and the names of a path after `.` may be keywords, `ulang.test.cases`, which the lexer gives as names (`named_after_dot` of `ulang/parse/lex.u`), so that no keyword of a path starts a command or a statement where the parser resumes after an error. `format` writes the paths as the source does (`written_type` of `ulang/format/format.u`). Declared hooks `show`, `compare`, and `==` are no candidates: uses take the builtins, which reach the hooks through the types of their arguments (`is_hook` of `ulang/check/check.u`).
- An applied name infers its arguments first, then keeps the candidates of its arity whose instance unifies with them and the expected type, each tried on a copy of the substitution, where a clash with a part of type `TError`, which `report` drops, still rules a candidate out, since `trials` and `fits` of `ulang/check/check.u` count every error that `report` sees, so `size` of a `List[TError]` is `list.size`. One remaining candidate is committed; with several, the use gets a fresh type, a placeholder name, and a pending entry.
- Pending entries are solved to a fixpoint at the end of the command, before `zonk` replaces the placeholders, since `enter` of `ulang/check/check.u` starts each command with an empty substitution, so a type that a phase records while one command is checked must be zonked before the next, and lets do not generalize their types. A use resolves uniquely, by its types alone, without preferences: since the substitution only grows, a candidate that does not fit never fits again, so a use with one candidate left is committed, whatever the order of solving, e.g. `map.put` of a map literal, which then fixes the type of its `map.empty` when `set` and `array` are imported too. No candidate is an error, and several at the end of the command are ambiguous, both listing the candidates with their types.
- Accesses `e.f` and updates `e with f := a` resolve by the type of `e`, which must be known when the checker reaches them, else `UnknownFieldOwner`. Lambdas that are arguments wait until the other arguments and the function type are known, and then take the types of their formals from it, so `exists(xs, lambda q => q.x == 3)` and `(lambda p => p.x)(Point(1, 2))` check (`infers_first` and `infers_lambdas` of `ulang/check/check.u`); a lambda that is bound by a `let` has no expected type, while the declared type of a local, an assignment, or a result gives one, `let g: Point -> Int := lambda p => p.x`, and so does an annotation of a formal, `lambda p: Point => p.x`, or an ascription, `(p: Point).x`, which the hint of `UnknownFieldOwner` suggests (`hint_of` of `ulang/check/message.u`).

## Modules

- The root of a project is the nearest directory above a file with `project.u`, else the file's own directory, and a module of a project is known by its path from the root without `.u`, a `Path` of `ulang/syntax/syntax.u`, the list of the names of its directories and its file, which `Name(path, base)` holds as the module of a resolved name, empty for a name without one, and which messages, ` in m`, the field `module` of diagnostics, and hints show with `.`, e.g. `ulang.check.check` (`path_text` of `ulang/syntax/syntax.u`), while directories and files keep `/` and are converted at the edges (`dir_path` of `ulang/syntax/syntax.u`); the modules of the library, a directory with `prelude.u`, as members of the package `prelude`, e.g. `prelude.map` (`place_of` of `ulang/parse/parse.u`, `library_module` of `ulang/syntax/syntax.u`), except in C, where they keep the names of their files, e.g. `t_list_46_List` and the key `"os.OsError"`, as the runtime and the seed refer to them, and the other names keep `/` between the names of their paths, which no base contains, unlike `.` (`c_text` of `ulang/compile/lower.u`). `import p.q` loads the package of the directory `p/q` from the root, once, without the tests of its members, where the names of the path have letters, digits, and `_`, also keywords, so no `..` and no `-`, and a string, `import "p/q"`, the form before paths, is a parse error that writes the path; an import of a file `….u`, of an unknown package or one without members, of the own package, of the library, which every module sees without importing it, and a cycle of packages are parse errors (`parse_import` and `import_package` of `ulang/parse/parse.u`), where an import that fails stays among the imports of the module at its line, as an error node of its error, which the checker does not see (`import_failures` and `without_unparsed` of `ulang/parse/parse.u`), so that `format` and `refactor` keep it in place. An import of a package of which the module uses nothing is the type error `UnusedImport` at the import, which does not block a run, judged after the package of the loaded file checks without errors, whose members have their tests, and only if the source parses, since a part that does not parse may use an import: a package is used by the modules of the resolved names of the checked commands of the module (`used_modules` of `ulang/check/uses.u`), of the pattern and type aliases that it uses, which checking expands and records, and of the resolved patterns of the pattern aliases that it declares, also of those with `_`, which have no definition (`aliased`, `alias_uses`, and `unused_imports` of `ulang/check/check.u`). `Mod.imports` are the ids of the imported packages, each at its line (`import_ids` of `ulang/syntax/syntax.u`), which `seen_modules` of `ulang/syntax/syntax.u` expands to their members. The parser gives `Source(mods, packages, main)` of `ulang/syntax/syntax.u`, the modules in load order, each after its imports, as `Mod(name, imports, exported, builtins, implemented, comments)` with the commands of its sections paired with their positions and the comments of the file, and the packages as `Package(id, members)`. Its only state is the source loaded so far, from which each module gets its initial notation, the exported notation of its imports and of the other members of its package (`exported_notation` of `ulang/syntax/notation.u`, `exported_ops` of `ulang/parse/parse.u`).
- Packages: every `.u` file but `project.u` is a member of the package of its directory, known by the directory from the root, and `prelude` for the library, also a file without sections, which has all its commands implemented and exports nothing. A package is exactly its directory, as in Go, spanning no subdirectories, so that the imports check the layers of `ulang/`, which a package of its subdirectories would merge, and each directory of tests below `ulang/test/` is a package of its own. Loading a module loads its package, all members, each parsed with the notations that the export sections of the others declare, read from their tokens before they are parsed (`load_package` and `package_files` of `ulang/parse/parse.u`). Members see each other's exports without imports, also cyclically, and overload each other by type, while their private declarations, also their procedures without formals and their tests, and the constructors and fields of their abstract types stay private to their file; several members may each have a private `main`, which `run file.u:proc` chooses by the file. Packages are the only units of imports, and cycles are cycles of packages. A project with a directory `prelude/` at its root shares the ids of the library, which `import prelude` rejects, and clashes with it in C.
- Every module implicitly imports the whole library, the package `prelude` of `prelude`, `option`, `list`, `str`, `set`, `map`, `array`, `buffer`, `os`, `io`, and `window`, whose members, the `.u` files of the directory that `os_library_dir` gives, see each other (`implicit_imports` of `ulang/syntax/syntax.u`, `package_files` of `ulang/parse/parse.u`), so no module imports one; a module may declare their functions again with other types or arities, which overload them, and their types, which hide none, as no type hides another, of the library, of an import, or of the module itself, so that two visible types of one name make an unqualified use `Ambiguous`, and the use writes the path of the one it means, `ulang.compile.Gen` beside `Gen` of `ulang/syntax/syntax.u`, or `prelude.Int` beside the `Int` of `ulang/test/modules/own_int.u` (`visible_names` of `ulang/check/check.u`); each member that names a type of an imported package imports that package itself.
- A module sees its own declarations, the exported ones of the members of the packages it imports and of its own package, and the prelude, and likewise for notations: imports are not transitive. The checker resolves every name to its module, also of tests, `CTest(name, …)`, and gives `Prog(cmds, builtins, imports, main)` of `ulang/syntax/syntax.u`, every command of the export and implementation sections of all modules with qualified names, at its declaration, the definitions checked and the rest as written, then the tests of examples and lemmas, the builtin sections apart, the imports of each module at their lines, which hold the errors of imports such as `UnusedImport`, and the module of the loaded file, where the backends and `translate` take `definitions`, without the signatures and the pattern aliases, so that the driver takes the tests and `translate` the lemmas of a module by the modules of their names; it checks the members of each package together, once, after their imports, against their signatures (`check_program` and `check_package` of `ulang/check/check.u`, `Sig` of `ulang/check/sig.u`), where the private declarations of the members are in the signature, hidden from the other members by `State.hidden` and `State.hidden_sorts`, and type aliases are declared each after those it names.
- Sections, see `ulang/prelude/set.u`: imports, then `export` with notations, datatypes, aliases, signatures without bodies, and abstract types `type T[A]`, then optionally `builtin`, then `implementation` with definitions that repeat the signatures exactly, else `SignatureMismatch` at the definition names the first part that differs, `Differing` of `ulang/check/check.u`, `data` for the abstract types, private declarations, and tests. A module without sections has all its commands implemented and exports nothing; its private procedures and tests are the entry points of `run` and `test`.
- A `builtin` section has exported signatures without definitions and types without a definition, `type T[A]`, which the interpreter (`builtin_names` of `ulang/run/run.u`) and the runtime (`builtin_functions` and `proc_name` of `ulang/compile/lower.u`) define, make, order, compare, and show; its uses keep their module, and its types are not abstract types that raise `Unordered` or `Incomparable`, but datatypes without constructors, so `is_data` of `ulang/check/sig.u` holds for `Str`, `Int`, and the others. ## Errors

A type error is reported at the innermost part around it, and a part of the wrong type at the part, with the type expected and found, e.g. `1 + true` as `expected Int but found Bool in argument 2 of next command, at the next statement, and at the next `,` or `)` of an argument, reporting the errors of all of them, which the parsed modules hold as their parts that do not parse, `AUnparsed` of `ulang/syntax/syntax.u`, also the commands (`parse_errors`, `has_errors`, and `require_parsed`, which raises them, of `ulang/parse/parse.u`, `parse_stmt_recovering` and `parse_arg`), where neither the parse nor its errors depend on the layout, only on the tokens, since a statement ends at the next statement keyword, at what ends its body, or at a name after what ends an expression, outside its brackets and blocks (`skip_stmt` and `at_next`), where a missing operand is found at the next token, which may be on the next line, and a file with parse errors is checked without its commands that do not parse, while a definition whose part after `:=` does not parse keeps its signature (`parse_expr_recovering` of `ulang/parse/parse.u`), and a procedure whose contract does not parse keeps its body `ulang/parse/parse.u`, `check_partial` and `is_blocking` of `ulang/check/check.u`).

- Parse errors are reported at their token, type errors at the innermost part around them, since every part of an expression, statement, and pattern has its position (`At` of `ulang/syntax/syntax.u`, `infer`, `statement`, and `binders` of `ulang/check/check.u`), where the checker records each error by `report` and continues, and a part of the wrong type is a `Mismatch` at the part (`expect`), the innermost one, since `check` passes the expected type down to the components of a tuple, the elements of a form, the body of a `let`, and the arguments of a call of one candidate whose result fits it (`infer_against`, `apply`, and `checks_args` of `ulang/check/check.u`), else at their declaration, with the module `m` if it is other than the file, of an imported package or a sibling (`ImportError` of `ulang/parse/parse.u`, `Located` of `ulang/check/check.u`). Each error is a `Diagnostic` of `ulang/syntax/error.u`, printed as one JSON object on a line by `format_diagnostic`, with the fields `file`, the file to edit, that of the module of the error, from the working directory if it is below it (`diagnostic_file` of `ulang/ulang.u`), `module`, `line`, `column`, `kind`, the name of an `ErrorKind`, `code`, `message`, details such as `expected` and `found`, and `severity` `warning` for a warning, which does not fail the command (`format_warning`), the only output of errors, read by agents and the VS Code extension (`parseDiagnostic` of `vscode/extension.js`), and a missing procedure that `run` or `compile` is to call is the runtime error `UnknownEntry` of `require_entry` of `ulang/check/defs.u`. Runtime and internal errors have no positions; the texts of the runtime errors that both backends report are `runtime_message` of `RuntimeError` in `ulang/syntax/error.u`, which `ulang/compile/compile.u` writes into every program as the formats `u_text_*` that the runtime prints; `InternalError` of `ulang/syntax/error.u` holds the errors of the interpreter, the checker, and the compiler that checked programs never raise, since an earlier phase rules out what they meet, with `Unexpected(what)` for code without a case of its own; the messages of type errors are `located_message` of `ulang/check/message.u`, and those of internal errors `internal_message` of `ulang/syntax/error.u`.
- Every part of an expression, statement, and pattern is an `At` of `ulang/syntax/syntax.u`: `AOk(pos, span, that)` at the position of its first token or of the token that names it, a call at its name, an operator at the operator, and with its `Span` from its first token to the end of its last, which the parser reads from the tokens, each with the stop of the code before it (`Tokens` of `ulang/parse/lex.u`, `span_from` of `ulang/parse/parse.u`), while the translations of the checker take the span of what they translate, and code that a phase makes without one the empty span `span_at(pos)`, and so is each declared formal and local, `At[Var]` at its name, which the phases after the checker read by `vars` and code that the parser did not read places by `unplaced_vars`, while the outs and refs of a call are plain variables; `AUnparsed(pos, span, text, error)` is a part that does not parse, which the parser makes, and `AErr(pos, span, that, errors)` a part or a command that checking rejects, with its diagnostics, whose positions may be inside it: a part, when its check ends, takes the errors reported while it was checked that none of its parts took (`take_errors` of `ulang/check/check.u`), so that a mismatch stands on the call, the `if`, or the assignment that finds it, while its diagnostic points at the part, and what manifests after the parts, the pending overloads, the errors of declarations and of raises, stands on the import at its position, else on the command that contains it, else is `Unexpected` (`with_errors`), as the errors of the prover stand on the lemma and on the function whose termination is open (`with_proofs` of `ulang/prove/lemma.u`); patterns and parts at `Pos(0, 0)` take none, and the walk of errors is `cmd_errors` and `part_errors` of `ulang/syntax/syntax.u`, for the source and the checked program alike. No phase stops at an erroneous part: each treats it as it treats a part that does not parse, and the raises are checked over the commands without errors. A call that no declaration fits has the type `TError`, so that its uses make no follow-ups, while the other parts with errors keep the types of their declarations, which their consumers check (`application`, `choose`, and `unify_result` of `ulang/check/check.u`); the errors of a translation, as of a form, stand on the part that it translates (`translated`); and the commands of a package whose check raised are kept as written, as error nodes without errors of their own (`unchecked`). Errors are deferred: `run` and `check --test` run a program with errors if its main module is checked (`is_runnable` of `ulang/ulang.u`), also if a package that it imports has errors, since each package is checked against the signatures of those before it, also of those with errors, and only a package whose check raised stops the packages after it (`check_source` of `ulang/check/check.u`), where a definition that its own errors make unsafe to run, all but those of raises and of proofs (`blocks_run` of `ulang/syntax/error.u`), has an error node of them as its body (`rejected` of `ulang/syntax/syntax.u`), while a part that does not parse stays in the checked body of its definition, and the interpreter raises the runtime error `Deferred` with the first of its errors where it reaches one (`require_checked` of `ulang/run/run.u`), so that only the paths through such a part raise; the file fails with the status of its errors, or 3 if a test fails, `check --prove` proves no lemma if code that the lemmas may reach has errors, and `compile` refuses it unless they generate no code. Positions are never stripped: the checked program keeps them, code that does not care reads `x.that`, and comparisons modulo positions, as the round trip of `format` (`same_cmds` of `ulang/ulang.u`) and the parser tests, take `strip_cmd` and the like, which set them to `Pos(0, 0)` and its empty span, as `nowhere` places code that the parser did not read.

# Style

## Names

- Formals are the parameters of functions, procedures, and lambdas; params are type parameters.
- Functions, procedures, and locals are snake_case, e.g. `zonk_type`; constructors and types are CamelCase, e.g. `TSort`, `TypeError`.
- Names are descriptive but short, and one concept has one name, without short and long forms, for types, functions, and variables alike: `Constr`, `Mod`, `Sig`, `Prog`, not `Constructor`, `Module`, `Ctx`, `Program`, and a variable `constr` never has a `constructor` next to it.
- Variables are named by their type: `toks`/`tok`, `cmds`/`cmd`, `sig`, `loader`, `run`, `typ` and `types`, `fun`/`funs`, `text` for source and `offset` for positions in it, `name` for an `Id`, `cases`, `cond`, `body`, `prec`, `constr`/`constrs`, `field`/`fields`, `prog`, `expr`/`exprs`, `pat`/`pats`; `i`, `j` for plain counters.
- A variable of type `Stmt` is `stmt`, unless the declaration has another statement of that name, e.g. a pattern of `EProc` or `CProc`; parts of a statement keep their roles, `body`, `loop`, `step`.
- Patterns bind the names of the fields they match, `case EField(base, field)`, so a field is named by its role and a variable around the match by its type; where both would clash, the field name is the one to improve.
- Names carry no numeric indices, e.g. `stmt1` or `e1`: two of a kind in one scope get names by their roles, e.g. `decl` for the record of a constructor where a pattern binds `constr`, and a clash is resolved by a better name for one of them. Two conventions name the rest: what the checker makes of a part has the prefix `typed_` before the name of the part's field, `typed_expr`, `typed_pat`, `typed_guard`, `typed_args`, as `expr_branches` of `ulang/check/check.u` binds them; and the second of a pair without roles of their own has the suffix `_`, the tails `xs_` and `ys_` of two lists matched together, the types `t` and `t_` of `unify`, or the signature `params_` and `formals_` of a definition against `params` and `formals` of its export in `check_signatures`. Renaming never makes a short name long, e.g. `t` to `candidate`.
- Procedures that consume tokens start with `parse_`, except `advance` and `expect`; functions that build trees do not. Predicates on the next token are `at_X`, grouped together.
- Predicates, functions to `Bool`, are `is_X` for a property, `is_useful`, `has_X` for a part, `has_holes`, a verb in the third person for a relation, `contains`, `covers`, `occurs`, and `at_X` for the next token, never a bare adjective or noun such as `useful` or `holes`.
- `show` is text that parses back literally, never `show_X`; `format_X` prints into another language, e.g. types, values, tokens, programs, or C as source.
- Pattern aliases name a shape at the level where code works with it, by the prefix of that level, `VInt(n)` of values in `ulang/run/run.u`, `PCons(head, tail)` of patterns, `ECall(name, typ, args)` of expressions, `TBool()` of types, `HTuple()` of heads, and not names, so no guard such as `if constr == cons_name()`; they always build as well as match, so none has `_`, except the aliases of alternatives that name a group of constructors by a definition, such as `CNoCode` and `CNoSpec` of `ulang/syntax/syntax.u`, which only match, stand for a group where every site treats its members alike, and which a new constructor joins only if it fits the definition; and a type inside, as of `Var`, is a formal, `_` where matched and `THole` where built. Aliases over names that checking resolves, such as `PNil()` and `ENil(typ)` of `ulang/syntax/builtins.u`, match only checked code; unresolved names, as the parser writes them, are matched directly, `PApp(Name(List(), "Nil"), List())`, where a constructor written bare, `case None =>`, is a `PVar` that the checker resolves and `None()` a `PApp`, so a test of the source takes both. Functions such as `nil_name()` remain where a `Name` is used on its own.

## Docs and examples

- Docs state what the code and its names do not: a rule, a reason, or a convention that holds beyond the line, e.g. that a position is in another module, or in which order a function visits. Omit those that restate the name of a declaration or the lines below. Name a piece of code by a function instead of commenting it, and put a note on the statement, `case`, or command that it explains.
- A function whose name and types leave its meaning open, such as the order of its arguments or what it does at the edges, has an example, exported or private, on the first occurrence of its signature, `example slice("abcd", 1, 3) == "bc"`, which, unlike a doc, cannot go stale. An example applies its own function to arguments of the types of its signature, since an overloaded name may otherwise take another declaration, which the checker does not catch.

## Code

- Functions only for computations that terminate; code that may not terminate, such as the evaluator of `ulang/run/run.u`, is written as procedures, unchecked.
- Records over positional tuples for anything kept in a table or passed on, with fields named by role, which uses read as selectors, `sc.typ`, `proc.ins`; tuples for pairs that are built and taken apart at once. A datatype of one constructor is named as its type, `Sig`, `Scheme`; the alternatives of a sum have the prefix of their datatype, `CFun` of `Cmd`; separate records of one family share a suffix, `ProcSig` and `ConstrSig` of `Sig` (`ulang/check/sig.u`), `FunDef`, `ProcDef`, and `ConstrDef` of `Defs` (`ulang/check/defs.u`).
- Patterns have two printers: `format_pat` of checked patterns, for messages, and `format_pattern(notation, …)` of the source, which alone keeps the round trip of `format`.
- The notation is threaded as the first parameter where it is needed, not bundled into records.
- A match names the constructors where a new one would need a decision, e.g. a traversal, with `|` where they share a body, `case THole | TMeta(_) | TParam(_) =>`, for every datatype alike, so that the exhaustiveness check lists each place to change. A catch-all `_` stays where every other constructor means the same: a predicate or a selector of one or two constructors, a dispatch on the next token whose `_` is the parse error of everything else, a match over the many constructors of `TypeError` that treats a few of them apart, and a match where another place decides, as `enter_section` of `ulang/parse/parse.u` does what a section holds. A constructor that an earlier phase rules out gets a case of its own, which in a procedure raises `Unexpected` or another `InternalError` of `ulang/syntax/error.u`, and in a function, which cannot raise, gives the value of the other cases, with a doc of the phase that rules it out, as `exposed` of `ulang/check/check.u` does.
- Write recursions with a large `match` explicitly, not as `foldl` with a step function; folds are for small steps.
- Each local is declared where it is first needed, in the innermost body that uses it, a case of a `match` or a branch of an `if`, and in each case that uses it, so that a reader sees which case uses which local, and by `let` unless something assigns it later (`UnassignedVar` of `ulang/lint/lint.u`).
- In traversals such as `ulang/prove/simp.u`, bind every result of a recursive call by `let` before using it, keep the recursion in the traversal (`simp_term`), which passes the simplified parts to one helper per kind of term (`simp_app`, `simp_ite`) that only combines them.
- Iterate a map by `for k => v in m`, not by first making a list of its entries, `List(for x in m)`, and then taking the pairs apart; `for (k, v) in c` is for a list of pairs. This was mistaken for `for (k, v) in m` when flattening `field_table_decls` of `ulang/compile/compile.u`.

## Layout

- Signatures that do not fit on one line have one parameter per line, with `in  ` padded so that names align with `out ` and `ref `.
- The printer (`format`) lays out `match` and `catch` by one rule: each case body starts on the line after `=>`, and a blank line separates the cases unless there are at most two and each has a head and one line of body (`case_chain` of `ulang/format/format.u`); a `List(…)`, `Set(…)`, `Map(…)`, or `Array(…)` wider than 80 characters has one element per line, also a `List(…)` in a pattern, and so has a procedure head that is wider, with the modes `in`, `out`, and `ref` in front of the first formal of their group; the body of a function and the pattern of a pattern alias start on the line after `:=`, and the body of a `let` on the line after `in`, at the indentation of the line of the `let`; `if … then … else …` in expressions stays on one line if it fits in 80 characters, else each branch has a line of its own, one deeper, with `else if` at the level of the first `if` (`ite_text` and `spread_ite` of `ulang/format/format.u`).
